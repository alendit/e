* Review loop

** DONE High: Writer command ids collided after an Emacs restart

*** Problem

The initial writer protocol used a process-local integer sequence.  Reusing a
session directory after restart could make a newly submitted record look like
an already committed command.

*** Change

Commands now combine a fresh ULID controller instance id and a local sequence.
The Node writer deduplicates these opaque string ids.

*** Evidence

=e-session-persistence-test= verifies writer-owned journal/catalog commits and
the command-id shape; commit =46a19c8= contains the corrective slice.

** DONE High: Reconciliation loaded every transcript despite a current catalog

*** Problem

The first stale-catalog reconciliation pass read all JSONL files at startup,
breaking the indexed-session listing contract.

*** Change

Reconciliation compares journal file names with catalog ids and reads only
journals absent from the catalog.

*** Evidence

=e-session-test-index-store-lists-without-loading-transcripts= passes alongside
the stale-catalog recovery test; commit =cdb7a0e= contains the correction.

** DONE High: A message display update replayed the complete transcript

*** Problem

The live profile showed two =message-updated= events taking about five seconds
each.  A claim-validation correction changes the display disposition of an
already-rendered assistant message, but the chat shell had no identity bridge
from durable message id to its rendered block, so it rebuilt the entire
transcript.

*** Change

The chat buffer now owns a transient =message-id -> block-id= projection.
Each durable entry retains its own invisible layout range when normally hidden,
including immediately preceding separators.  A normal display update changes
that range locally and refreshes only derived local selection/separator state.
The explicit audit-reveal command still uses its full replay path because its
dimmed hidden-entry representation is intentionally different.

*** Evidence

=e-chat-test-message-updated-reconciles-rendered-reply-locally= proves both
hide and restore invoke no transcript replay.  The full chat suite passes with
310 expected results and one existing environment-dependent markdown skip.

** DONE Medium: Every provider text chunk entered the chat renderer

*** Problem

One provider response can produce hundreds of =assistant-delta= events.  The
core loop needs all of them to assemble the final assistant message, but the
chat shell does not render partial answer text: only the first chunk changes
its status to =streaming=.  The remaining callbacks therefore did no useful
presentation work.

*** Change

The shell records that it has shown streaming status for the current provider
response and drops later delta callbacks at its subscription boundary.  A new
=provider-request-started= event resets that local state, including a second
provider round after a tool call in the same turn.  The core loop and durable
message assembly remain untouched.

*** Evidence

=e-chat-test-subscription-skips-redundant-assistant-deltas= proves one delta
is rendered per provider response and that the next response is re-enabled.

* Final review

No unresolved findings.  Durable journal appends now leave the Emacs UI thread,
the catalog is a debounced reconstructible cache, and latest-value chat state
uses one scheduled projection.  Terminal transcript updates remain ordered and
synchronous by design.

* Architecture review

The persistence controller owns transient outbox/retry state while the Node
adapter owns filesystem effects.  Journals remain authoritative durable state;
the catalog is derived and recoverable.  Chat event dispatch updates local view
state and asks the existing UI-work service to project it, avoiding a second
renderer or a new shared event abstraction.
The message-to-block index is likewise buffer-local derived state: the session
remains the durable owner of message identity, while the shell owns its current
layout and visibility projection.
Provider chunk aggregation remains core-loop state; the shell owns only its
response-local decision that further chunks have no distinct presentation.

* Design self-check

1. Each committed slice is useful independently; local disposition updates
   remove a multi-second replay from an ordinary correction path.
2. The direction is UI-thread-free persistence and bounded latest-value UI work.
3. Writer transport is a local, replaceable boundary; journal format is stable.
4. The controller owns durability delivery; chat owns presentation state,
   including the durable-message-to-block projection.
5. Interfaces are narrow append/checkpoint/ack and scheduled projection calls.
6. Core policy depends on those contracts, not Node or shell implementation.
7. Filesystem effects are outside the Emacs interactive path.
8. Outbox state is transient; journals are durable; catalog state is rebuildable.
9. Work is coalesced, deferred for hidden buffers, and measured by trace.
10. No speculative common event interface was added.
11. Existing JSONL and catalog reads remain compatible.
12. The default synchronous catalog rewrite is removed from the interactive path.
13. Explicit flush exposes writer errors; unexpected process failure retries.
14. Persistence, recovery, indexed listing, projection, and event-burst paths
    have focused automated coverage.
