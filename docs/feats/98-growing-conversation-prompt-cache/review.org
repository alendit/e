*** TODO Medium/P2 R2-F1: Optional retention overrides unqualified organization capability

F98-C2 requires unknown optional controls to use the endpoint's compatible
automatic path.  =e-openai-profile-cache-retention= at
=lisp/adapters/openai/e-openai-profile.el:526--536= returns ="24h"= for listed

The current official OpenAI prompt-caching guide distinguishes model support
from organization availability: older models supporting both policies default
to extended retention without ZDR and to in-memory retention with ZDR, and the
guide requires verifying model and organization policies before selecting a
value.  Thus this branch demonstrably overrides an organization-dependent
provider default without evidence that the organization supports the override.
The model list proves syntax/model support only.  An HTTP rejection was not
observed or established by the documentation, and is not claimed here.

Source authority: [[https://developers.openai.com/api/docs/guides/prompt-caching][OpenAI prompt-caching guide]],
Cache lifetime / Retention defaults and Zero Data Retention, and Summary of
model differences (consulted 2026-10-05).  This supports provider design only;
it provides no gateway or configured-account acceptance evidence.

Smallest owning correction: omit optional retention while organization
capability is unknown and preserve the provider's eligible default.  The
documented non-ZDR default already selects extended retention; the provider
selects the eligible default for other organizations.  Keep stable internally
derived routing keys for older supported first-party requests.  Add no caller
policy or organization override.  Update the public request witness currently
expecting unconditional =24h= (=e-openai-continuation-composition-test.el:675=)
and diagnostics to describe the provider-selected default.  Parent independently

The pure temporal probe is =/private/tmp/e-feature98/review2-temporal-probe.el=.

ceiling with matching accounting and identity; cold or partial reads cannot
serve as that ceiling.  Require history-attributed reuse beyond it and repeated
state-only/keep transitions retaining the previously reusable unchanged history
at the immediate request, subject to provider granularity.  Distinguish those
transitions from material summary/erase rebuilds, which may warm again.  Prove
the repeated-keep phase and material rebuild phases separately, using the P2
append-only control.  Preserve missing or incomplete attribution as unconfirmed.
Strengthen classifier contract fixtures with both counterexamples and genuine
positive continuity evidence; a single keep-plus-summary warming sequence is
insufficient.
