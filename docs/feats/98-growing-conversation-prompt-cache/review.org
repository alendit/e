* Architecture self-check

1. If this package stopped here, would the project be better off?  It removes
   fixed-only cache policy and prevents unproved curation effects; provider
   benefit still requires external evidence.
2. Final direction: API-capability-owned caching with unchanged-history reuse
   and efficient curation admission.
3. Stable requirements are semantic projection and caller inability to weaken
   caching.  Optional provider syntax and capability proof remain adapter-local.
4. Adapters own syntax; core lifetime/loop owners own presentation and effects.
5. Coupling is reduced by removing harness cache-key and caller-policy APIs.
6. Core depends on backend semantic capabilities, never provider wire fields.
7. Network/auth/cache side effects remain in adapters and opt-in test runners.
8. Added derived capability values live per request; provider caches are
   disposable and accepted session projections remain the only history truth.
9. Automatic boundaries allow new history writes, whose cost is necessary to
   make later history reusable.  No measured latency or cost claim is made.
10. The semantic capability interface reports unavailable support explicitly;
    ordinary chat remains usable without a reserved carrier.
11. Stale caller controls are stripped; old persisted records remain readable.
12. Removed cache defaults/key inheritance, explicit-only selection, factory
    options, and obsolete test policy assertions.
13. Unsupported effects fail at admission/preflight/commit; provider errors
    remain provider errors, and missing cache evidence remains unknown.
14. Credential-free request, forced-effect, lifetime, replay, and classifier
    tests prove owner behavior; public harness composition gates prove joins.
