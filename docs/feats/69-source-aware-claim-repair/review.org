* Review loop

** DONE Medium: The recorded content digest included the URI

*** Problem

The source descriptor called its audit field =content-sha256=, but the first
implementation stored the digest of =URI NUL content=.  That value was useful
for source identity but did not meet the plan's contract for a full content
digest.  It would also change when identical content moved to another URI.

*** Change

=e-context-source-create= now derives the short source handle from
=URI NUL content= and records a separate SHA-256 digest of the content alone.

*** Evidence

The context test now proves that moving identical content changes its handle
but preserves =content-sha256=.  The 189-test context, capability, attachment,
harness, and Bayesian set passed after the change.

* Plan coverage

- Slice 1: context providers can retain internal source descriptors on context
  segments without leaking them into backend message plists.  Chat attachments
  advertise their exact handle, and turn-finished hooks receive captured model
  context.
- Slice 2: Bayesian marks accept and resolve =src:=, snapshot source metadata
  and digest, require a substantive claim, and carry originating handles into
  repair prompts.
- Slice 3: queued repairs are harness-originated, cannot validate themselves as
  human input, and are checked once.  Only accepted repairs hide the original;
  rejected repairs are hidden and record =correction-unresolved=.
- Slice 4: focused and end-to-end regression coverage passed.  Classic chat
  clears terminal pending status; modernchat still omits hidden messages.

* Architecture review

Ownership remains split at real contracts.  Core context owns provider-neutral
source descriptors.  The harness owns input origin and turn lifecycle.
Chat-session owns attachment reads and source annotation.  Bayesian reasoning
owns citation grammar and correction policy.  Shell code only renders generic
audit state.

No stable policy depends on the chat shell, Org canvas, or a backend adapter.
The added durable state is limited to message origin and compact audit
snapshots.  Existing transcripts remain compatible because user messages with
no origin replay as human input.

Source hashing adds two linear SHA-256 passes over content already read for
prompt construction.  It adds no extra file or buffer read and no repair-time
scan.

* Design self-check

1. Each committed slice is independently useful: auditable sources first,
   validated repair second, then the digest-contract review fix.
2. The result moves toward source-traceable answers that recover without
   discarding supported content.
3. The uncertain handle presentation stays local; source identity, origin, and
   one-shot validation remain explicit stable contracts.
4. Each behavior has one owner as recorded in the architecture review.
5. Coupling is reduced through a narrow optional source descriptor.
6. Dependency direction remains from providers and policy toward core
   contracts, never from core toward a shell or capability.
7. Attachment I/O stays at the chat-session edge.
8. Captured model context is turn-scoped; only compact origin and audit facts
   persist.
9. Hashing is bounded to content already materialized and requires no extra
   I/O.
10. Providers can omit source descriptors without weakening their other
    contracts.
11. =in:= and =ev:= remain valid; legacy messages without origin remain human.
12. The role-equals-human assumption and unconditional correction acceptance
    were removed.
13. Expected repair rejection becomes =correction-unresolved=; unexpected
    errors still surface.
14. Core policy is covered without a real backend; shell tests cover only
    presentation consequences.
