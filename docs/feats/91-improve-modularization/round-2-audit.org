#+title: Feature 91 Round 2 Session and Storage Audit
#+startup: overview

* Scope and status

This is the implementation audit for the Feature 91 Round 2 session/storage
family.  It covers =F91-OWNER=, =F91-SESSION=, =F91-TOPOLOGY=, and
=F91-PRESERVATION=.  The implementer left the work uncommitted.  Parent review
accepted the round on 2026-08-30 after requiring and verifying an acyclic
runtime graph, storage-owned physical state, pure codec/catalog boundaries,
and application-service replay/persistence composition.  The running Emacs
was not queried, reloaded, signaled, or changed.

The stable =e-session.el= facade remains the application-service composition
root.  The session aggregate, pure durable codec, pure catalog projection
policy, and current JSONL storage adapter now have separate reasons to change
and one-way runtime dependencies.  Feature 87 remains =Planned=: no SQLite
schema, migration, cutover, new durable format, or replacement persistence
implementation was introduced here.

The intended public behavior is unchanged: documented =e-session-*= APIs,
session values, JSONL/index/checkpoint names and fields, record ordering,
atomic writes, queue/controller retry behavior, recovery errors, lazy and
chunked replay, and restart lifetime remain the preservation contract.

* Actual dependency and call graph

The final owner runtime graph is:

#+begin_example
e-session facade -> aggregate, codec, catalog, storage
aggregate        -> codec
codec            -> e-context-lifetime (stable domain contract)
catalog          -> codec
storage          -> codec
#+end_example

There are no owner-to-facade calls and no mutual owner pair.  The graph above
is the actual call graph, not only the =require= graph: aggregate calls codec
only for the canonical board-routing wire-size copy and JSON-null handling;
catalog calls codec for detached record mapping; storage calls codec for
physical wire mapping and line parsing; and the facade composes all other
joins.  No declaration, callback slot, process-global registry, or service
locator hides a reverse edge.

The application sequence for a normal mutation is:

#+begin_example
facade -> aggregate semantic mutation
       -> codec record-for-entry
       -> storage prepare/commit-mutation
       -> catalog + aggregate detached projections
       -> storage publish-projections at the existing barrier
#+end_example

Replay is similarly one-way: storage reads a detached physical value; the
facade asks codec to decode it; the facade passes semantic data to
=e-session-aggregate-apply-record=; aggregate state changes happen only there.
The codec does not call replay callbacks and the storage/catalog owners never
inspect an aggregate plist.

Evidence: =/tmp/e-session-final-audit-sweep-v4.log= (owner edge counts, zero
foreign private refs, zero facade-private refs, and zero duplicate owner
definitions).  The fresh owner probes in
=/tmp/e-session-fresh-owner-loads-round2-final.log= independently exercise the
same load direction.

* Owner-shaped contracts and Feature 87 replacement trace

The aggregate contract is semantic: create/get/list/fork, typed mutation and
replay application, identity/path/navigation, context/board/provider
projections, and admission state.  It does not expose a storage controller or
physical writer operation.

The codec contract is pure: detached record/index encode/decode, JSON-line
parsing, fixed durable normalization, and =replay-record= returning semantic
data.  It has no store argument and no state mutation.

The catalog contract is pure and bounded: index entry/sort, checkpoint
manifest/JSON projection, retained records, and checkpoint validity.  It does
not read or write files.

The storage contract is the single current adapter direction selected for the
later Feature 87 replacement: registration, bounded session header/reference,
resume checkpoint and journal reads, typed =prepare-mutation= and
=commit-mutation=, admission publication/abort, detached projection
publication, queue flush/finalize, and bounded durability status.  Generic raw
=append-record=, path, index-slot, checkpoint-slot, command, and controller
operations are private storage mechanisms.

Replacing the current JSONL adapter later therefore changes the storage owner
and its adapter tests while preserving aggregate semantic mutation, codec
values, catalog policy, and facade application service.  No expected-revision,
SQLite, migration, or unsupported-operation semantics were invented in this
round.

Deterministic schema/type handling is fixed in the codec and context domain
contracts before replay: record versions and known context types are dispatched
by explicit code, not a load-order-sensitive registration hook.

* Durable format and restart-equivalence record

- Each session remains a newline-delimited UTF-8 JSONL journal named
  =<session-id>.jsonl=.  The derived =index.json= and per-session
  =<session-id>.checkpoint.json= names and JSON fields are unchanged.
- Existing record types, metadata keys, symbol/array normalization, context
  versions, board envelopes, parent/head ordering, index ordering, and
  checkpoint version remain unchanged.  New writes remain v3-only where that
  was already the current behavior; legacy replay handling remains read-only.
- Direct and queued appends retain record order, generation/sequence
  ordering, critical-before-derived index ordering, retry/dedup behavior, and
  the existing Node writer protocol.  Atomic temporary-file replacement and
  controller acknowledgements remain in storage.
- Malformed/truncated-tail, missing/invalid checkpoint, invalid schema,
  admission, and controller errors remain surfaced at the existing boundaries;
  unexpected errors are not swallowed.  Lazy index stubs, cooperative chunked
  replay, and explicit checkpoint migration retain their prior lifetime and
  performance semantics.
- Restart coverage includes chat messages, board identity/messages,
  context generations/promotions/curation, metadata/schema, catalog/index and
  checkpoint recovery, queue/controller retry, and corrupt-tail behavior.

Residual large roots are intentional.  =e-session.el= remains the application
service and stable facade; it is not an implementation copy.  The aggregate
remains one cohesive semantic root because its identity, path, derived state,
board, context, and typed mutation transitions share one reason to change.
The storage owner remains one adapter because direct/queued/Node append,
checkpoint, retry, and atomicity policy share one physical durability reason to
change.  The codec and catalog are smaller pure boundaries.  Further splitting
would be a new scope unless it creates a real independent owner contract.

Known risk is limited to the future Feature 87 adapter replacement and the
external Node writer process boundary; both are explicit and covered by
bounded tests.  There is no known behavioral blocker.  Parent architectural
acceptance is intentionally still pending.

* Design self-check

1. If this package stopped here, the project is better: session meaning,
   mapping, recovery policy, and physical durability have explicit owners,
   direct contracts, and preservation evidence.
2. It moves directly toward Feature 87's local storage replacement and later
   Feature 91 runtime/adapter rounds.
3. Durable formats and public behavior are stable.  The current JSONL adapter
   is the only intentionally replaceable decision; uncertain SQLite details
   remain local to the planned future adapter with no speculative registry.
4. Aggregate owns session meaning and transitions; codec owns wire mapping;
   catalog owns bounded recovery projection; storage owns physical durability;
   facade owns application composition.  Each has one primary reason to change.
5. Coupling is reduced: raw persistence reach-through and representation-only
   owner helpers are gone or private, and the retained boundaries are semantic.
6. Dependencies flow from facade/consumers to stable owner contracts; the
   aggregate-to-codec edge is downward and no owner points to the facade,
   storage, catalog, provider, UI, or transport in reverse.
7. File, timer, process, queue, retry, and atomic-rename effects remain in
   storage; catalog is value-only; aggregate does not perform I/O.
8. Aggregate state is process/store/session-local; storage queue/controller
   state is adapter/store-local; durable files retain restart lifetime; no
   shared mutable record or generic bag was added.
9. No intended runtime work was added.  Existing incremental derived fields,
   bounded checkpoint selection, queue ordering, retry/dedup, and chunked replay
   remain; performance scenarios show no repeated scans or synchronous-write
   regression.
10. The abstractions are real and substitutable: the opaque-owner storage
    contract double commits typed values without aggregate or JSONL internals,
    while the current adapter retains all old preconditions and error behavior.
11. Compatibility applies to documented facade APIs and durable files.  Private
    names have no compatibility promise; obsolete persistence paths were deleted.
12. Removed now: the monolithic persistence module/test mirror, duplicate
    operational copies, foreign private reach-through, raw controller/index
    calls from consumers, and forwarding-only private bridges.
13. Expected malformed-tail, checkpoint, schema, controller, and admission
    errors remain at their owning boundary; unexpected errors surface through
    the facade or test process.
14. Direct owner tests prove each pure/stateful owner independently; facade,
    restart, consumer, and graphical suites prove composition.  An alternate
    implementation satisfying these contracts can replace an owner without
    rewriting unrelated tests.
