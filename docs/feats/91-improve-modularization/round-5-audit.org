** Current lifecycle remediation

The independent review found that the earlier stale-drain terminal branch
retired only the board catalog entry and main client.  On an active board that
left a detached binding discoverable through the harness/session catalog and
left independent subscription clients active after their subscriptions had
been marked inactive.  The correction keeps the service binding when its main
client is still an authorized current client and only its observer lease is
cancelled, faulted, or expired: =e-chat-service-drain-binding= replaces that
observer through the board-registry owner at the old =next-seq= cursor, updates
the binding's observer field, and returns nil for the repair step.  If the
authorized main client was detached, the same service operation installs one
fresh client/requester and observer over that cursor before releasing the old
client.  Both paths require the captured client role to remain equal to the
board's current grant; revocation, role changes, and externally replaced leases
are terminal rather than silently reattached.  The same repair guard is applied
to an asynchronously scheduled main drain.  An expired cursor starts its
replacement at the retained board boundary so it cannot cycle through an
unrecoverable pre-retention position.  No runtime participant attachment or
durable board/session association is recreated or changed.

is the service-side coordinator: it first fences the binding generation,
cancels its observer/subscriber/idle timers, removes the exact service catalogs,

the single runtime owner operation =e-board-runtime-retire-attachment=.

retirement through =e-board-registry-retire-participant-exact=.  Thus the
service never mutates runtime maps or participant state directly, and a
same-id higher-generation replacement is left untouched.  Both service and
runtime retirement are idempotent and accept a held board in =active=,
=closing=, or =closed= state.  They leave durable session and board
association records intact; once registry close finishes, public ensure can
recreate the board and binding and submit normally.

**** Staged transition and retry postconditions

For an exact current attachment, retirement transitions
=live -> local -> maps -> done=.  At =local= it captures the prior work
generation, marks the attachment =retiring=, increments callback generation,
stops its observer (retaining the handle if that stop errors), cancels its
reconciliation request, and settles local producer/activity/invocation state.
The exact participant and all three runtime maps remain authoritative while
the registry/board owner completes route retirement.  A failure at observer
stop, route transition, route timer/replay cleanup, or participant-map cleanup
is propagated; the stage and exact object remain retryable.  A repeated call
is idempotent and re-runs only owner cleanup still needed.  Replacement maps
are never removed because every mutation is object-identity fenced.

Service binding retirement mirrors this contract: it marks the binding
=retiring= and retains the service/catalog identity until
=e-board-runtime-retire-attachment= succeeds.  Thus an unexpected lower-owner
error remains visible, public ensure cannot create an ambiguous duplicate, and
the repeated retirement can complete.  Once successful, the binding becomes
=retired= and service-owned clients/catalogs are removed; durable session/board
association remains available for allowed re-ensure and submit.

| Delivering/accepted/cancelling pickup | Mark source attempt uncertain, settle exact producer delivery/turn slot | Old receipt cannot decrement or publish replacement work |
| Consumed pickup / active turn handoff | Index turn by attachment-local board/participant/generation/turn key; settle on terminal turn receipt or retirement | Retained old =turn-finished= may close its exact producer record only; no output/activity row reaches replacement |

Producer settlement is attachment-local and idempotent.  The producer item
unsettled counter, attachment delivery/turn indexes, and process-local pending
queue counters are all reduced at their owner terminal edge.  The implementation
does not search unrelated board pickups or use a board-global producer index.

**** Exact ordinary-route lifetime fence

=e-board-retire-subscription-exact= owns one exact subscription object and its

removes only the current id-table entry.  Same-id replacement objects retain
their independent token and are not changed.  Repeated retirement of a
cancelled or inactive exact object is a no-op with the same terminal route
postcondition.  The registry operation enumerates participant routes and
delegates every transition to this board owner before removing source and
registry participant maps.  Admission rollback uses the same operation;
durable participant removal remains its explicitly documented event-emitting
exception.

** Correction mechanics and exact phase evidence

Invocation terminalization first verifies exact table ownership, sets terminal
state, removes the target, and decrements only =open= or =applying=.  The
unsettled notification runs after that transition, so a signaling hook leaves a
terminal object and a retry cannot decrement again.  If an invocation callback
retires its attachment, retirement owns the transition and the outer apply is
an idempotent no-op; repeated completion reports the existing unknown-target
error without changing accounting.

Pickup scheduling captures the current generation in the timer closure.  A
retirement that removes attachment-owned queue cells increments the generation,
clears the scheduled bit, and schedules any remaining queue under the new
generation.  A retained callback from the old generation returns before
touching the queue.  If retirement occurs during a drain, the generation check
stops the old page and the retirement fence owns the replacement scheduling.

Grouped classification captures one exact route at authorization, stores it in
the classification's authorized map and participant bucket, and copies its
participant object into each prepared pickup.  Group, prepare, and commit each
revalidate subscription object/token and participant identity.  A route retired
after any of those phases changes the whole transaction to
=subscription-lifetime-changed= before the pickup set becomes visible.  A
committed stale pickup is failed and its producer record is settled directly by
delivery id, whether or not a current attachment exists.

** Failure partitions and mechanical-equivalence notes

The runtime registers the exact invocation object in both owner indexes, then
increments the invocation count.  A post-notification commit check requires
the same global/local object, count token, open state, and current active
attachment.  A board-stage signal or normal return after same-key replacement
therefore aborts only the old board token and leaves the replacement authority.

Board staged appends push an exact receipt before returning to a caller that can
signal after list/tail/message-count mutation.  Abort removes exact index cells
then newest staged event cells, while preserving monotonic sequence allocation.
An inverse that signals before mutation leaves its receipt and maps as the sole
retry authority; the runtime retries the same board token once
inside the initiating transaction.  An inverse that signals after mutation has
already acknowledged its receipt, so a repeated abort is a no-op.  The first
unexpected admission error remains the surfaced error; no replacement is
rediscovered or removed.

The only mechanical exception is the addition of process-local object/receipt
fields and the opaque lease value at an existing board effect seam.  Successful
public behavior, durable formats, ordering, atomicity, retry/error visibility,
and restart semantics remain equivalent.  The Work source owner did not need a
new implementation file; its exact inverse contract is covered directly.

   mutates the event map/list/head/link/tail/message-count fields.  Staged

** Exact transition, inverse, and error evidence

For both event and index append, the receipt exists before the first observable
mutation.  The forward stage is acknowledged only after each corresponding
map/list/head/link/tail/count mutation.  The inverse verifies the exact current
node, captured predecessor and successor, root/head, and queue/board identity;
it updates the successor before discarding the detached predecessor.  A raw
cons cell whose owner node was detached is rejected.  Two staged admissions
can be aborted in either order; an interleaved unrelated event/index cell is
kept; repeated inverse calls are no-ops after the receipt is terminal.

Deadline removal marks its exact receipt terminal before changing the routing
count notification.  Thus a reentrant abort cannot decrement twice, and a
notification fault leaves the receipt's exact retry state.  Terminal classifier
and deadline records retain exact aggregation objects rather than looking up an
equal id during a later drain.  Legacy fallback drains exist only for old
explicitly constructed in-memory records lacking a receipt; production queues
take exact paths and the fallback does not participate in admission authority.

Board admission cleanup removes classifier receipts, index receipts, event
receipts, exact activation/map state, and timer/deadline state in owner order.
Runtime cleanup performs one bounded retry of the same token; if both inverse
attempts fail, the primary initiating error remains surfaced and the exact
token remains in the board/runtime recovery catalog.  A later related
operation retries the captured token before creating replacement state.  No
descriptive id, global scan, or replacement lookup is used.

The aggregation effect closure is intentionally not an admission map/index
authority: it is the existing deferred effect-drain record and is fenced by
the exact aggregation/activation state after abort, preserving normal
cancellation semantics.  The admission covers the prepared activation and
event that make that effect eligible; the ordinary effect count is settled by
the existing bounded effect drain.
