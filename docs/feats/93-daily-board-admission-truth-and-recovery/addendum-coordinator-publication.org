#+title: Addendum 2: Coordinator-Owned Daily Completion and Publication
#+startup: overview

* Status

In-progress.

The operator approved this addendum on 2026-09-16 after a live Daily run
demonstrated that the accepted Board-first workflow could still strand a run:
model-owned shell timeout semantics killed a required collector, the
reconciliation model had to drive separate =:apply= and =:finalize= actions,
literal prose matching rejected an otherwise terminal projection, and the
generic topic turn hook committed the Board-owned Daily independently of the
publication lifecycle.

This addendum changes completion ownership, not the Daily's Board identity,
source policy, generated section names, or SQLite authority.

* Behavioral goal

Goal =F93A2-G01=: one Daily coordinator scatters the selected gatherers, receives
one durable terminal projection after every gatherer succeeds, fails, or reaches
the run-owned deadline, obtains one typed complete section map from the sole
reconciliation continuation, validates it before mutation, and performs one
idempotent publication containing the Daily note and admitted generated
artifacts.  Any pre-publication failure leaves the note and Git history
unchanged and remains durably visible.

Direct scenario: all selected gatherers settle while Slack fails optionally.
The terminal projection contains the typed gap, reconciliation supplies every
generated section exactly once, the coordinator commits the Daily and admitted
raw artifacts once, and SQLite reaches =finalized=.  A deadline, invalid
reconciliation result, restart, and retry are adversarial partitions of this
same scenario.

* Ownership and transaction order

1. The Daily controller freezes one absolute deadline in the manifest and
   dispatches each selected task with that deadline.
2. =e-work= owns the timer and cancellation.  =e-subagent-runner= owns the
   exactly-once conversion from child settlement to the terminal Board report.
3. Existing Board orchestration owns durable reduction and the bounded terminal
   continuation projection.
4. The sole hidden reconciliation continuation may only submit the typed Daily
   result.  It receives no file/Git mutation action.
5. The Daily publication application service validates the entire candidate
   before its first write.  It alone materializes, commits the exact admitted
   paths, and records publication/finalization.
6. Presentation and generic turn hooks do not participate in this transaction.

Unexpected runtime, validation, storage, or Git errors surface through the
coordinator Work and durable lifecycle evidence.  Expected optional-source
failure is represented as a typed gap.  No broad error swallowing or prose
matching decides publication.

* Deadline policy

The contract requires a positive absolute run deadline, not one public numeric
value.  Grimoire supplies a private configurable default of 900 seconds.  The
observed deterministic collector takes about 49 seconds, so this admits more
than an order of magnitude of measured collector time plus model and transport
variance while bounding participant/process occupancy and eventual fan-in.
At the exact deadline unsettled child Work fails and cancellation is requested;
an already terminal report wins.  Revisit the default if healthy runs approach
12 minutes or resource evidence requires a tighter occupancy bound.

* Delivery packages

** F93A2-DP1: Deadline-aware Board dispatch

Add the narrow optional absolute-deadline input to Board-addressed subagent
dispatch and prove exactly-once terminal publication under expiry and late
callbacks.  This establishes F93A2-C01 and is independently useful to any
Board-run consumer.  It changes core runtime behavior and requires a full
Emacs restart to use in the running process.

DP1 delivery evidence: the Board dispatch API validates and forwards one
positive absolute timestamp into the admitted child Work context and metadata.
The Work deadline remains the runtime owner of failure and provider
cancellation; the runner's publication observer converts only the typed
=e-work-deadline-exceeded= settlement into one durable failed terminal report.
The existing live settlement guard makes provider callbacks after expiry
no-ops.  Focused coverage proves the ordinary queued/running acknowledgement,
deadline expiry and cancellation, exactly one terminal report, the late
callback path, and the unchanged dispatch path when no deadline is supplied.
Parent accepted the scoped e implementation at commit
=45fe89f60a69068cd5997307da458a00bf58a8a1=; core runtime changes require a
restart of any process that should use the new dispatch contract.

** F93A2-DP2: Coordinator-owned Daily completion

Consume DP1 from the Grimoire controller; bound the runtime-owned collector by
the same run deadline; replace ordinary model-driven =:apply=/=:finalize= with
one typed reconciliation result and one internal publication operation; exclude
Board-owned Dailies from generic turn commits; update instructions and tests;
and pass the configured cold-start gate.  This establishes F93A2-C02 through
F93A2-C06.  If work stopped here, the ordinary public Daily path would have one
completion owner and one publication boundary.

The split follows the =e=/configured-consumer ownership boundary.  DP2 may not
be accepted without DP1.  Internal materialization and finalization steps stay
together because separating them recreates the stranded externally driven
workflow this addendum removes.

DP2 implementation evidence is now available in the Grimoire working tree:
the direct batch ERT suites pass daily-run 50/50, publication 25/25 (including
typed optional-gap injection when the model omits or paraphrases the failure,
exactly-once rendering, unchanged no-gap maps, and lifecycle gap persistence),
and topic-commit 12/12; the configured cold-start gate passes 8/8.  Parent
acceptance remains pending for DP2; no running Emacs or canonical Board was
reloaded or mutated while collecting this evidence.

* Compatibility and removals

- Preserve SQLite Board/run/task/attempt and publication lifecycle formats.
- Preserve restart recovery and exact Git evidence; no data migration.
- Remove the ordinary Daily reconciliation prompt's =:apply= and =:finalize=
  instructions and remove their model-facing action surface when no remaining
  supported caller requires it.
- Retain internal materialization/finalization helpers only as private phases of
  the one publication operation and the explicit offline incident repair.
- Do not add a second scatter/gather framework, session identity, completion
  store, fallback commit path, or prose-based gap detector.

* Non-goals

- Repairing or mutating the currently stranded live Daily or Board;
- changing source selection, section prose policy, or Board-facing UX;
- replacing Board orchestration or its durable terminal reducer;
- adding presentation polling or exposing sessions as Daily identity; or
- reloading or restarting the user's running Emacs automatically.
