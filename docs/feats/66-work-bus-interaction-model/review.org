* Review summary

All eight High findings are resolved.  Public chat shells now use one
board-backed application service for session creation, input, observation,
controlled reads, and abort; bundled runtime producers require explicit live
producer bindings and publish facts with generation-fenced source identities;
and the process-level quiescence request composes constant-time owner
projections behind one admission epoch.

and client revocation fence later work, deferred routing rechecks current
subscription lifecycle, exact invocation effects revalidate the composite
endpoint generation, retryable delivery remains scheduler-owned, and retained

now prevent public shells, chat capability ingress, or bundled producers from
reintroducing direct live harness/session paths.

*** Expected

board client, post input to the board, observe matching board records without
consuming them, and retain no standalone session path.  The same slice deletes
direct live-session create/prompt/queue/steer interfaces, generic harness
presentation feeds, missed-final transcript fallback, and =:handler=/=:start=
tool-registration branches.  See =plan.org:1553-1576= and
=plan.org:1710-1720=.

*** Observed

The plan's own implementation ledger says that Slices 0--4 remain private and
that the supported product is wholly pre-cutover (=plan.org:296-303=).

- Chat creates a harness session at =lisp/shells/chat/e-chat.el:2009-2014=,
  subscribes directly to harness events at =e-chat.el:2079-2092=, reads durable
  messages/activity for missed-final recovery at =e-chat.el:7786-7813=, and
  reads the harness active-turn table at =e-chat.el:9311-9316=.
- =e-chat-service= is still a facade over direct session creation, submit,
  steering, and queueing (=lisp/shells/chat/e-chat-service.el:77-104=).
- Starter, modernchat, debug, Org Canvas, and Canvas still create/read/subscribe
  through harness/session state.  They have no explicit board-client cutover
  disposition.
- =e-tools-register= still accepts/stores =:handler= and =:start= and branches
  over them (=lisp/core/e-tools.el:241-268= and =e-tools.el:925-975=).
  =await= is registered through =:start= at =lisp/core/e-await-tool.el:145-161=.
- The structural start-boundary test fails because of that =await= registration.

No =e-board= reference exists in the main chat/session service paths.  This is
consistent with =cutover-audit.org:23-44= and =cutover-audit.org:65-70=, not with
a completed feature.

*** Why it matters

The top-level product contract requested by this feature is absent.  Calling
the private primitives “implemented” would expose neither board-only ownership
nor the required observer UX, and attempting to activate them alongside the old
paths would create the mixed compatibility mode the plan explicitly forbids.

*** Smallest corrective direction

Keep the private services private until the other blockers in this review are
closed.  Then perform one source cut with an explicit shell matrix.  For every
public entrypoint, record its board/client/participant binding, observer
selector and correlation rule, retained UX, and migrate/remove/disable decision.
Replace tool registration with only the current =:work= and dedicated
invocation-subscription contracts; do not update legacy allowlists to bless
=:handler=/=:start=.

*** Verification required

  caller or model-facing =:handler=/=:start= registration.
- Per-shell tests prove each entrypoint is board-backed or explicitly disabled.
- The complete board/chat end-to-end scenario in =plan.org:1714-1722= passes
  after a full restart, with no transcript fallback or standalone session.

*** Resolution

=e-chat-service= is now the single board-backed application seam.  It creates
and attaches sessions, owns a board client/requester/observer binding, posts
=inject= and =queue= input, translates immutable board messages for shell
reducers, and exposes controlled read projections.  Chat, starter, debug, Org

*** Evidence

*** Expected

Cron, file/annotation triggers, domain events, task queue, and subagent changes
must post to an explicitly configured live board with descriptive tags,
attributes, and a stable source key.  Zero matching subscribers must stay
unrouted and must never create a session or autospawn (=plan.org:1568-1571= and
=plan.org:1709=).

*** Observed

- Task queue records no board binding, and its default runner creates a session,
  subscribes to harness events, reads the transcript, and prompts directly
  (=lisp/core/e-task-queue.el:553-608=).
- Subagent direct execution subscribes and prompts a child harness and spawning
  creates a child session (=lisp/layers/agents/e-subagent-runner.el:107-147= and
  =e-subagent-runner.el:234-269=).
- Background triggers lazily create a session and submit a prompt directly
  (=lisp/shells/e-background-session.el:216-250=).
- Cron still routes to task queue/background session or an arbitrary =:call=

- Annotation dispatch and sweep route directly into subagent/task paths
  (=lisp/layers/annotations/e-annotation-answer.el:157-182= and
  =e-annotation-answer.el:213-248=).

The plan says boards are process-local but does not yet make the producer target
lifecycle concrete: a persisted producer cannot safely treat an old board id as
a live destination after restart.

*** Why it matters

These paths can still create standalone sessions and bypass board identity,
routing, observation, authorization, and causal audit.  A stale process-local
board target could also make a timer appear enabled while silently pointing at
nothing.

*** Smallest corrective direction

Define one runtime-scoped producer binding containing a live board reference/id,
producer epoch, tags/attributes, and source-key generator.  On startup or board
replacement, a missing/historical target must leave the producer visibly
disabled or faulted until explicit rebind.  Remove arbitrary cron coordination
callbacks and lazy harness/session wake paths; keep domain registries
authoritative and publish their facts asynchronously without weakening domain
mutation order.

*** Verification required

Test every bundled producer or its explicit disabled state: enable without a
live board fails; stale restart targets never fire work; retry posts one
idempotent fact; zero matches remains unrouted and creates no participant.

*** Resolution

The runtime now owns explicit process-local producer bindings with a producer
epoch, live board identity, tags/attributes, and stable source-key sequence.
Task queue, cron, background triggers, annotation answer/sweep, and subagent
registry changes publish facts through those bindings.  Missing or stale
bindings fail visibly; arbitrary cron callbacks and lazy session paths were
removed.  Subagent child sessions enter through the board-backed chat service.

*** Evidence

- The bundled-producer structural regression passes.
- The 55-test task/cron/background selection and four board-only annotation
  tests pass.
- Producer tests cover missing/stale bindings, idempotent facts, and zero
  participants after publication.

** DONE High: Runtime quiescence cannot yet authorize the full-restart cutover

*** Expected

The cutover closes one O(1) admission epoch and asynchronously waits on bounded,
owner-local projections proving that no active turn, invocation, work carrier,
queued input, pickup/receipt/effect, control request, producer item, or writer
outbox remains.  It must never poll, scan, wait on the main thread, or race a new
admission (=plan.org:1555-1558= and =plan.org:1710=).

*** Observed

=cutover-audit.org:13-19= explicitly says runtime quiescence cannot be proven.
The runtime, harness, and =e-work= now contribute useful counters, but board-core
receipt/effect state and persistence writer state do not; direct harness callers
remain outside the runtime gate (=cutover-audit.org:46-63= and
=cutover-audit.org:89-108=).  No controlled aggregate runtime-quiescence request
exists.  The offline preparation command has correctly not been run on user data.

*** Why it matters

Without this fence, the offline snapshot/store swap can race accepted in-memory
work or writes, lose a queued interaction, or carry an old callback across the
cardinal record-shape change.  A scan-based substitute would still race and
would violate the no-main-thread-blocking requirement.

*** Smallest corrective direction

Add board-core and persistence owner counters plus hard-bounded change hooks at
the exact state transitions that own them.  Route every remaining root/control
start through the runtime admission epoch.  Build one controlled request that
freezes the epoch, composes only those projections, reports named blockers, and
settles from change notifications.  Only then run the separate offline
preparation and full restart.

*** Verification required

Use held fake owners to prove each blocker class prevents a green result,
settlement wakes the request without polling, stale epoch callbacks cannot
reopen admission, and an independent heartbeat/composer edit runs between
bounded progress steps.

*** Resolution

One O(1) admission epoch now fences board-runtime roots and producers.  The
controlled quiescence request composes owner-local counts and monotonic change
notifications from board core/registry, runtime, every harness, =e-work=, and
session persistence.  It reports named blockers, never scans or polls, and only
its opaque fence token can reopen its epoch.

*** Evidence

Held-owner regressions prove every blocker class holds the request pending,
owner notification settles it, cancellation leaves admission closed, and a
stale token cannot reopen a later fence.  The 67-test runtime/structural
selection passes.

** DONE High: Revocation does not fence the original requester or attached clients

*** Expected

Current authorization must be rechecked before delivery, including the frozen
requester and exact-target grant.  Revoking board/client read access must advance
the client-generation fence and schedule bounded observer closure before later
delivery (=plan.org:887-889= and =plan.org:1313=).

*** Observed

=e-board-registry-participant-delivery-authorization= checks only the target
participant and its principal (=lisp/core/e-board-registry.el:680-709=).
=e-board-runtime--deliver-pickups= calls that target-only function before the
adapter and after acceptance (=lisp/core/e-board-runtime.el:1888-1936=), even
though the pickup retains its frozen requester actor
(=lisp/core/e-board.el:2175-2177=).

A bounded probe exact-posted through a requester's target =post= grant, routed
the input, revoked that grant, and drained delivery:

#+begin_example
(:calls 1 :state consumed :requester "requester")
#+end_example

The current uncommitted tests revoke the target participant principal, so they
do not cover this requester/grant case.

Separately, =e-board-registry-revoke-principal= only removes the grant
(=lisp/core/e-board-registry.el:284-296=).  Requester resolution compares a saved
context to the still-active client record without consulting current grants
(=e-board-registry.el:390-409=), and observer installation requires only that
client record (=e-board-registry.el:411-433=).  A bounded revoke probe returned:

#+begin_example
(:resolved "member" :client-state active :observer "observer")
#+end_example

*** Why it matters

Revoked authority can still disclose or deliver protected content and can keep
reading through a live observer.  This is a security boundary failure, not a
retention or eventual-consistency choice.

*** Smallest corrective direction

Make delivery authorization consume the frozen requester actor, input mode, and
target; recheck current board membership and exact-target grants both before the
adapter call and when reconciling acceptance.  Principal revocation must detach
or generation-fence affected clients and close their observers in bounded
scheduled work.  All requester and observer operations must consult the current
grant, not only the captured client role.

*** Verification required

Add revoke-after-route tests for requester membership and cross-target grants,
plus requester resolution, post, observer install/page/accept, and held-page
callback tests after client principal revocation.

*** Resolution

Delivery authorization now rechecks the frozen requester actor and target
participant before adapter entry and accepted-receipt reconciliation.
Principal revocation advances affected client generations, detaches requester
authority, and closes owned observers in bounded scheduled work.  Requester
resolution and observer operations require the current grant and generation.

*** Evidence

Registry/runtime tests cover requester membership revoke, exact-target grant
revoke, revoke during acceptance, requester resolution, observer install/page
acceptance, and held-page callbacks after client revocation.

** DONE High: Deferred routing ignores later subscription lifecycle transitions

*** Expected

Append may pin the historical selector/effect bytes, but a later mute, cancel,
replace, or timeout must be applied in board sequence before effect or pickup
start.  A held classifier may record its historical match, but no cancelled
pickup/effect may start (=plan.org:884-886= and =plan.org:1626=).

*** Observed

=e-board--queue-input-classification= copies every subscription at append
(=lisp/core/e-board.el:2213-2225=).  Pickup finalization later rechecks
authorization but never resolves the current subscription identity/state
(=e-board.el:2127-2203=).  The continuation path has a lifecycle fence, but the
ordinary pickup path does not.

A held-classifier probe appended a tagged input, cancelled the subscription,
and then released classification:

#+begin_example
(:routing routed :pickups (("board" "input" "p")) :subscription cancelled)
#+end_example

*** Why it matters

Cancellation, mute, and replacement are not reliable: work can start after the
consumer revoked its interest.  Replay cannot reproduce the plan's declared
board-sequence semantics if live execution uses the stale copied state.

*** Smallest corrective direction

Keep the pinned immutable selector bytes for historical/audit evaluation, but
also retain the subscription identity and source-state version.  Before pickup
or activation mutation, resolve the board-owned current lifecycle and apply all
later ordered transitions as a suppression fence.

*** Verification required

Add held-classifier tests for cancel, mute, replacement, and expiry.  Each may
record a historical match but must create no pickup/effect, must release its pin
once, and must advance the cursor deterministically.

*** Resolution

Frozen selector bytes remain historical audit input, while finalization now
resolves the board-owned current subscription identity and lifecycle version.
Cancel, mute, replacement, expiry, or later authorization revoke suppresses
pickup/effect creation in board sequence and releases the captured pin once.

*** Evidence

Held-classifier regressions cover cancel, mute, replacement, expiry, and
authorization revoke; all pass in the board-core selection.

** DONE High: Exact invocation effects can call a stale endpoint generation

*** Expected

An exact invocation freezes the original attachment token, participant,
endpoint, turn, and composite generation.  A lost or replaced endpoint becomes
unavailable/uncertain and must never deliver to a replacement or stale callback
(=plan.org:902-905= and =plan.org:1707=).

*** Observed

Invocation registration stores the attachment object and only its local
attachment generation (=lisp/core/e-board-runtime.el:333-355=).  Effect
application compares that stored integer to the same attachment record but does
not call the existing current/composite attachment check
(=e-board-runtime.el:357-379=).

A bounded probe enrolled a qualified invocation, removed its harness registry
mapping, settled the work, and drained the effect:

#+begin_example
(:current nil :reply (finished "done") :invocation-state committed)
#+end_example

*** Why it matters

An exact tool result can mutate the transcript/loop belonging to an endpoint
that is no longer current.  That breaks exactly-once correlation across harness
replacement and violates the board/runtime ownership boundary.

*** Smallest corrective direction

Freeze the opaque endpoint token and full composite instance/harness generation
in the invocation target.  Revalidate the exact current attachment before
effect application and receipt reconciliation; mark an invalidated target
unavailable or uncertain and never resolve a replacement by session identity.

*** Verification required

Replace or clear the qualified endpoint between enrollment, terminal
classification, effect application, and acknowledgement.  Assert no stale
callback, one visible terminal effect state, and no delivery to the replacement.

*** Resolution

Invocation targets now freeze the opaque endpoint token and full composite
instance/harness/session generation.  Acceptance and effect application both
use the current-attachment check.  A lost or replaced endpoint settles visibly
unavailable/uncertain without calling stale completion code or resolving a
replacement by session id.

*** Evidence

The acceptance-generation and stale-invocation-effect regressions pass beside
the qualified rebind generation tests.

** DONE High: Retryable delivery failures can strand a ready pickup

*** Expected

Every ready pickup either receives a bounded retry/backoff or reaches a visible
terminal failure.  One item failure must not stop independent participants, and
all terminal turn edges must release/retry eligible FIFO work
(=plan.org:1678= and =plan.org:1717=).

*** Observed

The pickup drain removes the queue key before adapter invocation
(=lisp/core/e-board-runtime.el:529-550=).  If the adapter signals,
=e-board-runtime--deliver-pickups= returns the pickup to =ready= and re-signals
without re-enqueueing it (=e-board-runtime.el:1968-1971=).  Busy delivery is
also returned to =ready=, but only =turn-finished= re-enqueues the participant;
=turn-failed= and =turn-cancelled= do not (=e-board-runtime.el:763-776=).

The two bounded probes returned:

#+begin_example
(:caught error :pickup-state ready :pending 0 :queue nil)
(:calls 1 :pickup-state ready :pending 0 :queue nil)
#+end_example

*** Why it matters

The board says the input is routed and ready, but no scheduler owns its next
attempt.  The input can remain permanently invisible to the participant, and a
signalled error can also abort the current drain before unrelated work runs.

*** Smallest corrective direction

Contain errors per pickup.  Either schedule an explicit bounded retry/backoff
with attempt budget or commit a visible terminal failure; never leave =ready=
without a queue owner.  Re-enqueue the safe FIFO head on every relevant
turn-terminal idle edge, including failure and cancellation.

*** Verification required

Add signal-once-then-success, busy-then-failed, busy-then-cancelled, exhausted
retry, and first-participant-error/second-participant-continues tests.

*** Resolution

Each pickup failure is isolated.  Retryable failures retain one
scheduler-owned ready record and a bounded retry budget; exhaustion becomes a
visible terminal failure while other participant lanes continue.  Every turn
terminal edge releases an eligible FIFO successor, and accepted queued input
reconciles through exact consumed/discarded receipts during reset or detach.

*** Evidence

Signal-once retry, exhausted signal, independent-lane continuation,
busy-then-failed/cancelled, reset, and participant-removal FIFO regressions pass
in the 67-test runtime selection.

** DONE High: Several scheduled paths still do unbounded main-thread work

*** Expected

Non-blocking means both no synchronous wait and no unbounded main-loop
occupancy.  Append/settlement does only fixed work; routing, effects, observers,
registry/catalog operations, persistence, and UI yield under explicit
record/byte/work-unit budgets.  Hot paths perform zero full-log/registry scans
(=plan.org:1734=, =plan.org:1698=, and =plan.org:1717=).

*** Observed

- Input append copies the complete subscription list before scheduling the
  classifier (=lisp/core/e-board.el:2213-2225=).
- Event and message append copy their growing lists with =append=
  (=e-board.el:298-305= and =e-board.el:2055-2058=).
- A live observer page starts at the beginning of the message list and scans the
  prefix before its cursor (=e-board.el:1520-1533=).
- A history page calls =reverse= on the complete message log before applying its
  page limit (=e-board.el:1345-1361=).
- Registry paging visits every board and repeatedly sorts/bounds a candidate
  list (=lisp/core/e-board-registry.el:306-330=).

Moving these operations into a zero-delay timer does not bound their occupancy.
The focused tests assert page result counts and matcher calls, but have no
sentinel that fails when retained-prefix or subscriber/registry work exceeds the
declared budget.

The full suite's direct-render guard also fails because the legacy handler
adapter uses raw =e-work :render= in =lisp/core/e-tools.el=, while board tests use
the UI carrier as a generic async fake.  Updating the allowlist would weaken the
intended boundary.

*** Why it matters

Large histories, many subscriptions, or many boards can freeze Emacs on append
or on one scheduled callback.  This directly violates the user's no-main-thread-
blocking requirement and invalidates the plan's performance acceptance claims.

*** Smallest corrective direction

Use O(1) tail queues or indexed append structures for logs, generation/index
references instead of copying all subscriptions, sequence-indexed observer
cursors, and an ordered registry index capable of bounded continuation.  Keep
UI rendering behind =e-ui-work=; use an appropriate cooperative fake carrier in
board tests and delete the legacy handler adapter during cutover.

*** Verification required

Add instrumented storm tests whose counters fail if append, page, or drain work
depends on retained prefix length, total subscriptions, or total boards beyond
the configured budget.  Hold each page while an independent heartbeat and
composer edit run, and make both currently failing structural tests pass without
expanding their allowlists.

*** Resolution

Board events/messages append through owner-local tail cells and retain an
ordinal message index.  Live/history observers address bounded index windows

* Architecture review

The dependency direction now matches the target.  =e-work= remains independent
of the board; board core owns ordered routing/settlement facts; registry owns
identity, authorization, and cursors; runtime owns endpoint composition,
admission, producers, and quiescence; the core =e-chat-service= is the narrow
application seam; presentation shells own buffers, reducers, and UI work only.

Deferred work is also genuinely bounded: owner-local tail/index structures make
append and page cost independent of retained prefixes, while explicit budgets
yield between classification, effects, pickups, activity, producers, observer
pages, and UI mutation.  No adapter hides a whole-collection scan.

No compatibility window was retained.  Direct live presentation/producer
paths, legacy tool registration, arbitrary producer callbacks, session-context
annotation export, metadata repair, and the one-shot preparation command are
removed; structural tests reject their reintroduction.
