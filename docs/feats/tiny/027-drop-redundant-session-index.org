#+title: Drop Redundant Session Position Index

* Status

Done.

* Change

Stop creating =session_records_position(session_id, position)= because the
=session_records= composite primary key already creates an index on the same
columns in the same order.  Existing v5 stores remove the named secondary index
idempotently during worker open; this is a physical index-layout correction,
not the planned v6 logical-schema migration.

Add a regression proving both that a new store omits the index and that opening
an early-v5-shaped store drops it.  The implicit primary-key index remains.

This is tiny because it removes one redundant physical structure without
changing stored rows, query semantics, public interfaces, or schema version.
