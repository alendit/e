* Failed boundary

Feature 88 =F88A3-SEM= requires the next ordinary request after a consumed
observation to exclude its raw observation, call, replay item, result marker,
and contaminated response IDs.  =F88A3-DELIVERY= disallows an
observation-bearing response or descendant as a durable cross-turn anchor.
The steering fixture's request C still contains =RAW-STEERING-RESULT= in its
neutral messages.  A same-state OpenAI request-shape probe sent no network
request: with a valid profile-matching anchor, C used
=previous_response_id="resp-B"= and only =steer now= as literal input; without
that anchor, the canonical body included =RAW-STEERING-RESULT= as a
=function_call_output=.  The current request is therefore unsafe in either
shape.  The direct evidence is
[[file:../88-generational-context-ephemeral-frames/addendum3.org][Feature 88 Addendum 3]]
contracts =F88A3-SEM= and =F88A3-DELIVERY=, plus the steering ERT in
=test/e-harness-context-lifetime-composition-test.el=.

=e-loop= currently drains queued steering in =start-request=, including the
immediate provider request that carries a curation acknowledgement.  Separating
that protocol request from the next ordinary request is a candidate recovery
seam; verify it against native replay and canonical refresh before changing
policy.  Keep the immediate acknowledgement request-local and one-shot.
