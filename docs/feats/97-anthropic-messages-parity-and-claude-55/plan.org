* Behavioral goal

- Goal ID :: =F97-ANTHROPIC-COMPOSED-TURN=.
- Behavioral goal :: A user can select an accessible Claude 5.5 Messages model
  through the engineering gateway, use ordinary tools and model-directed
  ephemeral-source curation, continue with valid Anthropic tool history, and
  reuse a stable prompt-cache prefix without changing what the model sees.
- Direct scenario :: Select the gateway's =claude-opus-5-5=.  Present stable
  instructions and a changing ephemeral source.  The model calls an ordinary
  tool, then uses =context-curate= to keep one source and omit another.  The
  immediate follow-up contains the exact signed thinking/tool blocks required
  by Messages, a matching tool result and curation acknowledgement, but no
  consumed source marker.  The model answers; a later user turn reconstructs
  canonical context without the omitted raw source.  A repeated request with
  the same stable prefix reports cache creation and then cache read tokens.
- Product authority :: The user/operator through Feature 97.  A proposed
  change to curation meaning, labels, limits, or durability returns to Feature
  88's owning contract before this adapter plan changes.
- Owning contracts :: =F97-C01=--=F97-C06= below.
- Behavioral status :: Partial at the direct gateway boundary: Opus 5.5
  accepts basic Messages, cache control, and native tool use.  The composed
  =e= scenario is unavailable until the planned adapter packages exist.
- Mechanism status :: Not started.

Here a /semantic checkpoint/ means Feature 88's durable, provider-neutral
context boundary.  An Anthropic /cache checkpoint/ is a =cache_control= marker
on a wire prefix.  A cache hit accelerates a request; it never keeps or drops
source content on behalf of =context-curate=.

* Supporting design and ownership

** Capability declaration and context semantics

Once its carrier and cache layout are proven, the Anthropic backend can declare
=:continuation none=, =:observation-delivery inherited=,
=:prefix-cache explicit= when enabled, =:provider-compaction none=, and
=:reserved-effect-carrier context-curate-wire=.  Declare =:reasoning-state
replayable= only for effective model/options whose signed blocks the adapter
actually carries.  A configured beta =context_management= request alone does
not establish =e='s opaque provider-compaction operation.  Do not claim
request-local replacement or server-side continuation from cache hits.

The harness already owns stable, dynamic, and ephemeral segment meaning.  The
Anthropic adapter should render the complete leading system projection and use
segment identities only to choose eligible =cache_control= positions.  Feature
88's request-local ephemeral marker is informational and belongs next to its
matching source.  Core should identify that generated marker as a typed
request-local projection item; Anthropic should render it as a text block
immediately before the corresponding =tool_result= in the same user content
array, preserving both labels and result order.  It must not hoist these late
markers into the top-level system prefix or parse marker text to recognize them.
Other system content retains its order and the source value remains unchanged.
The same translation applies to full and continuation projections, with cache
on or off.
Start with the last eligible stable system block and preserve the existing
explicit =5m=/=1h= TTL option.  A later request for multiple distinct cache
boundaries should use the same segment identities and Anthropic's documented
checkpoint rules, with a separate request-shape and gateway proof; Feature 97
does not invent a generic checkpoint configuration surface.  Tool definitions
precede system blocks in Anthropic's cache prefix, so changes to tool schemas
must invalidate a previously warm prefix.

** Native Messages replay and curation

The Anthropic decoder should collect one assistant response's content blocks by
native index until =message_stop=.  Keep exact signed =thinking= or
=redacted_thinking= material and the relative order of thinking, text, and
=tool_use= blocks in an opaque, provider-tagged request-local replay bundle.
The collector must validate terminal completion and required replay before it
emits any ordinary tool call.  Missing terminal completion, invalid block
order, or absent signed material fails the response without dispatching tools;
cancellation discards the bundle.  This applies to injected and buffered
requests in =F97-DP2=.  =F97-DP5= later streams text incrementally but retains
the same effect-admission guard.
The renderer substitutes that bundle for the just-produced assistant tool
envelopes, groups all calls in one assistant content array, and groups their
ID-matched results in the following user content array.  It must not append
duplicate synthetic =tool_use= blocks or split one native response into a
series of assistant/user pairs.  A curation-only response has no ordinary tool
entry, so its native =tool_use= and acknowledgement travel through the existing one-shot
=:provider-request-replay-items= path.  For mixed ordinary and curation calls,
one native assistant block sequence covers all calls in original order, and the
ordinary result and reserved acknowledgement share the matching user array.

The semantic =context-curate= arguments, label validation, commit, and
duplicate budget stay in Feature 88's core/loop owners.  Before adding the
Anthropic carrier, move OpenAI's current schema literal and guidance to a
narrow core-owned carrier descriptor with the current revision and limits.
OpenAI and Anthropic each map that descriptor to their own wire format and
prove schema, guidance, and revision parity.  The Anthropic adapter builds ordinary =tool_use= definitions
separately from the reserved carrier and filters the reserved name before
application-tool dispatch.  Keep corrective/invalid acknowledgements provider
local and one-shot.  Session projections already remove replay metadata from
later durable context; test that boundary rather than persisting signed
thinking as a new semantic record.

** Usage and model limits

The decoder should add one unambiguous full-context-input count to the
provider-neutral usage event, while keeping Anthropic's fresh input, cache
read, cache creation, output, and total counters separately available.  The
core budget consumes that full-context value when present and retains its
existing fallback for other adapters.  Model inventory must tolerate a listed
model without =max_input_tokens= and return unknown for its window; it must not
turn a successful catalog fetch into a fabricated limit.  A configured limit
requires a gateway-specific contract or probe, not only public model claims.

** Transport completion

Keep the existing cancellable request handle and idle deadline.  Incremental
SSE decoding belongs in the Anthropic transport/decoder, with bounded partial
line/event buffering and exactly one completion/error/cancel transition.  Text
may stream for display, but effectful tool and curation items wait for a valid
terminal response.  Do not emit a =done= item or promote an anchor from a
missing =message_stop=, a provider =error= event, or a truncated HTTP body.
The synchronous injected requester remains a test seam but must obey the same
terminal validation.

the selected Opus endpoint.  Existing transcript and curation records need no
migration.  Opaque signed blocks live only for the causal follow-up and are not
a new durable context authority.  The added work is linear in the already
bounded response blocks and SSE bytes; no request-time catalog lookup, polling,
or synchronous network call belongs in the interactive path.  Tool dispatch
waits until =message_stop= rather than =content_block_stop= so a later stream
failure cannot follow an already executed effect.

The smallest faithful aggregate uses the existing backend capability and
one-shot replay seams, one core-owned carrier descriptor for shared Feature 88
meaning, and a typed request-local marker projection for Anthropic's native
layout.  Keeping the schema literal separately in each adapter would reduce a
small shared boundary but allow curation meaning to diverge.  Letting the
Anthropic adapter infer markers from text or own source lifetime would remove
the typed boundary at the cost of brittle classification or inverted ownership.
The selected aggregate adds no durable state or generic checkpoint layer; its
six delivery packages separate complete accounting, replay, cache, curation,
transport, and profile outcomes with focused evidence before one composed gate.

Before implementation, check that each chosen abstraction serves an actual
cross-adapter contract: the existing backend capability values, core-owned
curation schema, and one-shot replay seam suffice unless a concrete test shows
otherwise.  Core must not import Anthropic fields; the adapter must not decide
source lifetime.  Unexpected wire or replay errors surface as failed turns.
External cache and Sonnet access remain explicit unknowns until fresh gateway
evidence resolves them.  A completed mechanism package does not make the
direct behavioral scenario pass.

* Design self-check for implementation review

Apply these questions to each package and again to their final composition.
The planned answers identify the present design direction; implementation
evidence must replace assumptions before a =Done= decision.

1. If this work package stopped here, would the project be better off than if
   it had not been built?  Each DP states a useful independently testable
   outcome, even when the full scenario still waits for DP6.
2. What final direction does this move toward?  One provider-neutral context
   policy with native Messages and Responses adapters.
3. Which decisions are likely to change, uncertain, or stable, and are
   uncertain ones local and reversible instead of hidden behind speculative
   abstraction?  Gateway access, TTL, and effective limits remain profile or
   adapter evidence; Feature 88 disposition meaning stays stable.
4. What component owns this behavior, and why?  Core owns curation and budget
   semantics; Anthropic owns wire shape and SSE transport; configuration owns
   model selection.
5. Does this change increase or reduce coupling?  Are interfaces narrow,
   consumer-shaped, and free of unused capabilities?  Use the existing backend
   capability and one-shot replay seams; share only the real curation carrier
   descriptor.
6. Did any dependency start pointing the wrong way, especially from stable
   policy toward concrete adapters, providers, UI, transport, persistence, or
   tool clients?  Check that core imports no Anthropic or OpenAI module.
7. Could any side effect be moved outward into an adapter or shell?  Catalog
   HTTP, SSE, and provider acknowledgements stay in the Anthropic adapter;
   semantic commits stay in the harness/session owner.
8. What state does this change add or mutate?  Who owns it, how long should it
   live, how often does it change, can it be rebuilt, and why is this the
   smallest correct storage lifetime?  Signed replay and partial SSE state
   last one causal request; semantic curation remains in existing durable
   records; model metadata is refreshable adapter cache.
9. What is the performance impact of this change?  Any regression must be
   justified from first principles.  Parsing is linear; text streams sooner;
   effectful dispatch may wait for =message_stop= to avoid truncated-response
   side effects.  Measure that delay in the configured scenario.
10. Are the abstractions and interfaces semantically real, and can
    implementations substitute for each other without narrowed preconditions,
    weakened behavior, ignored requirements, or unsupported-operation errors?
    The shared carrier descriptor must express one Feature 88 disposition;
    capability values describe only behavior the effective endpoint supports.
11. What compatibility expectations apply, and were obsolete paths removed
    unless required?  Preserve used older profiles; remove duplicate schema
    literals and replace the denied Opus 5 selection after validation.
12. What legacy code can we remove now?  Remove the Anthropic buffered-only
    happy-path completion and any redundant cache/system renderer after its
    replacement proves parity; do not retain dead compatibility branches.
13. Where are expected errors handled, and where do unexpected errors surface?
    Access denial and known transport errors are classified at the adapter;
    malformed replay or inconsistent curation fails the turn visibly.
14. What tests prove the core behavior independently of the full system?  If
    the design changed, would tests change narrowly, or would unrelated tests
    need rewrites?  =F97-S1=--=F97-S5= prove owner boundaries;
    =F97-S6a= and =F97-S6b= prove endpoint capability and composition
    separately.  Keep mechanism fixtures local.
