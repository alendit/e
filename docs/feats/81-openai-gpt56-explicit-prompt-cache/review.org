#+title: Review: OpenAI GPT-5.6 Explicit Prompt Cache
#+date: 2026-08-12
#+startup: overview

* Status

In-review.

* Review summary

The adapter now translates e's stable/dynamic segment boundary into the
documented GPT-5.6 explicit cache layout for provider profiles that declare
support.  The implementation also corrects the built-in ChatGPT Codex profile:
that endpoint requires =store=false= and can continue from the active socket's
connection-local response ID, but currently rejects both explicit cache fields.
It therefore uses the same segment-aware developer input without breakpoint
fields: stable context is carried by continuation and changed dynamic context
is re-emitted.

The repository contract is implemented and deterministic tests pass.  A
credentialed explicit-cache hit/write measurement remains unresolved because
the available ChatGPT Codex endpoint is not a compatible provider.

The follow-up alignment slice adds a canonical =openai= API profile and makes
the shared contract executable rather than conventional.  ChatGPT and API use
one segmented-context renderer, WebSocket continuation/fallback path, and
stateless encrypted-reasoning replay path.  Endpoint/authentication and the two
explicit cache fields are the only intended request differences.

* Scope reviewed

- generic segment propagation from =e-loop= into request-local backend options;
- OpenAI Responses rendering, cache capability gating, anchor layout revision,
  WebSocket full fallback, and usage parsing;
- built-in Codex profile normalization, segmented context, and =store=false=
  local continuation;
- canonical first-party API profile and cross-profile body equivalence;
- encrypted reasoning attachment to assistant/tool-call transcript carriers and
  ordered replay during full stateless requests;
- durable cache-write token telemetry and process reporting;
- deterministic unit/integration tests and synthetic credentialed E2E tests;
- the OpenAI prompt-caching and WebSocket-mode documentation current on
  2026-08-12.

* Findings

** Resolved High: model-name inference broke ChatGPT Codex

*** Problem

The first implementation enabled explicit fields for every model named GPT-5.6
or later.  Credentialed synthetic probes returned =Unsupported parameter:
prompt_cache_options= and =prompt_cache_breakpoint is not supported on this
model= from ChatGPT's =gpt-5.6-sol= endpoint.

*** Change

Explicit rendering now additionally requires provider profile capability
=:prompt-cache-breakpoint-mode explicit=.  The built-in Codex profile forces
that capability off; compatible OpenAI API profiles can opt in.

*** Evidence

The Codex profile unit test supplies GPT-5.6, a cache key, and stable segments
and proves the unsupported fields are absent while stable guidance remains a
distinct developer input segment.

** Resolved High: built-in Codex store normalization violated the backend

*** Problem

The previous normalization removed configured =store=false=.  A credentialed
HTTP diagnostic returned =Store must be set to false=, while the WebSocket
closed or stalled under the stored request shape.

*** Change

The built-in profile now forces =store=false=.  WebSocket completed responses
remain valid connection-local anchors; a lost socket or unresolved ID uses the
existing complete replay path.

*** Evidence

The synthetic credentialed WebSocket basic-response test passed in 10.392603s.
The original two-turn =store=false= continuation test passed incrementally in
13.834208s.  After segmenting ChatGPT context, the credentialed test passed in
10.975508s and proved the endpoint accepts separate stable and dynamic
developer input, the continuation candidate omits stable context, refreshed
dynamic context is present, and no explicit-cache field is sent.  The endpoint
closed its socket during that run, so transport correctly selected complete
segmented replay; deterministic transport tests cover the warm-socket branch.

** Resolved Medium: documented E2E timeout was ignored

*** Problem

=E_E2E_TIMEOUT_SECONDS= was documented but the board E2E wait helper always
used its hard-coded 30-second default.

*** Change

The helper now parses the positive environment value when no explicit timeout
argument is supplied.

*** Evidence

The credentialed test that initially timed out at exactly 30 seconds proceeded
under the configured 180-second budget after the fix.

** Resolved Medium: ChatGPT/API parity was not enforced

*** Problem

The adapter already shared most rendering and transport code, but only ChatGPT
had a built-in provider profile.  API profiles were local configuration, and
segmentation was named as a prompt-cache layout even though both providers need
the same Responses context layout.

*** Change

The built-in =openai= profile selects the first-party API endpoint,
=OPENAI_API_KEY=, GPT-5.6, WebSocket =store=false=, segmented developer input,
explicit breakpoints, continuation, and encrypted reasoning.  The shared layout
field is now =:responses-context-layout=.  A provider contract test normalizes
away only =prompt_cache_options= and =prompt_cache_breakpoint= and requires the
remaining ChatGPT/API bodies to be equal.

*** Evidence

Focused adapter tests prove the canonical profile values and structural request
equivalence.

** Resolved Medium: stateless replay discarded encrypted reasoning

*** Problem

Both first-party profiles use =store=false=.  Full replay reconstructed visible
messages and tool traffic but did not request or preserve encrypted reasoning
items returned by Responses.

*** Change

Both profiles request =reasoning.encrypted_content=.  The adapter emits opaque
replay items; the provider-neutral loop attaches them to the assistant message
or tool call they immediately precede.  The common Responses renderer restores
those items in their original position only for OpenAI.

*** Evidence

Parser, loop, assistant replay, and tool-call replay tests cover the complete
deterministic path without exposing encrypted content as transcript text or
provider diagnostics.

* Plan coverage

- Segment propagation: implemented without persisting derived segment data.
- Explicit request shape: implemented and provider-gated.
- Dynamic suffix after the marked stable developer block: implemented.
- Continued and full-fallback layouts: implemented with revisioned anchors.
- Cache write telemetry: implemented through durable activity and process
  reporting.
- Credentialed hit/write counters: test exists and requires an explicit-capable
  provider; the new =e-e2e-config-openai-api.el= selects the canonical profile
  when =OPENAI_API_KEY= is available and remains intentionally unrunnable
  against current ChatGPT Codex.

* Architecture review

Provider support lives in the provider profile and OpenAI adapter, not generic
context policy.  The loop exposes its already-derived segment list through
request-local options.  Durable state stores the response anchor, wire layout
revision, and opaque encrypted reasoning attached to its transcript carrier;
it never stores a derived segment cache.  Unsupported providers preserve their
previous request layout.

* Design self-check

1. The package is safer and more observable even if work stops here: Codex is
   live again and compatible providers can use the new layout.
2. This moves toward provider adapters faithfully translating generic context
   placement into provider-native cache controls.
3. Provider feature availability is uncertain and remains a local profile
   value; the stable segment contract and GPT-5.6 wire shape are explicit.
4. =e-context= owns placement, =e-loop= owns request assembly, and =e-openai=
   owns provider rendering and transport behavior.
5. One optional profile field reduces coupling to model-name guesses.
6. Generic policy does not depend on OpenAI request fields.
7. Network and serialization side effects remain inside the adapter.
8. Anchor layout revision and opaque stateless replay items are durable;
   segments and capability flags remain derived per request.  Replay items live
   on their smallest correct transcript carrier rather than in adapter-global
   or session-global cache state.
9. The renderer adds one segment scan and avoids cache-write churn when enabled;
   unsupported providers retain the old work.
10. The profile capability names a real wire compatibility difference proven
    by provider responses.
11. Older models preserve the legacy shape.  ChatGPT GPT-5.6 uses segmented
    input without unsupported breakpoint fields.
12. The obsolete normalization that removed =store=false= was replaced.
13. Expected unresolved-response errors retry with a full request; unexpected
    provider errors surface through normal backend failure.
14. Renderer units, harness integration, WebSocket integration, and live probes
    cover progressively wider boundaries.
