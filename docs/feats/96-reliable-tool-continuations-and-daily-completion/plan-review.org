* Review loop

** Resolved P1: speculative callback diagnosis did not match production

The first draft blamed duplicate callback request adoption, but production Bash
does not use =e-tools-callback-work=.  A current-source reproduction established
the actual owner: invocation-detail portability mapping mistakes a list of
resource plists for one alist object and creates duplicate =:uri= keys.  The
plan now repairs that exact projection and deletes the zero-production-consumer
callback constructor instead of redesigning it.

** Resolved P1: progress failure could disable the only terminal observer

The direct runner invoked consumer progress in the same subscription callback
which observed terminal events.  A throwing callback could fault the
subscription before settlement.  =F96-C03= now isolates progress as bounded
best-effort projection and tests both nonterminal and terminal callback errors.

** Resolved P1: terminal ordering ignored asynchronous Board publication

The first draft settled Work before starting/ignoring Board publication.  The
review restored Feature 82's required ordering: a coordinator-supplied,
pre-start Work terminal gate latches one proposal, awaits its idempotent Board
terminal publication, and only then commits Work terminal state and retires
live ownership.

** Resolved P1: the low-level runner could not control Work deadlines

The direct runner does not own child Work, deadline timers, Board target, or
live state.  The final plan assigns progress safety to the direct runner and
terminal convergence to the surrounding subagent coordinator through a narrow
generic Work gate.  Work continues to own the exact deadline and prompt provider
cancellation; only terminal commit waits for publication acknowledgement.

** Resolved P2: unsupported retry/reopen promise

No existing runner retry API or durable generic terminal intent can reconstruct
a lost process-local proposal.  The plan no longer invents either.  Publication
failure becomes a typed persistence-suspect Work failure containing both causes.
Reopen follows current Grimoire policy exactly: an ambiguously committed
terminal fact wins; orphaned running attempt 0 advances to durable attempt 1;
orphaned running attempt 1 terminalizes; an already-pending selected attempt is
the only unchanged redispatch.

** Resolved P2: interrupt and shutdown bypassed convergence

Public interrupt/shutdown directly cancelled, settled, published, and removed
live state.  The final physical boundary includes those paths.  They cancel the
provider promptly once, propose =cancelled= through the same gate, and retain
post-admission Work/live ownership until acknowledgement or composite
publication failure.

** Resolved P1: pending cancellation could resurrect or double-settle

Keeping a startable pending reservation during publication would allow late SQL
admission to start a cancelled provider.  Late admission failure could also call
=on-failure=, publish a competing failed terminal, and independently settle the
dispatch Work.  The final plan fences by removing the startable reservation
before publication.  Every later admission result—finished, failed, or
cancelled—is inert beyond request-local cleanup.  A detached gate closure alone
owns prepared child Work, the cancelled proposal, and dispatch settlement.
Tests cover all outcome orderings before and after acknowledgement.

** Resolved P2: cancelled dispatches disappeared from Daily aggregation

Grimoire counted only admitted and failed dispositions.  The final contract
requires an explicit =:cancelled= total and =attention= state when failed or
cancelled dispositions are present, preserving Feature 93's distinct bounded
cancellation outcome.

** Resolved P2: contracts and Daily packages were over-combined

Canonical Feature 94 behavior and eager capability readiness are prerequisites,
not reimplementation contracts.  Calendar already uses =fast-tool-user=; only
its executable =gog= guidance changes.  Calendar and exact saving now have
separate owner-local packages.  Exact saving is noninteractive, limited to the
closed commit-file set, and failure-propagating.
