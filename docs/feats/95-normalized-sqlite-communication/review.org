* Review loop

** DONE High: Board clear stranded session associations

*** Problem

=board-clear= copied participants into the new generation but left the current
session association referencing the retired generation.  Session-addressed
routing could therefore stop working after clear.

*** Change

The same Board transaction now advances matching association generations and
their revisions after copying participants.

*** Evidence

=e-board-sqlite-service-clear-advances-session-association= proves association
lookup and session-addressed append in generation 2.

** DONE High: Activity reads discarded normalized participant identity

*** Problem

The activity query selected only participant id and opaque payload, so current
name, principal, role, and state could disappear even though their authority
had moved to relational columns.

*** Change

The bounded set query selects the normalized participant columns and
reconstructs the canonical participant DTO through the shared worker helper.

*** Evidence

=e-board-observation-test-participant-columns-author-activity-page= verifies
the immediate and reopened page.  The isolated graphical participant-prefix
test also passes.

** DONE High: Resume and retry conflated task state with attempt history

*** Problem

Every transition to =queued= rewrote the prior attempt to =failed=.  Resume
therefore corrupted a paused attempt, while retry could race a reclaim before
the =running=-to-=queued= transition committed.

*** Change

Ordinary resume leaves attempt history unchanged.  Retry supplies a separate
=:attempt-transition= value which settles the failed attempt atomically with
the task transition.  SQLite success is now the redispatch boundary, so a new
claim cannot observe the pre-transition task state.

*** Evidence

=e-runtime-store-task-resume-preserves-paused-attempt-history= and
=e-runtime-store-task-retry-settles-prior-attempt-before-reclaim= pass before
and after reopen.  The final reviewer also audited task-owner FIFO and the
=claim-pending-p= duplicate guard.

** DONE Medium: Migration invented or accepted non-derivable facts

*** Problem

Migration supplied the current clock when a v7 Board record lacked
=:created-at= and accepted active =running= or =pausing= tasks with no attempt.
Those choices created durable facts that could not be derived from the source.

*** Change

Migration now rejects missing record creation time and attemptless active task
topologies with Board or queue/task/status keys.  It does not repair them.

*** Evidence

=e-runtime-store-offline-v7-rejects-underived-normalized-facts= covers missing
time plus attemptless =running= and =pausing=.  The final migration suite passed
32/32.

** DONE Medium: Retired Board record aliases remained accepted

*** Problem

The orchestration reader still preferred legacy =:kind=, and fixtures retained
=:kind= and =:durable-position=.  That preserved a second representation after
the v8 clean cut.

*** Change

Orchestration consumes only canonical =:record-kind=; current-schema fixtures
no longer emit the aliases.  Legacy shapes remain only inside historical
migration fixtures.

*** Evidence

The orchestration suite passed 17/17, and the implementation review found no
stale =F95-DP1= cells.

* Architecture self-check

1. The package is independently useful: current and upgraded stores now have
   one coherent communication authority and reject corrupt source facts.
2. It moves toward SQLite-authoritative, bounded domain storage with detached
   consumer DTOs.
3. Stable v8 semantics are modeled directly.  The only uncertain boundary,
   historical v7 interpretation, is isolated in the stopped-store upgrader and
   fails closed when facts are not derivable.
4. Board, session-query, task, and migration workers each own their relational
   facts; queue policy owns scheduling.  No presentation component owns SQL
   policy.
5. Coupling is reduced by removing duplicated payload fields and aliases.
   Adapters expose narrow typed operations and detached DTOs.
6. Domain policy does not depend on presentation.  Runtime owners depend on
   their storage ports; SQLite details remain in adapters/workers.
7. SQLite mutation, migration, and process effects remain at worker and
   adapter boundaries; reconstruction and policy helpers remain pure where
   practical.
8. Only durable identity, immutable event facts, and mutable domain state are
   stored.  Display/progress caches remain process-local; rebuildable selector
   indexes remain relational projections.
9. Bounded reads use set queries rather than N+1 reconstruction.  No accepted
   performance regression was introduced.
10. The task storage port, Board operations, and DTO helpers represent real
    substitutable contracts; no implementation ignores required operations.
11. Schema v8 is an explicit clean cut.  Compatibility exists only in the
    offline v7 upgrader; ordinary startup rejects v7.
12. Duplicate payload authority, four Board record aliases, the unread
    session-admission table, and obsolete runtime branches were removed.
13. Expected source conflicts fail in migration with bounded identifying keys;
    unexpected SQLite and worker errors surface through existing top-level
    request settlement.
14. Owner-local ERT proves joins, transitions, bounds, rollback, and reopen;
    the graphical test narrowly proves the visible attribution behavior.
