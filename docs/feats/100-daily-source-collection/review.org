* Architecture and design self-check
1. Would stopping here leave the project better off? :: Deterministic collectors, executable MCP promotion, and durable selected-attempt commit scope are accepted independently and through the actual Daily/Canvas owners.
2. What final direction does this move toward? :: Source-specific mechanical work belongs below model interpretation, with durable evidence and narrow summaries between workers and coordinator.
3. Which decisions may change? :: Slack text-envelope grammar and Gmail CLI adaptation can change locally; frozen windows, stable identities, and truthful coverage remain stable contracts.
4. Who owns the behavior? :: e owns generic tool activation/context lifecycle; Grimoire owns Daily collection and report policy; the external helper owns Gmail process I/O and local normalization.
5. Does coupling change? :: Worker prompts depend on compact evidence and collector facts instead of source pagination protocols; no provider-specific policy was added to e.
6. Do dependencies point correctly? :: Grimoire calls existing public e Work, MCP, Board, session, and subagent APIs; core e does not depend on Grimoire.
7. Can side effects move outward? :: Gmail commands, Slack MCP calls, artifact writes, and Git commits remain at their existing process/client/filesystem owners.
8. What state is added? :: Run/task/attempt candidates and query-identity checkpoints are rebuildable evidence; successful watermarks persist only accepted complete coverage. The bounded coordinator descriptor lasts with its durable session under an existing capability-state namespace. Turn-local executable registries live only for the turn.
9. What is the performance impact? :: Collection needs no model turns; overviews have a byte ceiling. Whole-window enumeration is retained because Slack does not supply a reliable edit/delete fingerprint for safe detail reuse.
10. Are abstractions real? :: Existing Work and Board contracts are reused; source adapters expose only Daily's required frozen-window collection behavior.
11. What compatibility applies? :: User notes and existing source artifact paths for other workers are preserved. New Gmail/Slack candidates are explicitly scoped; obsolete model paging-ledger admission is removed.
12. What legacy code was removed? :: Repeated activation schema output, worker-controlled Gmail/Slack paging, and the manually asserted Slack paging ledger no longer own these paths. The commit hook no longer consumes mutable flat Daily metadata; public reopen supplies the canonical namespace before activation.
13. Where are errors handled? :: Collectors classify expected source failures and preserve evidence; manifests retain explicit partial/unavailable gaps. Invalid artifacts fail their owning Work; subprocess diagnostics and credential-bearing structures are not propagated.
14. What independently proves behavior? :: Source fixtures, real process interruption/timeout probes, public collector/report/SQLite tests, and configured/graphical composition gates cover separate boundaries; parser changes stay local to source fixtures and actual-format replay.
