* Findings

** P2 F87-PR01: The session placement inventory is stale after Feature 91

The plan says Feature 87 was rebaselined on Feature 91's session/storage
boundary (=plan.org=:8--11), but P1 says to introduce =e-session-storage=
(=plan.org=:140).  The design inventory assigns JSONL, checkpoints, and the
catalog to =e-session.el= plus the Node writer (=design.org=:23--25).

That is not the current source boundary.  Accepted Feature 91 Round 2 says the
stable facade is =e-session.el=, semantic mutation is in
=e-session-aggregate.el=, normalization/replay is in =e-session-codec.el=,
catalog/recovery policy is in =e-session-catalog.el=, and the replaceable
JSONL/index/queued/Node adapter already exists in =e-session-storage.el=
(=docs/feats/91-improve-modularization/plan.org=:143--152).  The source says the
same thing directly: =lisp/core/e-session-storage.el=:8--11 owns the current
physical adapter and is intentionally replaceable by Feature 87, while
=lisp/core/e-session-aggregate.el=:8--12 owns semantic mutation without
physical I/O.

This is an implementation-placement defect, not naming polish.  Following the
current wording could recreate a storage boundary, put SQLite behavior in the
facade, or bypass the accepted aggregate/catalog/codec dependency direction.

Owning correction: update the current-state inventory and P1 placement at the
existing session-family boundary.  Do not add a second session storage facade
or teach the aggregate SQL.

Proposed replacement for =design.org=:23--25:

#+begin_quote
Session semantics are exposed through the stable =e-session.el= facade.
=e-session-aggregate.el= owns loaded identity/path state and semantic mutation,
=e-session-codec.el= owns deterministic durable normalization and replay,
=e-session-catalog.el= owns catalog/checkpoint projection and recovery policy,
and =e-session-storage.el= owns the current replaceable
JSONL/index/queued/Node physical adapter together with
=e-session-writer.mjs=.
#+end_quote

Proposed replacement for =plan.org=:140:

#+begin_quote
Replace the JSONL/index/queued/Node implementation behind the existing
=e-session-storage= boundary with the typed SQLite worker protocol; preserve
the accepted =e-session= facade, aggregate, codec, and catalog dependency
direction.
#+end_quote

** P2 F87-PR02: F87-C12 cannot be established completely by P1

=F87-C12= combines two independently changing outcomes: process/host-loss
durability and restrictive permissions for all artifacts (=plan.org=:83).
The row maps both to P1, whose scope can establish database/WAL behavior and
permissions (=plan.org=:131--154).  P4, however, first creates the migration
working files, reports, verified pre-upgrade backup, explicit backups, exports,
and disposable-store system path to which the same permission requirement
applies (=plan.org=:242--255; =design.org=:306--331).  P1 cannot prove the
permission behavior of operations that do not exist until P4.

The row therefore fails one-observable-contract normalization and package
closure.  It also makes the bidirectional contract/package relation inaccurate:
part of the accepted C12 outcome is established only by P4 although the matrix
assigns it exactly once to P1.

Owning correction: keep the failure/durability outcome in C12/P1 and give P4's
operator-artifact permission behavior its own P4 contract row, or move that
behavior into a single existing P4 row whose public composition and S9/S10
evidence cover it.  Do not add a generic security or artifact framework.

Proposed C12 wording:

#+begin_quote
WAL =synchronous=NORMAL= preserves database consistency and acknowledged
commits across e/worker process failure; it does not promise survival of the
latest acknowledgement after host or power failure.  The database and WAL use
restrictive local permissions.
#+end_quote

Proposed P4 permission row wording if a new row is selected:

#+begin_quote
Migration and upgrade working files, deterministic reports, verified
pre-upgrade backups, explicit backups/exports, and disposable pathname copies
use restrictive local permissions; encryption and key management remain out
of scope.  Owner: migration/upgrade and worker-owned operator operations.
Package: P4.  Evidence: S9 artifact-permission matrix and S10 negative scan.
#+end_quote

** P2 F87-PR03: The 0.07-second release gate has no reproducible threshold record

P1 makes the 15,722-record/38 MB resume no slower than an approximately
0.07-second checkpoint baseline unless an approved explanation changes the
gate (=plan.org=:160--162).  The source observation was a closed operator store:
the journal was 37,851,478 bytes, its checkpoint 5,756,709 bytes, and one batch
run took about 0.07 seconds
(=docs/bugs/session-resume-replays-full-journal/investigation.org=:41--48;
=docs/feats/78-session-resume-checkpoints/review.org=:81--91).  The reviewed
plan names no repository fixture identity or construction, command, warm/cold
cache policy, sample count, statistic, reference machine, or exact threshold.

Consequently the check is neither reproducible as a deterministic release gate
nor safely classified as telemetry.  “Approximately” cannot decide pass/fail,
and an unspecified approval escape cannot repair the missing evidence record.
The structural no-full-scan and interactive-responsiveness invariants are
valid deterministic targets; the historical wall-clock observation is not yet
one.

Owning correction: make bounded indexed work and timer/commit progress the
deterministic gate.  Treat the historical 0.07-second value as observational
unless product authority adds a complete reproducible performance record.

Proposed replacement for =plan.org=:160--162:

#+begin_quote
The test-owned 15,722-record/37,851,478-byte fixture restores through indexed,
paged reads without reading unrelated audit history; the interactive timer
advances and queued commits complete during the load.  Record elapsed resume
time against the historical approximately 0.07-second operator-store
observation as observational telemetry.  A deterministic wall-clock regression
gate may replace that telemetry only after the plan records the fixture or
generator, command, cache policy, sample count, statistic, environment,
pass/fail threshold, and revision trigger.
#+end_quote

This correction preserves the AGENTS.md requirement that any observed
regression receive a first-principles justification; it stops presenting an
unrepeatable observation as an exact gate.
