* Review summary

Package 4 makes the one-store SQLite composition the ordinary runtime backend,
adds explicit offline migration and schema upgrade operations, removes the
production Node/task/raw/cron/voice/Goodnite sidecar writers and the
Board/session log-owner proxy, and adds bounded maintenance and cutover proof.
This artifact records repository-side evidence; it does not self-approve the
feature or claim live operator behavior.

The final mechanism deliberately has no durable writer-command ledger,
command hash, ordinary revision/CAS protocol, or automatic resubmission.
Worker loss fails active and queued operations once and freezes that store
object.  Because the interrupted write may have committed, recovery is an
explicit close/reopen followed by owner reload from canonical SQLite state.
A submitted timeout applies the same freeze.  Callback failure cannot interrupt
failure fanout or publish a late success; it remains visible in bounded status.

* Operator UX

The entrypoints are deliberately offline and positional:

#+begin_src sh
scripts/e-runtime-migrate dry-run COPIED_LEGACY_SOURCE UNUSED_TARGET
scripts/e-runtime-migrate install COPIED_LEGACY_SOURCE NEW_STATE_DIRECTORY
scripts/e-runtime-upgrade CLOSED_STATE_DIRECTORY [BACKUP_FILE]
#+end_src

The source argument must be a copy, the migration target must not exist, and an
upgrade target must be closed.  The later operator gate must copy the real
legacy tree to =/tmp= and invoke only =dry-run=; neither command should point at
the running operator store.  Both commands reduce failures to a bounded
single-line operator message rather than emitting a decoded-state backtrace.

* Findings

** DONE High: Worker acknowledgement machinery exceeded the selected failure model

Earlier packages retained stable command hashes, a durable writer-command
ledger, owner revision preconditions, and automatic resubmission after worker
loss.  The operator replaced that model with simple single-worker ownership.
The adapter and worker now remove those relations and arguments; worker loss
fails all outstanding requests once and freezes the store until explicit
close/reopen and owner reload.  Runtime-store 13/13 and the unified SQLite
50/50 suites cover the replacement behavior.

** DONE Medium: Reentrant Board drains could run inside a durability wait

A zero-delay input-routing or chat observer callback could run while its Board
was mutation-frozen by the cooperative worker wait, reject itself, and lose the
only wake.  Board durability now owns a process-local post-barrier callback
queue.  Board runtime and chat service defer already-admitted drains behind
that barrier and retain their generation fences.  The combined preservation
suite passes 315 expected results with no unexpected result.

The same gate exposed a stateless policy-copy defect: a completed node was
never removed from the active path, so two fields sharing one finite selector
were mistaken for a cycle.  The task-stack leave marker and a direct finite-DAG
regression resolve it without adding state or a persistence abstraction.

** DONE Medium: A retired legacy test wrote an opaque SQLite reference as a file

The legacy-context compatibility test appended JSON to the value returned by
=e-session-storage-session-reference=.  After cutover that value is an opaque
=sqlite:session:*= reference, so the test left a root-level sidecar artifact.
It now builds a copied =sessions/*.jsonl= fixture and invokes the read-only
legacy decoder directly.  The focused regression and final full suite pass the
test, leave no pseudo-reference file, and keep production legacy decoding
offline-only.

** DONE High: Copied-tree inventory silently omitted durable and retired state

The first copied-operator dry run exposed two files absent from the migration
mapping: a nested Grimoire Daily task queue and the retired chat-overview read
marker sidecar.  Migration now discovers every =task-queue/**/records.eld=,
maps the root to =default= and nested queues to stable relative identities, and
imports their task-owned history.  The chat-overview file is explicitly
classified as a preserved derived presentation artifact: commit =e28957c1=
moved its useful high-watermark into session metadata, and current read markers
are process-local presentation state.  Inventory rejects every file without an
explicit import, validation/rebuild, or retirement disposition.

The same operator attempt showed that an uncaught batch backtrace could print a
large decoded snapshot.  Migration and upgrade entrypoints now catch and bound
operator errors; a 256 KiB failing task payload produces less than 4 KiB of
combined CLI output in the focused test.

The corrected copied-tree rerun then enumerated 1,674 additional unmatched
files in one bounded pass: 1,249 active session checkpoints, 300 checkpoint
backups, 115 journal backups, 3 index backups, and 7 historical nested task
=.org= fragments.  Active checkpoints are session-owned resume state.  The
legacy decoder now validates them, translates each JSONL byte boundary to the
equivalent SQLite record position, and the migration application persists the
otherwise exact value through =e-session-storage=.  Timestamped backups remain
inactive rollback inputs, and task =.org= fragments remain external historical
products; both classes are hashed and reported as source-preserved instead of
silently ignored or promoted to runtime authority.

* Architecture review

The default composition is the sole process-level owner of the runtime store.
Domain owners receive narrow ports; only worker-side owner modules know SQL.
Migration is an application service over isolated legacy decoders and owner
ports.  Upgrade is a separate offline worker because ordinary startup cannot
own that side effect.  Reports, backups, exports, and subprocess pathname
copies are explicit file products rather than a second runtime authority.

The P4 source additions have distinct change reasons: runtime protocol/schema
maintenance, offline upgrade, legacy decoding/import, default composition, and
operator scripts.  Board/session association now owns only association and
notification composition; it has no durable Board-log proxy or owner table.

* Design self-check

1. The package leaves a usable one-store default plus safe adoption and
   maintenance operations, so stopping here is better than retaining split
   sidecars.
2. It reaches the accepted direction: one SQLite authority with semantic owner
   ports and explicit offline adoption.
3. Private schema details, report representation, and timing remain local and
   reversible; the stable owner contracts and offline-only rule are modeled
   directly.
4. Runtime-store owns protocol and connection lifetime; each domain owns its
   facts; migration owns legacy-to-current composition; defaults own process
   assembly.
5. Coupling is reduced by deleting file writers and injecting narrow ports;
   removing cross-restart command reconciliation also removes a generic
   protocol concern from every owner operation.
6. Policy still points toward domain contracts.  SQL and filesystem upgrade
   effects remain outward in worker/adapter modules.
7. Database, backup, report, and rename effects are in physical adapters or
   operator application services, not session/Board policy.
8. New durable state is current schema metadata and migration identity.  It is
   process/store lifetime state at the smallest cross-restart scope.
9. Interactive work remains on the worker; reads are paged and write priority
   is preserved.  Recorded wall-clock values are observational.
10. Owner ports are consumer-shaped and substitutable for their accepted
    contracts; unsupported old schemas fail explicitly rather than narrowing a
    hidden fallback.
11. Preserved legacy sources are inactive rollback input.  Ordinary legacy
    writes and automatic compatibility paths are retired.
12. Node session/task writers, raw-result files, cron/voice/Goodnite sidecars,
    and Board-log ownership can be removed now; pure decoders remain only for
    migration.
13. Expected version, ownership, conflict, and malformed-input errors are
    targeted.  Unexpected worker, codec, and filesystem errors surface;
    worker loss freezes the store until explicit reopen/reload.
14. Focused owner tests prove migration, nested-queue preservation, complete
    inventory disposition, bounded operator errors, upgrade, restart,
    permissions, cutover, and bounded progress independently; broad and
    isolated E2E gates protect composition.
