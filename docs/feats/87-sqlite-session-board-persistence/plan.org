* Goal and boundary

One =<e-state-directory>/store.sqlite3= becomes the only ordinary persistent
authority for all e-owned mutable runtime state:

- sessions, catalog and resume projections, message display, and durable tool
  follow-up classification;
- Board records, routing outcomes, pickup FIFO/lifecycle, and replay progress;
- task queues, attempts, cron cadence and firing claims;
- voice tells and Goodnite demand events;
- =raw-result://= and e-managed session =tmp://= resources, including complete
  tool-invocation details.

SQLite owns durable facts and transition arbitration.  Domain modules own
meaning and policy.  Memory holds provisional intent, caches, executable
subscriptions, callbacks, timers, live handles, endpoints, and presentation
state.  Every durable transition is commit-first.

Files remain when file identity is the product or protocol: user-authored files,
explicit exports and backups, migration reports, screenshots, diagnostics, and
subprocess artifacts that genuinely require a pathname.  Such artifacts are
not a second runtime-state authority.

Feature 89 owns chat-visible Board-run status and completion handoff.  Feature
90 owns the meaning and publication of complete tool-invocation details.
Feature 87 supplies their durable storage and restart boundaries without taking
over their product policy.

* Accepted decisions

The matrix incorporates these operator decisions:

- one physical database and one e runtime per state directory;
- every database read and write goes through the worker;
- durable state is commit-first rather than an asynchronous mirror of mutated
  Lisp state;
- stable Board routing and pickup state is durable, while executable predicates,
  callbacks, endpoint objects, timers, and Feature 91 admission tokens are not;
- task and cron work is claimed durably before action;
- e-managed =tmp://= and raw-result content moves into SQLite;
- session, Board, task, and cron audit remains until explicit owner deletion;
  expired resources are physically deleted, and Goodnite cleanup follows an
  acknowledged consumer checkpoint;
- session deletion purges private state but not shared Board history or old
  operator backups;
- committed routing outcomes are final; historical rerouting is explicit;
- typed composite transactions exist only for accepted cross-owner invariants;
- =synchronous=NORMAL= is sufficient; host/power-loss preservation of the latest
  acknowledgement is not promised;
- migration and schema upgrades are explicit offline actions;
- backups are explicit except for the verified backup created by the explicit
  schema-upgrade operation; deletion creates no automatic backup;
- restrictive local permissions are required for the store and every
  operator artifact; encryption/key management is not;
- the first resource implementation uses one BLOB and a generous private limit,
  not chunk streaming;
- shells may display pending intent, but agents and durable projections see only
  committed state; post-submission cancellation reconciles and then records a
  later durable transition when needed.

* Delivery packages

Packages are ordered and owner-complete.  Internal steps and design checkpoints
do not count as accepted packages.  Each package runs its focused gates and is
committed before dependent work begins; the complete repository and graphical
matrix runs once at Package 4.

Before P4, “establishes” means that the complete contract passes for an explicit
new or disposable SQLite store.  It does not claim the default runtime has cut
over or that =F87-GOAL= is behaviorally available.  P4 alone makes SQLite the
ordinary backend, removes the legacy runtime path, and can advance the direct
scenario from =unavailable= to =passing=.

** P1: Runtime store, sessions, tool continuity, and temporary resources

Establishes =F87-C02=, =F87-C03=, =F87-C04=, and =F87-C12=.

Scope:

- add the exact tagged value codec and typed storage protocol;
- implement the batch Emacs worker, migrations for a new store, command
  deduplication, revisions, WAL/foreign keys, exclusive runtime ownership,
  bounded reads, restart/reconciliation, status, barriers, permissions, and
  explicit diagnostics;
- replace the JSONL/index/queued/Node implementation behind the existing
  =e-session-storage= boundary with the typed SQLite worker protocol; preserve
  the accepted =e-session= facade, aggregate, codec, and catalog dependency
  direction, and make session mutations commit-first;
- store session history/catalog/display projections and paged restore paths;
- persist tool admission, claim, result, follow-up, promotion, settlement, and
  current restart classification; never persist live requests or handles;
- move e-managed session =tmp://= content and complete invocation details to one
  bounded SQLite BLOB per resource;
- retain the legacy session backend only as the still-default production path
  while the SQLite path is exercised with new/disposable stores.

Gate:

- exact codec property/rejection tests;
- worker creation, reopen, duplicate/conflict, process crash, restart,
  second-runtime, cancellation, read scheduling, permissions, and host-loss
  consistency tests;
- session semantic suite against disposable SQLite, including branch,
  compaction, display, clear, delete, and exact value restore;
- tool crash matrix before claim, after claim, after start, after result, and
  before settlement;
- resource URI, expiry, session deletion, and exact/one-over private-limit tests;
- a deterministic test-owned 15,722-record/37,851,478-byte fixture restores
  through indexed, paged reads without reading unrelated audit history; an
  interactive timer advances and queued commits complete during the load;
- record elapsed resume time against the historical approximately 0.07-second
  operator-store observation as observational telemetry.  A deterministic
  wall-clock gate requires a separately accepted fixture or generator,
  command, cache policy, sample count, statistic, environment, threshold, and
  revision trigger.

Useful stopping point: new and disposable stores can run complete SQLite-backed
sessions, restart-safe tool classification, and temporary resources without
changing the user's legacy default store.

** P2: Board authority, durable routing, and session admission

Establishes =F87-C05= and =F87-C06=; depends on P1.

Scope:

- move Board identity, canonical records, order, source-key constraints,
  selectors, and replay to =e-board-storage=;
- make commit the only publication boundary and remove authoritative in-memory
  message/source-key indexes;
- persist final routing outcomes, pickup identity/FIFO, claims, acceptance,
  consumption, retry, tombstone, and replay progress;
- preserve executable subscriptions, predicates, callback fencing, endpoint
  attachments, and scheduler handles in the Feature 91 process-local owners;
- split the combined =e-chat-service= chat/session binding and remove the
  session-selected Board-log owner;
- add the typed pickup-admission operation that atomically appends admitted
  session input and advances Board pickup acceptance;
- recover unprocessed rows and unresolved pickups after missed wakes or restart
  without changing pickup identity or rerouting a committed outcome.

Gate:

- publication before/after-commit, clear/generation, duplicate/conflict,
  selector, replay, noisy-history, and processing-record tests;
- routing finality, no-recipient, explicit reroute, detach/rebind, FIFO, claim,
  acceptance/consumption, missed-wake, and restart tests;
- pickup/session atomicity before and after the composite commit;
- dependency searches prove no generic transaction surface, no executable
  subscription persistence, no Board record through session storage, and no
  owner access to another owner's private representation.

Useful stopping point: an opt-in SQLite store provides complete Board
publication, routing, delivery recovery, and session admission while preserving
Feature 91's live ownership boundaries.

** P3: Remaining scheduler, adaptation, and resource state

** P4: Migration, cutover, removal, and system proof

Establishes =F87-C01=, =F87-C09=, =F87-C10=, and =F87-C11=; depends on P1-P3.

Scope:

- implement dry-run legacy import with source hashes, owner validators,
  canonical Board extraction/deduplication, semantic manifests, integrity

- implement explicit offline SQLite schema upgrade with automatic verified
  pre-upgrade backup; keep ordinary startup migration-free;
- make SQLite the only persistent runtime backend and produce targeted errors
  for legacy-only, older-schema, newer-schema, and missing-SQLite stores;
- remove the Node writer, checkpoints, =index.json= rebuild, legacy runtime
  loaders, per-session file identity, Board-log-owner proxy, persistence
  callbacks, duplicate durable indexes, and all sidecar runtime-state writers;
- add explicit worker-owned backup/export/integrity operations; migration
  working files, reports, verified pre-upgrade backups, explicit backups and
  exports, and disposable pathname copies use restrictive local permissions;
- update architecture and E2E documentation, run the complete repository and
  isolated graphical matrix plus the current-config compatibility runner
  against disposable stores, and record system, restart, backup/restore,
  migration, and performance results in =review.org=.

Gate:

- repeat migration is manifest-identical; malformed, conflicting, missing-root,
  legacy-shape, incomplete-tail, and failed-upgrade fixtures do not install;
- S9 verifies restrictive permissions for every migration, upgrade, backup,
  export, report, and disposable-path artifact;
- a dry migration of a copy of the current user store passes without touching
  the live store;
- S1-S11 pass on one reviewed revision;
- source scan proves SQLite is the only ordinary persistent authority and no
  implicit legacy fallback or dual write remains;
- complete batch tests and =bash e2e/run-graphical-tests.sh= in isolated mode

- =bash e2e/run-current-config-tests.sh= passes with its default harness

  graphical persistence scenario, its exact named selector must also pass with

- performance evidence covers catalog startup, session resume, Board replay,
  commit/finalization, worker startup, resource limits, WAL/database size, and
  main-thread responsiveness.

Useful stopping point: the user has a verified migration and cutover to one
complete SQLite authority, the legacy sources remain rollback material, and no
partial alternative backend remains to maintain.

* Package boundary rationale

P1 combines infrastructure with its first full consumer so it does not stop at
an unused adapter.  P2 remains separate because Board publication/routing and
the one real Board/session atomic composition have a distinct owner and failure
surface.  P3 groups smaller existing file stores because they share the same
mechanical migration pattern but retain separate semantic ports; splitting them
would create small repetitive cycles without changing a design decision.  P4
combines migration and cutover because neither is a safe stopping point alone:
the default changes only after every owner and rollback proof is complete.

* Scenario portfolio

- =S1 migrated-system restart= :: Covers =F87-C01=.  Migrate a legacy copy,
  open sessions/Boards/tasks/cron/resources, complete new work, restart, and
  prove exact committed reconstruction with no sidecar writer.
- =S2 worker and ownership failure matrix= :: Covers =F87-C02= and =F87-C12=.
  Stop before commit and after commit-before-ack, reject a second runtime,
  recover the worker by command id, freeze effects while unavailable, and verify
  consistency after simulated host loss.
- =S3 session/tool crash matrix= :: Covers =F87-C03=.  Exercise session changes
  and every durable tool-follow-up boundary; uncertain external effects become
  explicit rather than blindly repeated.
- =S4 temporary-resource lifecycle= :: Covers =F87-C04=.  Round-trip exact bytes
  through =tmp://=, restore, expire, session-delete, and prove exact/one-over
  private-limit behavior without a backing file.
- =S5 Board publication/routing/restart= :: Covers =F87-C05=.  Exercise commit
  publication, final/no-recipient routing, pickup FIFO/lifecycle, missed wakes,
  detach/rebind, clear/generation, and restart replay.
- =S6 pickup/session atomicity= :: Covers =F87-C06=.  Stop on both sides of the
  typed composite commit and prove session admission and pickup acceptance
  cannot tear.
- =S7 task/cron claim and restart= :: Covers =F87-C07=.  Stop before claim,
  after claim, and after external start; restore only to the state permitted by
  the action's idempotency/reconciliation contract.
- =S8 auxiliary-state lifecycle= :: Covers =F87-C08=.  Migrate and restart voice,
  Goodnite, and raw-result state; prove caps, consumer checkpoints, expiry, and
  cleanup boundaries.
- =S9 migration and upgrade= :: Covers =F87-C09=.  Dry-run, repeat, corrupt,
  conflicting, interrupted, upgrade, and operator-artifact permission fixtures
  prove all-or-nothing install, source preservation, verified backup, and
  restrictive local access.
- =S10 cutover negative scan= :: Covers =F87-C01= and =F87-C10=.  Source and
  runtime probes find no sidecar writer, runtime legacy fallback, permanent dual
  write, or duplicate durable Board ledger.
- =S11 bounded interactive load= :: Covers =F87-C11=.  Large paged session and
  Board loads keep an interactive timer responsive while commits continue.

Each scenario is a deterministic release gate.  Performance measurements not
named as pass/fail thresholds remain observational.  No external credentialed
probe participates in Feature 87 acceptance.

* Acceptance decision

Feature 87 becomes =Done= only when:

- every =F87-C*= contract is established by its mapped package;
- S1-S11 pass on the same reviewed revision;
- all four packages and their focused gates are complete;
- the complete repository and isolated graphical gates plus the current-config
  compatibility runner pass against disposable SQLite stores; any Feature
  87-specific graphical selector also passes in current-config mode;
- migration proof used only a copy of operator state and the running Emacs was
  not opened, migrated, reloaded, or restarted by repository validation;
- =review.org= records no unresolved finding or required unknown.

Implementation progress and behavioral progress remain separate.  Passing
owner/mechanism tests does not make =F87-GOAL= pass before S1 succeeds.

* Non-goals

- Persisting active turns, provider requests, callbacks, timers, work handles,
  executable Board subscriptions, exact admission tokens, endpoint objects,
  Lisp predicate closures, focus, windows, overlays, render caches, or other
  process/presentation state.
- Exactly-once execution of arbitrary external effects.  Automatic retry needs
  a tool/action-specific idempotency or reconciliation contract.
- Latest-acknowledgement survival after host failure or sudden power loss.
- Generic SQL, transaction builders, or cross-owner mutation ports exposed to
  agents, shells, capabilities, resources, or domain owners.
- Chunk-streaming resource storage before observed sizes justify it.
- Encryption at rest or key management.
- Full-text search, cloud sync, shared network storage, concurrent multi-runtime
  consumption, or a generic capability-projection framework.
- Automatic startup migration, permanent JSONL dual write, runtime legacy
  replay, format fallback, or deletion of preserved legacy sources.
- Treating one session as the owner of a Board shared by several participants.
- Rewriting operator-created historical backups during live deletion.

* Compatibility and operator boundary

Cutover requires Emacs 29.1 or newer with built-in SQLite support.  Ordinary
startup may create a new current schema, but an older legacy or SQLite schema
reports a targeted migration-required error.  Legacy migration and future
schema upgrades are explicit offline operations.  Backups are explicit except
for the verified pre-upgrade backup created by the upgrade command.

Repository validation uses disposable stores and never opens or migrates the
operator's live store.  Running Emacs remains untouched.  Core runtime, worker,
session, Board, and record-shape changes require a full Emacs restart when the
operator chooses to use the new implementation; =e-dev-reload= is insufficient.

* Design self-check

1. *Useful stopping points*: Each package closes owner semantics, durable state,
   recovery, public composition, and focused evidence; none is only a helper or
   checkpoint.
2. *Final direction*: One SQLite authority replaces every hidden runtime-state
   file and duplicate durable in-memory Board collection.
3. *Stable versus uncertain*: Ownership, commit-first visibility, exact value
   shape, recovery classifications, retention classes, migration, and failure
   boundaries are stable.  Table names, private limits, page sizes, worker
   framing, checkpoint cadence, and chunking remain local and revisable.
4. *Ownership*: Session, Board, task, cron, voice, Goodnite, and resources keep
   their semantic ports.  The adapter owns only physical storage and typed
   composite execution.
5. *Coupling*: Sharing one database removes duplicated persistence while narrow
   ports and one use-case-specific composition prevent representation coupling.
6. *Dependency direction*: Domain policy defines commands/projections; the
   SQLite adapter depends on them.  Policy does not depend on SQL or tables.
7. *Side effects*: Database, migration, backup, export, and maintenance work is
   in the worker/adapter; shells request application operations only.
8. *State lifetime*: Durable facts and accepted recovery state persist by owner
   retention; rebuildable projections are indexed; live objects remain local.
9. *Performance*: Main Emacs performs no SQL; reads are bounded and yield to
   commits; the known large-session fixture and graphical timer prove the hot
   paths.
10. *Substitutability*: Owner ports contain only supported owner operations;
    there is no generic SQL, fake alternative backend, or unsupported method.
11. *Compatibility*: One explicit importer and upgrade path replace runtime
    fallback; preserved sources remain inactive rollback material.
12. *Removal*: Node/JSONL, checkpoints, derived index, sidecar stores, Board-log
    proxy, persistence callbacks, and duplicate durable indexes are deleted
    after proof.
13. *Errors*: Expected busy/transport failure is bounded and retryable;
    corruption, schema/value/identity/revision conflict, uncertain effects, and
    terminal worker recovery surface explicitly.
14. *Tests*: Pure policy tests remain storage-independent; disposable-SQLite
    owner, composition, migration, restart, graphical, and system scenarios
    fail at narrow boundaries.
