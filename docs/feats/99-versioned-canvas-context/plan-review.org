* Aggregate comparison and economic decisions

Accepted behavior to preserve: complete current authoritative text, no stale overwrite, stable native prefix across small edits/unchanged calls, bounded exact representation, existing curation/continuation authority. No checkout API or new database is needed.

Current proposed aggregate: one attachment capture owner; harness process-local accepted/pending chain and pure selection; resource mutation expectation path; adapters translate; existing evidence classifiers qualify. This is a reasonable direction. The missing joins are chronology and expected-revision propagation, not evidence for adding another semantic owner.

Smallest faithful alternative: one derived harness-context document chronology integrated before the existing segment/message frontier; exact source capture; a small linear exact patch constructor unless workload evidence justifies bounded multi-hunk complexity; ordinary resource-operation guard in the existing file/buffer owners; all provider differences remain adapters. A full replacement-only current observation is smaller but cannot satisfy the accepted small exact append outcome, so it is a valid DP1 stopping point rather than the final substitute. A durable retained-context copy would violate the intended lifetime and add an unnecessary authority.

Decision: retain the high-level decomposition, settle the two real joins, and compare the patch constructor options locally. Do not create a generic version-control service or new checkout/document tool vocabulary to hide the missing joins. The parent/product owner must accept any new advertised mutation vocabulary or changed scope before it becomes durable.

Defensive actions:
- Stale writes: source proves a saved coherent edit can be overwritten; operational frequency is unknown, but impact is durable loss of user work and C6 expressly requests the guarantee. Existing coherence/exact-match checks only partly contain it. One expected-revision comparison at the actual mutation owner is proportionate. No broad file-operation restrictions are justified.
- Baseline loss/failed send/branch change: source exposes immutable per-request frames and selected paths; a diff without a complete base is unusable by construction. Snapshot fallback and acceptance-owned eligibility directly protect C2/C5; no speculative provider-memory recovery is justified.
- Pathological diff work: arbitrary superlinear diff on interactive Emacs has a concrete existing local precedent, but no new workload probability is fabricated. A linear constructor or local work budget is the smallest adequate response. New durable services/queues/metrics are not justified.
