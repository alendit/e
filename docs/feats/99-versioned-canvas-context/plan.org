* Current evidence

[[file:../../../lisp/layers/chat/e-chat-session.el::e-chat-session-context-attachments-provider][Attachment context]] renders complete live-buffer/file text as dynamic system context.
[[file:../../../lisp/layers/org-canvas/e-org-canvas-capabilities.el::e-org-canvas--context-provider-messages][Org Canvas context]] also mixes instructions with focus/visibility metadata.
[[file:../../../lisp/adapters/anthropic/e-anthropic.el::e-anthropic--system-blocks][Anthropic]] hoists system messages before conversation history; automatic caching and rolling markers already exist.
Claude's [[https://platform.claude.com/docs/en/build-with-claude/prompt-caching#what-invalidates-the-cache][cache hierarchy]] explains why changing this prefix can invalidate later reusable history.

The October 16 read-only audit observed 170 usage-bearing requests in the October 14 Daily parent chat: 18,111,932 input tokens, including 17,453,809 cache reads, 657,763 writes, and 360 fresh tokens.
These are whole-request observational counters, not canvas-only cost or proof of an individual miss's cause.

[[file:../../../lisp/core/e-harness-context-runtime.el::e-harness-context-lifetime-apply-projection][Current projection]] appends current observation segments after durable history, while completed lifetime frames contribute no observation bytes.
Retaining an old chain at that moving frontier alone would not preserve its position among later messages.
Ordinary [[file:../../../lisp/core/e-operations.el::e-operation-write][write/edit dispatch]] currently has no expected-revision argument; file/buffer coherence alone cannot detect an already saved coherent user edit.
Attachment capture is complete and currently uncapped; ordinary read-result limits do not bound it or a diff algorithm.

* Supporting implementation appendix

This appendix chooses a feasible initial design for the rows above; its private names, representation, and tuning values may change with equivalent contract evidence.

** Owners and smallest faithful design

Source capture stays at the attachment/resource boundary, preferring the live buffer to disk.
Pure revision, patch, and selection operations belong beside the context owner, without file I/O or provider calls.
The harness owns derived document chronology and pending/accepted state, and adapters only translate it.
The shell retains presentation state; resource owners retain atomic mutation.
No version-control service, database schema, durable canvas transcript copy, new document tool family, or provider-specific canvas subsystem is needed.

A full replacement-only frontier is smaller and is the useful DP1 stopping point, but cannot establish C3's exact append-preserving changes.
A durable retained-context copy adds another authority and the wrong lifetime for C5.
The selected alternative is one process-local harness document chronology, one linear patch operation, and a narrow addition to existing resource operations.

** DP1 semantic split

Separate stable canvas behavior instructions, canvas reference data, and volatile focus/visibility data at their contributing context boundaries.
Use the existing reference-data role where it faithfully represents the semantics, with narrow metadata distinguishing active canvas data from instructions/retained facts.
Do not reinterpret arbitrary system messages, synthesize tool calls, or persist active canvas data through the retained-fact journal.
All shipped serializers consume the same semantic split; Anthropic maps data to native reference content after the canonical conversation prefix.
Responses/Chat Completions preserve genuine instruction authority and valid native tool pairing.
DP1 still supplies a complete current snapshot at the request frontier.
Material layout identities cover the new distinction independently of optional curation carriers; affected routes remain unconfirmed until DP3.

** Exact source, patch, and byte policy

Capture immutable property-free source text once and use that same value for hashing, evidence, and patching.
Use the existing evidence encoding rule for the content hash, explicit UTF-8 for payload size, and no additional whitespace/newline normalization.
URI remains a separate identity; focus/folds do not enter the document revision.

Choose a single exact replacement span derived from common-prefix/common-suffix scans of the complete old and current strings.
The suffix scan does not overlap the prefix; positions are character boundaries and replacement text is exact.
Applying the span to the baseline must reproduce the captured result and hash before publication.
The algorithm has linear work/allocation bounded by the complete operands, avoiding arbitrary superlinear multi-hunk diff work on the Emacs thread.
Escaping and applying the payload also remain linear.
Capture still reads the complete attachment: read-tool truncation is not an attachment cap, and ordinary context-window handling remains independent.
Benchmark separated edits as well as one-checkbox changes; separated small edits may select a snapshot rather than justify a multi-hunk engine by default.

Measure complete backend-neutral model-facing UTF-8 payloads, including URI/revision fields, coordinates, replacement text, escaping, and framing.
Compare a patch with a snapshot of the same current source under the same envelope rules.
Provider-specific envelope bytes are observed separately; bytes are not exact tokenizer or billing estimates.

Initial private defaults for implementation experiments:
- Choose a snapshot without an eligible complete baseline/chain.
- Equal resulting hash chooses no new observation.
- Otherwise choose a snapshot when patch bytes are at least 30% of snapshot payload bytes, when cumulative patch payload bytes would reach one current snapshot payload, or when the next patch would exceed 16 patches since the baseline.
- Otherwise append the exact patch.

These values are tuning candidates, not stable product contracts or provider cache switches.
Use integer comparisons and explicit equality cases, including empty documents, and report realistic byte/runtime comparisons before retaining or revising them.
Changing the constants invalidates their mechanism checks rather than the semantic portfolio.
Unexpected hash/encoding errors surface; there is no catch-all snapshot fallback that hides bugs.

** Chronology and request settlement

The harness context owner keeps accepted snapshot/patch observations at insertion boundaries in the selected canonical session path, not at a moving global tail.
Use the request's selected-path frontier anchor and existing bounded path-position machinery, including anchors whose message is filtered from semantic history.
Merge accepted canvas observations with selected history at those boundaries before deriving final messages, segments, entry alignment, lifetime source presentation, full native requests, or eligible continuation deltas.
For example, H0,S0 becomes H0,S0,A0,U1,P1, never H0,A0,U1,S0,P1.
The pending observation belongs at the current request frontier, after the accepted chronological projection.
Only its successful terminal response plus existing semantic acceptance makes that observation eligible for subsequent projections.
Preview/status calls may inspect but never commit or advance document state.

Scope state to harness/session, canonical canvas identity, selected branch/generation, and compatible layout; retain exact base text, accepted operations/anchors, and per-request pending captures only while needed.
Bind settlement to the immutable request and prepared state identity so an older completion cannot overwrite a newer cursor.
Retry an immutable valid request or rebuild from the last accepted state; failed, cancelled, or ambiguous attempts do not authorize a new base.
Tool continuations receive that same authoritative projection, rather than an independently maintained serializer-only list.

When a selected-path boundary disappears, a generation/branch/layout changes, curation removes required bytes, or state is lost on restart, discard the ineligible chain and establish one authorized current snapshot at the new frontier.
A reset removes the superseded chain from the next projection and is a deliberate measured cache boundary.
Never treat summarized content as an exact patch base or reintroduce a source whose current authorized projection excludes it.
Process-local state is released through existing session/turn invalidation and cleanup; no new persistent schema is introduced.

An unchanged decision adds no observation but does not authorize dropping required bytes from a stateless request.
Full requests serialize the complete baseline and accepted changes unless a separately qualified continuation supplies them.
The current effective evidence handle identifies the reconstructed complete resulting text; framing distinguishes historical patches from the one current revision.

** Ordinary revision-checked resource mutation

Choose an explicit optional =expectedRevision= string on existing =write= and =edit= operation schemas, not a new action/tool.
Dispatch it through the existing resource-operation path to revision-aware file/buffer mutation owners.
For an attached canvas the argument is required; absence is a visible conflict rather than an unguarded legacy route.
The argument comes from the revision the caller was shown, not a silently substituted latest harness cursor.
Canvas context, successful supported reads, and successful guarded mutations expose the complete resource revision so subsequent calls can use it.
A partial read reports the revision of the complete captured resource, not a digest of only the returned range.
A conflict exposes the current revision and directs a fresh read/reconsideration; it performs no edit, save, or linked-buffer synchronization.

Derive attached-canvas target scope from immutable trusted request context and carry it through ordinary tool dispatch; do not query unrelated live session state synchronously inside a file handler.
Canonical resource resolution belongs to the existing file/buffer owners: relative/absolute file aliases and a visiting buffer identify the same target; authorization and path/symlink policy remain in force.
Check current authoritative live-buffer/file text and apply the mutation in one synchronous check-and-apply section with no intervening await/process callback.
Preserve existing coherence and exact-text replacement checks as additional constraints.
Non-canvas calls without the argument remain unchanged; an unsupported method cannot silently accept and ignore an explicitly requested revision check.
Arbitrary shell or unrestricted =run_elisp= writes remain outside C6, rather than acquiring a misleading global safety promise.
