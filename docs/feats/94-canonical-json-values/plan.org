#+title: Canonical JSON Values Across Model and Persistence Boundaries
#+startup: overview

* Status

Done.

This work was opened after the Daily reconciliation action exposed a list-of-
plists corruption path.  A schema-aware compatibility normalizer repaired the
immediate symptom, but retained the underlying ambiguity between Elisp lists,
plists, alists, and JSON arrays.  This feature replaces that compatibility
matrix with one canonical JSON representation and then rebases the Daily
coordinator correction on it.

* Canonical contract

| JSON value | Canonical Elisp value |
|-
| object | keyword plist; the empty object is =nil= |
| array | vector; the empty array is =[]= |
| string and number | native string and finite number |
| true | =t= |
| false | =:json-false= |
| null | =:json-null= |

The boundary is structural and exact.  It rejects alists, hash tables,
list-based arrays, non-keyword object keys, arbitrary symbols, non-finite
numbers, and cycles.  JSON Schema validates this representation but never
reinterprets it.  Applications may explicitly map canonical values into
domain records after the boundary.

Provider adapters parse wire JSON into the representation once.  Tool and
action dispatch preserve it unchanged.  Canonical encoders preserve empty
object versus empty array and false versus null.  Existing arbitrary Elisp
runtime-store values remain a separate domain; only persisted fields declared
to contain canonical JSON adopt the canonical contract.

* Compatibility decision

Current durable SQLite/runtime-store values retain their tagged Elisp codec.
Existing JSONL session/catalog/checkpoint data is read through one named,
read-only legacy migration adapter and is written canonically thereafter.
Versioned temporary tool-invocation documents, Grimoire raw JSON sidecars, and
embedded Agenda Apply JSON must round-trip canonically.  Generated graph,
semantic, and source data is migrated with its adapter; rebuildability is not
an excuse to keep ambiguous shapes.

Board semantics do not change.  Board owns terminal fan-in and continuation
delivery.  The Daily application owns reconciliation, publication, recovery,
and the mapping from a canonical section vector into publication-domain
records.

=d6e2bf52=, =9740ef9b=, =a7f12efb=, =c150d4e6=, =fb2398c5=, and

The completed contract uses =nil= only for an empty JSON object and =[]= for
an empty array.  =:json-false= and =:json-null= remain distinct.  Provider
decode, schema validation, tool dispatch, action dispatch, application mapping,
and canonical persistence no longer guess among lists, plists, alists, and hash
tables.  The one retained compatibility boundary is the named read-only legacy
session migration adapter; ordinary runtime-store tagged Elisp data remains an
explicitly separate domain.

Deletion audit found no remaining recursive action normalizer, tool JSON-string
reparser/coercer, JSON fingerprint normalizer, Daily string-key/container
fallback, terminal-recovery queue, or public =:apply=/:finalize= reconciliation
surface.  The original list-of-plists corruption path is rejected at the
canonical action boundary and Daily consumes only a vector of keyword-plist
section objects.
