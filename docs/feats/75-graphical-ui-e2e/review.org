The implementation satisfies the plan contract.  Graphical behavior runs in a
fresh Emacs with a real frame and command loop, while the default macOS path

* Resolved findings

** Resolved: durable activity could expire later reasoning output

*** Problem

Durable lifecycle events advanced the board source watermark, but locally
allocated reasoning activity did not share that watermark.  A later reasoning
delta could therefore look older than an already published lifecycle event.

*** Change

Reasoning now uses the event's durable source key when present.  The local
allocator advances to every durable key, and untagged reasoning gets the
default =main= tag.

*** Evidence

=e-board-runtime-test-reasoning-follows-durable-lifecycle-watermark= passes,
and the hidden graphical streaming scenarios display reasoning updates.

** Resolved: generic focus preservation overrode chat viewport policy

*** Problem

The board-event UI job used generic one-buffer focus preservation after chat
rendering.  That restoration could undo the composed chat shell's explicit
follow-or-preserve decision.

*** Change

The event consumer now declares explicit focus handling and leaves focus and
viewport ownership with the chat shell.

*** Evidence

=e-chat-test-board-event-consumer-defers-focus-to-chat-policy= and the
graphical focus, draft, and scroll scenarios pass.

** Resolved: first running status stranded a pinned window

*** Problem

Before a running-status block existed, status insertion had no status-relative
display state to restore.  A transcript pinned at its physical tail could stay
at the old tail after the first status appeared.

*** Change

The first status render captures and restores physical-tail windows.  Later
status updates retain their status-relative restoration path.

*** Evidence

Both short-output and long-stream graphical scenarios keep the output tail
visible while pinned.

** Resolved: point-max could sit outside the short-output display matrix

*** Problem

The two-row follow margin was too small for an empty final line plus
display-only status rows in a graphical frame.

*** Change

The follow placement now reserves six rows.  This keeps the actual transcript
tail visible near the bottom without selecting the transcript window.

*** Evidence

The graphical suite checks pixel geometry with =posn-at-point= and
=pos-visible-in-window-p= while composer focus and draft text remain intact.

** Resolved: deterministic integration tests were incorrectly optional

*** Problem

Five deterministic tests lived behind the live-provider E2E switch despite
requiring no credentials or graphical display.

*** Change

They now live under =test/= as integration tests and run in the default suite.
Only live-provider and development bytecode diagnostics remain opt-in.

*** Evidence

The focused integration run completed seven tests with six expected passes and
one Evil-dependent skip in the isolated batch environment.

** Resolved: native graphical tests interrupted the desktop

*** Problem

A normal native frame appeared on macOS and could steal focus while the tests
ran.

*** Change

The default macOS launcher now uses a private daemon and creates a transparent
off-screen NS frame with =no-accept-focus=, =no-focus-on-map=,
=skip-taskbar=, and =undecorated=.  It uses a temporary Emacs directory and
shuts the daemon down after the report.  =E_GRAPHICAL_E2E_NATIVE_VISIBLE=1=
keeps the visible path for diagnosis.

*** Evidence

The hidden native run completed four graphical tests with zero unexpected
results and did not connect to the user's Emacs server.

* Architecture review

The test launcher owns process, frame, and temporary-directory side effects.
The fake backend implements the existing asynchronous backend contract.  The
chat shell owns composed focus and viewport policy.  The board runtime owns
durable source ordering.  No production component depends on the test harness,
and no test-only state enters the runtime package.

* Design self-check

1. Yes.  This is a useful stopping point: recent chat regressions have real
   graphical coverage and the tests no longer interrupt desktop work.
2. It moves toward a harness/presentation split where presentation behavior is
   verified through public shell interactions and observable redisplay.
3. The OS launcher is local and reversible.  The stable contracts are backend
   callbacks, public commands, selected windows, viewport geometry, and
   workspace restoration; no speculative extension API was added.
4. The shell owns focus and viewport behavior, the board runtime owns activity
   identity, and the runner owns test-process orchestration.  Each has one
   reason to change.
5. Coupling is reduced: deterministic tests use normal integration discovery,
   and graphical tests consume narrow public behavior plus the backend
   contract.
6. No stable policy depends on a UI or test adapter.  Dependencies continue
   from presentation and tests toward runtime-owned contracts.
7. Frame creation, daemon lifecycle, temporary storage, and virtual-display
   setup remain at the shell/CI boundary.
8. Test state lives for one private process.  Stream callbacks live for one
   request.  The runtime sequence floor lives on its owning attachment and is
   rebuildable with that attachment.
9. There is no steady-state test cost in production.  Runtime overhead is a
   constant-time maximum/comparison and existing window placement; graphical
   CI is a separate short job.
10. The backend and focus-policy contracts are real and substitutable; no
    unsupported operation or weakened precondition was introduced.
11. The visible native runner remains an explicit diagnostic compatibility
    path.  Obsolete optional classification for deterministic tests was
    removed.
12. The old =*-e2e-test.el= deterministic paths, names, and environment-gated
    discovery were removed.
13. Missing graphical display and daemon failures surface at the runner.
    Asynchronous backend errors surface in ERT diagnostics; unexpected runtime
    errors are not swallowed.
14. Focused unit tests prove ordering and focus policy, batch integration tests
    prove cross-module flows, and graphical tests independently prove command
    loop, redisplay, geometry, scrolling, and workspace behavior.

* Follow-up: agent screenshot and transition traces

On 2026-08-07 the graphical support layer gained opt-in visual and structural
debug artifacts.  =E_GRAPHICAL_E2E_SCREENSHOT_DIR= records ordered state
checkpoints, before/after key and provider transitions, settled waits, and the
last state before timeout cleanup.  Each checkpoint contains an SVG rendering
of the actual test frame and a =.state.el= sidecar with exact geometry,
selection, mode lines, visible text, point, and viewport values.  The shell
runner converts SVG files to PNG after Emacs finishes when =rsvg-convert= is
available.

Rendering and PNG conversion are deliberately outside behavior timing.  An
initial implementation converted PNGs inside provider callbacks; the traced
focused-composer scenario timed out and exposed callback reentrancy.  Captures
now retain a cheap immutable frame model during the transition, render SVGs
after ERT completes, and convert PNGs in the outer launcher.  The same traced
scenario passes and produced fifteen ordered artifacts ending at the verified
=18% (64k/353k tok)= composer state.

The new graphical self-test proves arbitrary state capture, before/after
transition capture, SVG readability, and sidecar contents.  Fixture creation
also waits for deferred surface UI work before retaining window identities;
this removed the prior timing-sensitive leakage after the real persp-mode
case.  The full hidden graphical suite passes six tests with zero unexpected
results.

** Design self-check

1. Yes.  Agents can now debug graphical regressions without touching the live
   Emacs or opening a desktop window.
2. It moves toward observable, artifact-backed presentation testing in the
   isolated graphical tier.
3. The SVG renderer is a local replaceable adapter.  The stable contract is
   the captured frame model and ordered artifact names.
4. Graphical support owns capture; the runner owns deferred rendering and
   artifact finalization.  Runtime and chat production code are unchanged.
5. Coupling is limited to existing graphical helper actions and ordinary Emacs
   window APIs; agents receive a narrow capture API.
6. No production policy depends on the test renderer or shell converter.
7. File writes, SVG rendering, and PNG conversion remain at test and launcher
   boundaries.
8. Capture models live only until the current test run renders them; artifacts
   live only in the agent-selected directory.
9. Normal runs pay only the screenshot self-test.  Debug runs capture bounded
   visible state; expensive rendering and conversion happen after behavior
   timing.
10. State and transition helpers share one real capture contract and do not
    weaken behavior when screenshots are disabled.
11. SVG and sidecars are always available; PNG is an explicit optional
    compatibility output when =rsvg-convert= exists.
12. No legacy screenshot path existed.  The failed native desktop-capture
    probe was not retained.
13. Missing output directories and conversion failures surface directly;
    action errors get an error-state capture and are then re-signaled.
14. The graphical self-test proves the capture core, while a traced existing
    async chat scenario proves integration without changing its result.
