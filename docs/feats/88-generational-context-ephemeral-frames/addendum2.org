* Goal

Make warm continuation useful in ordinary tool-heavy and pause-prone sessions without retaining expired tool observations or depending on stored provider responses.

The completed behavior is:

#+begin_example
clean response R0
  → tool-producing response R1
  → tool-result descendant R2
  → later ordinary turn branches from R0 on the same socket
  → current request-local observations replace their prior values
  → only the durable post-R0 delta is sent as input
#+end_example

The built-in ChatGPT Codex socket remains available for 600 seconds after a completed request instead of the current 300 seconds.
A healthy socket can therefore cross a pause longer than five minutes but shorter than ten minutes.
Provider close, transport failure, request cancellation, explicit socket close, or the finite idle timer discards its connection-local response lineage.
An incompatible request identity sends full reconstruction without =previous_response_id=, but does not by itself close a healthy socket or clear other connection-local ledger entries.

* Decisions

Keep =tool-result= ephemeral and =inherited=.
A function-call output is causal provider state for its matching follow-up.
The Responses continuation interface does not provide a request-local replacement channel for that bundle.
The tool-producing response and its descendant therefore remain ineligible as durable cross-turn anchors.

Permit a later request to reference any known compatible response ID that remains available on the same WebSocket, not only the immediately preceding response ID.
The adapter must validate the requested response against connection identity and the request properties recorded for that response.
It must not infer compatibility from the socket's latest response alone.

Give the exact built-in ChatGPT Codex WebSocket an explicit 600-second idle-close policy.
This doubles the current local idle window while preserving a finite adapter-owned lifetime.
Provider close, transport failure, request cancellation, explicit socket close, or expiry of that timer still closes it.
Keep the existing global idle-close policy unchanged as the fallback for profiles that do not declare a policy.

Do not use =store=true= as the ChatGPT Codex remediation.
The built-in profile remains =store=false=.
Cross-connection recovery is not part of this addendum.
Stored canonical OpenAI responses require a separate decision about retention, privacy, deletion, and cost.

Do not seed or rebase a clean anchor with a hidden model request.
A session whose first useful turn calls a tool still performs full reconstruction until it produces a clean response.
This bootstrap cost remains an explicit limitation unless later measurements justify a separate rebase design.

* Scope

This addendum changes only the OpenAI adapter's Responses WebSocket behavior, its profile-owned idle-retention policy, diagnostics, tests, and Feature 88 documentation.

It covers:

- branching from an older clean response ID after one complete tool-call and tool-result chain on the same socket;
- preserving the current request-local =instructions= replacement behavior on that branch;
- sending the durable or promoted post-anchor delta without the consumed function call, replay item, or result;
- retaining the built-in ChatGPT Codex socket for an explicit 600-second local idle window;
- rejecting response IDs that belong to another socket, were never observed on the current socket, or were recorded under incompatible request properties;
- safe full reconstruction after provider close, transport failure, explicit close, or unavailable response rejection; and
- distinct diagnostics for older-anchor branching, local retention policy, and full fallback.

It does not cover:

- changing the lifetime or delivery classification of =tool-result=;
- making =process_marker= or another tool semantically exempt from the tool bundle;
- persisting provider response IDs as recoverable remote state;
- enabling =store=true= for ChatGPT Codex;
- adding a generic provider response graph to core;
- changing session durable-message ownership;
- adding a hidden model call to manufacture a clean anchor;
- changing prompt-cache accounting or promising cached-input pricing;
- adding a new backend teardown contract only for this optimization; or
- adding persistence, transactions, or recovery machinery ahead of Feature 87.

* Semantic and transport protocol

Let =R0= be a clean response, =R1= a tool-producing response, and =R2= the final response descending from the tool result.
Let =D1= and =D2= be durable user or promoted deltas, and let =E3= be the complete current request-local observation.

The required request sequence is:

#+begin_example
request 0:
  input = durable prefix
  previous_response_id absent
                         → clean response R0

request 1:
  input = D1
  previous_response_id = R0
                         → tool call in R1

matching follow-up:
  input = function call output and required replay items
  previous_response_id = R1
                         → contaminated descendant R2

request 3:
  input = durable or promoted delta after R0, including D1 and D2 as required
  instructions = E3
  previous_response_id = R0
                         → clean response R3
#+end_example

=R1= remains available only for its matching tool-result follow-up.
Neither =R1= nor =R2= is admitted as a durable session anchor.
The later request must not send their raw function call, replay item, function-call output, or response IDs.

The adapter may send request 3 incrementally only when all of these conditions hold:

- the current WebSocket is the connection on which =R0= completed;
- =R0= is present in the adapter's connection-local response ledger;
- the continuation-invariant request properties for request 3 equal the properties recorded for =R0=;
- the harness supplied =R0= as its selected compatible anchor; and
- no active request already owns the socket.

Changed =instructions= remain compatible because they are request-local under the accepted first-addendum contract.
Changed =input= and =previous_response_id= remain excluded from the continuation-invariant property identity.
Model, tools, response shape, storage behavior, and other existing invariant fields remain part of that identity.

If any condition fails, the adapter sends =full-body-data= without =previous_response_id=.
An unavailable-response error still triggers at most one full retry through the existing fallback path.

* Connection-local response ledger

The OpenAI adapter owns a small connection-local ledger for completed response IDs.
Core, the harness, and the durable session store must not learn its representation.

Each ledger entry contains:

- the completed response ID;
- the connection ID that observed it implicitly through ledger ownership; and
- the continuation-invariant request properties that produced it.

The ledger lives only as long as the WebSocket session.
Opening a replacement socket, provider close, transport error, explicit socket close, or cancellation that closes the socket clears it with the existing connection-local state.
The ledger is not serialized to JSONL or checkpoints.

The adapter records a response only after a completed terminal event.
It does not record failed, partial, cancelled, or unconfirmed response IDs.
A retry that falls back to full input records only the completed response from the actual full request.
When the endpoint rejects =previous_response_id= as unavailable, the adapter removes only that requested response ID and its recorded properties from the live ledger before sending the one full retry.
It preserves the healthy socket and every other ledger entry.
A later request for the removed ID selects the initial full path without =previous_response_id= instead of repeating the rejected incremental branch.

Use a direct adapter-private representation.
Do not add a generic graph abstraction.
Bound the ledger to 256 completed response entries per connection with an adapter-private constant rather than a new public setting.
Track insertion order alongside the response-ID lookup so insertion beyond the cap evicts the oldest entry deterministically.
Keep the newest completed response entry, including the response needed for an immediate tool-result follow-up.
Track recently evicted response IDs with a second adapter-private lookup and FIFO insertion order capped at 256 entries so diagnostics can distinguish eviction from an ID that was never observed.
Each new historical ID beyond the cap retires the oldest historical ID deterministically.
An evicted requested anchor selects full reconstruction with the bounded =response-evicted= fallback reason.
Connection close clears the lookup, insertion order, and eviction history in one owning operation.

The existing =last-response-id= field may remain as a fast path for immediate tool follow-up only when it does not remain a second compatibility authority.
Compatibility must have one owner.
Prefer replacing the scalar compatibility check with ledger lookup and removing obsolete scalar state when the ledger subsumes it cleanly.

* Profile-owned socket retention

Add an adapter-private Responses WebSocket idle-close field to provider profiles.
When present, its value is a non-negative number of seconds.
When absent, resolve =e-openai-websocket-connection-idle-seconds= unchanged.
Its existing =nil= value means retain until cancellation, failure, or backend replacement.
The exact built-in ChatGPT Codex profile must normalize to an explicit 600-second policy even when host configuration reconstructs the canonical profile.

Do not change every custom or canonical profile merely to fix ChatGPT Codex.
The request context resolves the effective value once and passes it to the WebSocket request path.
The scheduler uses that request's resolved value instead of reading the global variable directly.

A completed built-in Codex socket remains reusable until its 600-second idle timer expires.
Provider close, network failure, process exit, request cancellation, explicit close, and the finite timer still end the capability window and clear the response ledger.
The provider response remains connection-local and =store=false=.

Do not add a core backend lifecycle API in this package.
The built-in profile's finite timer supplies the adapter-owned bound that the current backend contract lacks.

* Acceptance criteria

** Semantic safety

- =tool-result= remains =inherited=.
- Tool-producing and tool-descended response IDs never become durable clean anchors.
- A selected promotion survives through the existing durable promotion path.
- A later warm request contains no consumed function call, replay item, or function-call output.
- A session without a prior clean anchor reconstructs fully rather than manufacturing an anchor.

** Connection-local branching

- The latest compatible response ID continues incrementally.
- An older known compatible response ID continues incrementally on the same socket.
- Compatibility is checked against properties recorded for the requested response.
- An unknown, stale, cross-connection, evicted, or property-incompatible response ID selects full reconstruction.
- A property-incompatible request sends full reconstruction without clearing a healthy connection's unrelated ledger entries.
- A later request may use an entry whose recorded properties are compatible.
- The live ledger retains no more than 256 completed response entries and evicts the oldest entry deterministically.
- The bounded eviction history retains no more than 256 IDs and enables a distinct =response-evicted= fallback reason.
- Eviction history retires its oldest ID deterministically when a 257th historical ID is inserted.
- Eviction never removes the newest completed response needed for immediate tool follow-up.
- Socket close clears the live ledger, insertion order, and eviction history.
- Failed, cancelled, and partial responses are never admitted to the ledger.
- An unavailable-response rejection removes only the rejected ID from the live ledger before performing at most one full retry.
- A later selection of that removed ID starts with full reconstruction while unrelated compatible ledger entries remain usable.

** Request shape

- The older clean anchor is sent as =previous_response_id=.
- Current =current-state= and =dynamic-context= values appear only in current top-level =instructions= under the accepted request-local contract.
- Prior request-local observations are absent from the complete literal request.
- The =input= contains only the durable or promoted delta not already owned by the selected clean anchor.
- ChatGPT Codex remains =store=false= and keeps its existing encrypted-reasoning and prompt-cache shape.

** Retention and fallback

- The exact built-in Codex profile resolves to a 600-second local idle close.
- An undeclared profile uses the current global policy unchanged, including its documented =nil= no-idle-timer setting.
- Explicit finite profile policies remain supported.
- A pause longer than 300 seconds and shorter than 600 seconds can reuse the same healthy Codex socket.
- Timer expiry at 600 seconds closes the socket and forces full reconstruction on the next request.
- Provider close, transport failure, cancellation, or replacement socket forces full reconstruction.
- A locally persisted anchor never authorizes cross-connection use for =store=false=.

** Observability

- Diagnostics distinguish latest-response continuation, older-known-response continuation, new-connection fallback, unknown response, bounded =response-evicted= fallback, property mismatch, and unavailable-response retry.
- =provider-request-finished= records =:websocket-anchor-position= and =:websocket-idle-close-seconds= without exposing the response ledger.
- Measurements report transport input count, provider input tokens, cached input tokens, request latency, connection ID, reuse count, and fallback reason as separate values.
- No acceptance claim equates =previous_response_id= use with cached-input pricing.

* Performance contract

The warm branch must avoid full request reconstruction on the wire after an ordinary tool turn when a compatible clean anchor exists on the same socket.
Measure request-body input item count and serialized request bytes in deterministic acceptance.
Measure provider-reported input tokens, cached input tokens, and request latency separately in live acceptance.

The response ledger retains at most 256 completed response entries and at most 256 evicted-ID diagnostic entries during one connection lifetime.
Both bounded collections have deterministic FIFO retirement order.
Lookup must be constant-time or otherwise independent of durable session length.
Insertion-order maintenance and eviction must have cost bounded by the fixed cap rather than session length.
Closing a connection must clear the live lookup, insertion order, and eviction history in one owning operation.

A longer socket lifetime may retain network and adapter objects longer than today.
The explicit 600-second idle timer remains the local bound when the provider does not close first.
Implementation review must prove that replacement, cancellation, transport failure, and timer expiry all close the socket and clear the ledger.

* Compatibility and migration

No session schema or persisted record migration is required.
Existing provider anchors remain opaque session optimization records.
A running process with an old WebSocket session record must be restarted before using the new adapter shape.

Custom profiles without the new idle-close field retain the global defcustom behavior.
Explicit finite policies remain valid.
The built-in Codex normalizer supplies its explicit 600-second policy to stale reconstructed canonical profiles.
Noncanonical profiles are not rewritten merely because their URL resembles the Codex endpoint.

The implementation should remove scalar compatibility state that becomes obsolete.
Do not keep dual latest-only and ledger authorities for compatibility.

* Risks and responses

- The private ChatGPT endpoint may reject branching from an older response ID even on the same socket.
  In that case, retain safe full reconstruction and return to design with the captured provider error.
- The provider may evict older response IDs before closing the socket.
  Remove only the rejected ID from the live ledger, preserve other entries on the healthy socket, and record the unavailable-response fallback.
- Longer retention may expose abandoned-socket cleanup gaps.
  Keep the 600-second adapter timer as the local bound and verify cancellation, explicit close, provider error, replacement, and timer expiry.
- A per-response property ledger may duplicate or drift from latest-request property logic.
  Make ledger lookup the single compatibility authority and delete obsolete scalar checks.
- A busy socket may outlive every idle timer and otherwise grow its ledger without bound.
  Cap both live entries and eviction diagnostics at 256, evict oldest entries deterministically, and fall back fully when a selected anchor is no longer retained.
- A live long-idle test is slow and provider-dependent.
  Keep deterministic timer coverage in normal gates and run the credentialed delay only as explicit acceptance evidence.
- Prompt-cache savings may remain weak even when transport continuation succeeds.
  Report cache accounting separately and do not broaden this package into cache-layout redesign.

* Architecture self-check

1. If this package stopped after deterministic older-anchor branching, the project would avoid full wire reconstruction after ordinary tool turns on a healthy socket while preserving semantic safety.
2. The final direction is provider-neutral semantic lifetime policy with adapter-owned transport reuse and safe stateless fallback.
3. Tool-result lifetime is stable.
   Older-response support on the private endpoint is uncertain, so it remains adapter-local and is guarded by live evidence.
   The 600-second policy bounds socket cleanup without adding a new lifecycle contract.
4. Core owns semantic lifetime, the harness owns clean-anchor selection, the session owns durable semantic records, and the OpenAI adapter owns connection-local response availability and socket policy.
5. The change reduces the mismatch between harness selection and adapter transport without widening a public interface.
6. Stable policy does not depend on WebSocket details.
   Only the adapter depends on its connection ledger and profile policy.
7. Socket mutation, timers, retries, and close operations remain in the adapter.
8. The new ledger is disposable connection-local state.
   It is rebuilt from completed responses, capped at 256 live and 256 evicted-ID entries, and cleared with the socket.
9. Warm requests perform one bounded hash lookup.
   Insertion order and eviction work remain bounded by the fixed adapter-private cap.
   The 600-second idle window trades a bounded live connection cost for fewer full requests.
10. The response ledger represents a real endpoint variation: response IDs can remain usable on one connection after newer descendants complete.
11. Existing session and provider contracts remain compatible.
   Obsolete latest-only compatibility state should be removed.
12. The single latest-response compatibility rule can be removed once the ledger owns compatibility.
13. Expected response unavailability selects one safe full retry.
   Unexpected configuration and transport errors remain visible.
14. Adapter tests prove the transport state machine, composed integration proves the harness join, and credentialed E2E proves the private endpoint behavior.
