* Architecture review

The implementation is =local-and-contained=.  Provider request variability,
reasoning identity, replay normalization, and wire schema remain in the OpenAI
adapter.  Exhaustive source disposition and bounds remain in provider-neutral
core.  Atomic side effects remain in the harness/session boundary, and external
classification remains in E2E.  No stable policy depends on the adapter, no
provider-specific branch enters core, and no UI, transport, or tool handler
acquires business policy.

State lifetime is minimal: disposition normalization is pure; frames remain
request-local; retained exact/summary items use the existing v3 record; drop
adds no semantic record or negative ledger; reasoning summaries add no new
semantic state; WebSocket availability remains connection-local; and evidence
records retain hashes/classifications rather than raw content.  V2 remains
read-only compatible, unrelated transports are unchanged, and obsolete
omission semantics have no runtime compatibility shim.

Performance is proportional to the material input: label validation is one
hash-table pass, dropped sources are not copied into the durable record,
retained work is capped at 16 labels and 8,192 bytes, and replay normalization
copies only provider replay items at the adapter boundary.  No extra ordinary
provider request is introduced; only explicit external evidence scenarios add
test traffic.  No performance finding or follow-up is justified.

The documentation-only remediation changes no ownership, dependency, state,
compatibility, or performance boundary.  No architecture finding or follow-up
remains.
