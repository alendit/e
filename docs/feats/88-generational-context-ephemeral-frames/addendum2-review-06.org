** INCOMPLETE P2-12: the live path does not report provider-request latency or successful metrics

The deterministic part is closed.  The composed test captures literal
serialized request bytes and input-item counts beside each request at
=test/e-provider-continuation-integration-test.el:1158-1171=.  It selects the

=addendum2.org:390-395=.

The live part still misses two explicit contracts: request-latency identity and
successful reporting.  The accepted requirements say separate measurements
must report request latency and provider token values at
=addendum2.org:521-526,550-554=.  The current E2E instead:

1. starts =warm-started-at= before =e-board-e2e-prompt-batch= and subtracts
   after the complete harness turn returns at =e2e/e-live-e2e-test.el:868-874=.
   That includes context construction, provider request, loop settlement, and
   harness publication; it is turn-scoped latency, as the handoff itself calls
   it at =addendum2.org:401-403=, not provider-request latency.
2. places elapsed time, input tokens, cached tokens, and the unavailable marker
   only inside an =ert-info= context at =e2e/e-live-e2e-test.el:955-983=.
   Passing ERT tests do not print =ert-info= contexts.  A one-test control in
   this Tick passed with no =metric= text, and the passing composed metric test
   likewise emitted no metric line.  Therefore a successful credentialed
   command still would not report values that an implementation review can
   record.
3. overlooks the correct existing owner: the loop captures
   =provider-request-started-at= at =lisp/core/e-loop.el:440-458= and publishes
   rounded =:elapsed-seconds= in the matching =provider-request-finished=
   payload at =:459-473= through =e-loop--request-lifecycle-payload= at
   =:207-239=.  The E2E already selects exactly that warm finished event at
   =e2e/e-live-e2e-test.el:899-909=.

Classification: P2 incomplete prior closure and acceptance-instrumentation
defect.  This is independent of the missing credential: even a passing live run
would measure the wrong latency boundary and hide the numeric values on its
ordinary success path.  Impact: the required performance evidence cannot be
captured reproducibly, and turn overhead can be misreported as provider request
latency.

Owning correction: consume and assert the warm finished payload's existing
=:elapsed-seconds= value rather than timing =e-board-e2e-prompt-batch=.  Emit one
bounded, explicit success-path metrics record or log line containing separate
request latency, input tokens, cached-input token value or =unavailable=,
connection ID, reuse count, and fallback reason.  Keep semantic endpoint status
separate from token-field availability.  Do not add another production timer,
infer a missing cache field as zero, or retain the whole-turn stopwatch as a
proxy.

* Architecture self-check

1. The package is materially better than the baseline: bounded older-anchor
   reuse, safe fallback, detached identity, incomplete settlement, and finite
   retention are all present.
2. It advances provider-neutral semantic lifetime with adapter-local transport
   capability and conservative full reconstruction.
3. Private endpoint response-cache behavior and live token fields remain
   explicitly uncertain and external; deterministic policy remains local and
   reversible.
4. The harness owns clean-anchor selection; the OpenAI adapter owns connection
   availability, property identity, retry, and timer state; the loop already
   owns provider-request lifecycle timing.
5. No public ledger interface or core WebSocket dependency was introduced.
6. Stable semantic policy still does not depend on the concrete adapter.
7. Socket, retry, timer, and close side effects remain in the adapter.  P2-12
   should reuse loop telemetry rather than introduce a second timing owner.
8. Ledger state remains disposable, connection-local, bounded 256+256, and
   cleared by one socket owner; its mutable leaves are now detached.
9. Fixed-cap work is independent of durable session length.  The prohibited
   five-minute test is gone.  Wire metrics measure literal requests; live
   latency still measures excess whole-turn work and must be corrected.
10. The private ledger is a real adapter variation and no speculative graph
    abstraction or unsupported shared interface appears.
11. Unknown, evicted, incompatible, cross-connection, and rejected anchors
    retain safe full reconstruction; no compatibility shim was added.
12. Ledger lookup remains the sole compatibility authority; no obsolete scalar
    latest-only authority resurfaced.
13. Expected unavailable and incomplete terminals now have explicit owners;
    transport and unexpected errors remain visible.
14. Owner tests and the realistic composed test agree.  The one remaining code
    evidence gap is narrow: report the already-owned provider latency and live
    usage values on successful credentialed execution.
