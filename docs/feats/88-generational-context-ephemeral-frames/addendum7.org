In particular, the current contract has optional =keep=, =summaries=, and
=erase= keys.  It has no =drop= key and does not require an exhaustive
partition.  Ordinary omission preserves separately owned projections such as
a Feature 90 receipt; explicit =erase= suppresses every automatic projection
derived from the selected ordinary tool result.

The implementation and review boundary is one behaviorally coherent package,
not separate A7.1/A7.2 deliveries.  Acceptance requires the real model carrier,
atomic durable application, receipt integration, and credential-free
model-to-context coverage together.

The integrated implementation is ready for independent fixed-point review.
Repository validation passes 2,453 tests with 2,451 expected passes, zero
unexpected results, and two expected graphical skips.  Warnings-as-errors
compilation, Org parsing, and whitespace validation also pass.  Configured

* Decision

Give the model one reserved =context-curate= effect with exactly three optional
keys:

#+begin_src json
{
  "keep": [1],
  "summaries": [
    {"sources": [2], "text": "The retained semantic conclusion."}
  ],
  "erase": [3]
}
#+end_src

An omitted key is an empty list.  Unknown keys are invalid.  After
normalization, at least one label must appear in =keep=, a summary source list,
or =erase=.  Labels are positive frame-local integers and may occur at most
once across the complete submitted disposition.  At most 16 distinct labels
may be submitted and the complete prepared semantic package is bounded to
8,192 canonical UTF-8 bytes.

=keep= retains the exact bounded model-visible value.  A summary replaces its
listed sources with compact durable text.  Ordinary omission removes the exact
source but permits a projection owned elsewhere.  =erase= is valid only for an
ordinary tool-result source and removes every automatic future model-context
projection whose evidence is that source.

Erasure changes model context, not storage.  Transcript entries, tool activity,
provider audit/replay state, shell history, and session-scoped invocation
details remain inspectable.  Explicitly reading one of those stores later
creates a new ephemeral observation with its own lifetime.

Generic narration is not strengthened.  Only the reserved carrier has concise
schema-directed guidance.  Responses requests continue to request
=reasoning.summary: "auto"=; ="detailed"= remains a diagnostic override.

The material carrier identity is =context-curate-v5=.

* Product choices

There are no unresolved product choices in this package.  The remote authority
settles the previously ambiguous negative semantics:

- ordinary omission is the receipt-preserving default;
- explicit =erase= is the considered, no-automatic-trace decision; and
- no carrier call remains operationally observable but says nothing about what
  the model noticed or rejected.

The historical explicit =drop= disposition is removed rather than assigned a
new meaning.  This intentionally supersedes Addendum 6 where it conflicts.

* Smallest semantic model

One response supplies one optional three-way curation disposition over a live,
consumer-bound ephemeral frame.  Core resolves frame labels to trusted source
provenance and prepares one detached semantic package:

#+begin_src emacs-lisp
(:promotion OPTIONAL-VERSION-3-CONTEXT-PROMOTION
 :erasure OPTIONAL-VERSION-1-CONTEXT-ERASURE)
#+end_src

The promotion component contains only retained exact values or replacement
summaries with core-derived provenance.  The erasure component contains only
source identity/provenance and tool-call identity; it contains no arguments,
result, purpose, receipt, URI, provider item, or backing object.

Session persists the package as one atomic =context-curation-package= entry.
The two semantic record codecs remain distinct because the remote contract
requires additive version-3 promotion compatibility and a content-free
version-1 suppression authority, but they are never separate commits for one
model decision.  Harness appends that package, appends its separate response
audit control, and only then consumes the frame.

The selected-path session projection exposes erased tool-call identities.
Feature 90 consumes that narrow projection before deriving any receipt block
or aggregate.  No receipt policy flows back into core curation semantics.

* Mechanisms retained and why

| Mechanism | Concrete requirement |
|-----------+----------------------|
| Runtime-only consumer-bound frame and numeric labels | The model must select current ephemeral sources without supplying durable identities. |
| Version-3 promotion codec | Existing exact/summary durable records remain readable and keep their established provenance contract. |
| Content-free version-1 erasure codec | Suppression must survive replay without copying source content or receipt details. |
| One atomic curation package | A mixed decision must not expose promotion without erasure, erasure without promotion, or consume the frame after a partial write. |
| Selected-path erasure query | A descendant must inherit suppression while a sibling before the decision must not. |
| Checkpoint/compaction retention by owning generation | A receipt or other derived projection must not reappear after reopen or compaction. |
| Receipt-provider filtering before aggregation | Erasure must leave no indirect count/latest/omitted mark. |
| Carrier revision and cache invalidation | The optional three-key schema is materially incompatible with Addendum 6 evidence and anchors. |
| =reasoning.summary: "auto"= | Reasoning visibility improves diagnostics without strengthening generic narration. |

* Mechanisms removed or collapsed

- The =drop= carrier field and every exhaustive-partition rule.
- Required top-level carrier keys and missing-label rejection.
- Drop-only audit, eviction, and autonomous-drop evidence machinery.
- Independent A7.1/A7.2 delivery, review, status, and measurement ledgers.
- Separate promotion and erasure appends for one decision; one session package
  is the only write boundary.
- Any generic narration or checkpoint reminder added solely to encourage tool
  adoption.
- Compatibility aliases and interim public APIs that are not needed to read a
  committed historical format or serve a real consumer.

Older addenda and review artifacts remain historical records.  Their =drop=
examples and =context-curate-v4= evidence are not current acceptance evidence.

* Compatibility consequences

Version-2 and version-3 promotion records remain readable.  Existing
transcript, activity, provider audit, and tmp-resource formats are unchanged.
The new erasure record and package entry are additive persistent formats.

The model-facing Addendum 6 carrier is intentionally incompatible: calls with
=drop= are rejected and omitted =keep=/=summaries=/=erase= keys are valid.
Schema fingerprints and provider anchors must therefore change with
=context-curate-v5=.  Addendum 6 external adoption/cache results remain useful
history but cannot establish compatibility for this carrier.  Responses HTTP
and built-in ChatGPT/WebSocket evidence remain separately classified.

No compatibility promise preserves uncommitted A7.1/A7.2 APIs, aliases, or
standalone write paths.  Read compatibility is retained only for actual
committed session formats.

* One behaviorally coherent implementation package

The package stops only when all of the following work together:

1. The actual backend carrier presents optional =keep=/=summaries=/=erase=,
   uses =context-curate-v5= identity, and Requests reasoning summaries.
2. Core validates labels, exclusivity, ordinary-tool erase eligibility, the
   16-label limit, and the complete 8,192-byte package before mutation.
3. Session atomically persists optional promotion plus erasure, replays it on
   the selected path, and preserves it through checkpoint and compaction.
4. Harness commits the semantic package before audit/frame consumption.
5. Feature 90 filters erased receipts before every bound and aggregate.
6. The credential-free real-adapter scenario proves both omission-preserves-
   receipt and erase-suppresses-receipt while activity/tmp details remain.
7. The configured naturalistic runner records explicit erase separately from
   missing adoption, keeps =reasoning.summary: "auto"=, and refreshes material
   cache/evidence identity.

Focused owner checks are used during implementation.  One independent
fixed-point review occurs at this integrated boundary; internal steps are not
separate acceptance points.

* Non-goals

- Deleting or rewriting transcript, activity, audit, shell, or temporary data.
- A model-controlled privacy or durable audit-erasure operation.
- Changing exact keep or summary content semantics.
- Treating omission or a missing carrier call as an explicit negative decision.
- Making erased tool descendants eligible as clean provider anchors.
- Adding erasure controls to ordinary tools or Feature 90 envelopes.

* Design self-check

1. If work stops at the package boundary, the real model-to-context path has
   useful receipt-preserving omission and durable no-trace erasure.
2. It moves toward explicit provenance-backed context lifetime without
   conflating context projection and storage deletion.
3. Provider adoption remains uncertain and is isolated in carrier guidance and
   external evidence; erasure semantics, provenance, and ownership are stable.
4. Feature 88 owns lifetime decisions; session owns durable path projection;
   Feature 90 owns receipt rendering and bounds.
5. The carrier and erased-ID query are narrow and consumer-shaped.  Removing
   =drop= and interim APIs reduces coupling.
6. Receipt projection depends on Feature 88 authority; core does not depend on
   a provider, receipt renderer, shell, or tmp implementation.
7. Transcript, activity, and resource side effects remain with their existing
   owners; curation preparation is pure.
8. Only compact semantic provenance is added durably.  Source content keeps its
   existing lifetime and can be rebuilt only through explicit reads.
9. Validation is bounded; receipt filtering adds bounded identity membership
   checks before existing aggregation work.
10. =erase= has one substitutable meaning: no source-derived automatic future
    model context.
11. Committed promotion compatibility remains; obsolete model-facing and
    uncommitted compatibility paths are removed.
12. The exhaustive =drop= carrier, its evidence runner, and superseded partial
    ledgers can be deleted now.
13. Expected invalid dispositions fail before mutation; unexpected persistence,
    replay, and projection errors surface visibly.
14. Core, session, harness, receipt-provider, adapter, credential-free E2E, and
    configured evidence tests isolate failures at their real owners.
