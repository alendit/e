* Findings

** DONE High P1 =F88A7.I1=: exact package retry conflicts after first append

Contract cell: =F88A7-ATOMICITY=.

Package identity hashes the session and semantic components, while duplicate
validation also compares the newly prepared parent with the historical parent
(=lisp/core/e-session.el:4221-4300=).  The first append advances the head to the
package (=lisp/core/e-session.el:4472-4478=), so an exact immediate retry has the
same ID but a different proposed parent and signals a conflict.

This breaks recovery when package append succeeds but the later audit append
fails.  Accept an exact existing package only when its type/components match
and it is on the selected path; keep rejecting off-path and conflicting
identities.  Cover immediate, descendant-head, audit-failure, reopen,
queued/controller, and sibling-conflict retries.

Closed at =772018ebb38f6c2a24ab57e29bbf289dc07bcb2f=.  Exact selected-path
retries accept the matching historical package independently of the newly
proposed parent; off-path and semantic identity conflicts remain errors.  The
required retry and failure-path cases pass.
