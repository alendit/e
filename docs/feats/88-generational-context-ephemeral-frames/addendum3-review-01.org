* Findings ordered P0--P3

** TODO P1-01: late input is inherited but the proposal does not revise the replacement capability

*** Proof

Addendum 3 requires changing current-state/dynamic observations to become late
provider =input= items while top-level =instructions= remains stable
(=addendum3.org:179-197=).  It still calls this “late-frontier projection for
replaceable current-state and dynamic context” at =:276=.

The accepted parent contract says the opposite wire fact is what justifies
=request-local-replaceable=: the complete observation is top-level
=instructions=, and appending a developer/system input item is not replacement
(=plan.org:247-275= and =addendum.org:21-57,131-165=).

Current source implements that contract:

- =e-openai--request-local-observation-delivery-map= reports current/dynamic as
  replaceable at =e-openai.el:433-440=;
- =e-openai--profile-context-capabilities= exposes that map at =:782-849=;
- =e-openai-codex--instructions= places the current observation in top-level
  instructions at =:1181-1205=;
- =e-harness--provider-anchor-selection-allowed-p= allows a linear anchor when
  delivery is replaceable at =e-harness.el:3539-3560=; and
- =e-harness--provider-anchor-candidate-persistable-p= treats a replaceable
  observation as non-inherited at =:3910-3946=.

The official WebSocket contract says =previous_response_id= inherits the prior
response context.  Therefore an observation sent as ordinary developer input
is intentionally inherited by its matching tool follow-up.

Impact: implementing only the requested wire move leaves a false semantic
capability claim.  The harness may persist or select a response as clean even
though its provider lineage still contains the expired observation, violating
Feature 88’s central lifetime invariant.

History: specification regression introduced by Addendum 3’s new layout, not an
inherited implementation defect.

*** Owning correction

Replace the first paragraph of “Put changing context at the frontier” with:

#+begin_example
For every Responses profile adopting F88A3-LAYOUT, current-state and
dynamic-context observations are rendered as late developer-role input and are
therefore inherited under previous_response_id continuation.  The adapter must
resolve those kinds to inherited for that effective profile identity.
The request-local-replaceable claim remains valid only for a profile that keeps
the complete current observation in top-level instructions.

An observation-bearing response and every contaminated descendant are
immediate-followup-only and must not become durable cross-turn anchors.  The
existing linear continuation path remains available for the latest
tool-producing response and its matching function-call output, because
inheritance is required within that one successful turn.  A later ordinary
request uses canonical reconstruction unless a semantically exact clean
continuation with no inherited ephemeral frontier is independently eligible.
No new core capability, provider predicate, or profile-specific harness switch
is introduced.
#+end_example

In =Status=, replace the first-addendum supersession sentence with:

#+begin_example
For every profile adopting F88A3-LAYOUT, this addendum supersedes the first
addendum's current-state/dynamic-context request-local-replaceable claim and its
top-level-instructions wire contract.  Profiles that retain that proven wire
contract remain governed by the first addendum.
#+end_example

Replace “late-frontier projection for replaceable current-state and dynamic
context” with:

#+begin_example
late-frontier projection for ephemeral current-state and dynamic-context input,
with delivery truth recorded by F88A3-DELIVERY;
#+end_example

Do not plaster this with adapter-only suppression of =previous_response_id=,
continued persistence of falsely clean anchors, or a new profile-specific core
switch.  Capability truth, anchor selection, persistence, and wire projection
must agree at their existing owners.

Architectural-scope signal: moving bytes without changing semantic delivery
would create duplicated authority between the adapter wire path and the
backend/harness capability path.  The proper correction is bounded to affected
profile resolution, existing anchor policy, adapter projection, and their
tests.  No durable follow-up exists, and this current violation is not eligible
for follow-up deferral.
