* Architecture review

Ownership remains local and dependency direction remains inward-to-outward:

#+begin_example
context lifetime -> harness event -> Board runtime -> chat service
                                                    -> classic shell
                                                    -> ModernChat DTO -> Rust view
#+end_example

Context lifetime alone derives accepted semantic facts.  Harness owns the
side-effect sequence.  Board owns the public count-only activity and durable
source-key idempotence.  The service owns shared presentation language, and
each shell owns only its state and rendering.  Presentation reads no frame,
curation record, provider payload, or session-private identity.

The package adds one detached four-integer projection and one existing-tail
Board activity per successfully committed non-empty package.  It performs no
scan, polling, provider request, synchronous redraw, or cross-owner recovery.
Old sessions need no reconstruction; absent projections simply produce no
historical curation UI.  Unexpected malformed projections surface at core,
Board, or service boundaries instead of being swallowed.

No architecture or performance finding remains.

* Design self-check

1. Yes.  If work stops here, committed non-empty curation is observable in
   both shells while semantic behavior stays unchanged.
2. It moves toward observable, provider-neutral context lifetime with strict
   harness/presentation separation.
3. Wording and styling remain local and reversible; accepted counts, privacy,
   and success timing are direct stable contracts.
4. Context lifetime owns facts, harness owns completion, Board owns public
   activity, and shells own presentation.
5. Coupling is reduced: shells consume one narrow detached count projection
   instead of private session or frame state.
6. No stable policy depends on Board, shells, Rust, or the OpenAI adapter.
7. Persistence and publication remain outward side effects around pure count
   derivation and validation.
8. No semantic state is added.  Activity state uses the existing bounded,
   replayable Board lifetime.
9. Cost is constant per accepted package and requires no extra request, scan,
   or polling loop.
10. =context-curated= has one substitutable meaning across both shells and its
    four-field contract needs no unsupported operation.
11. Older sessions remain readable; no speculative backfill or compatibility
    fallback was added.
12. No new legacy path is needed or newly removable within this package.
13. Expected invalid decisions use existing turn failure; malformed public
    values signal at their owner and are not swallowed.
14. Pure owner, composition, direct adapter, Rust, graphical, and full-suite
    tests isolate behavior so future design changes remain narrow.
