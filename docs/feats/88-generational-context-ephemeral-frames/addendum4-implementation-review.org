* Findings

** TODO P1 =F88A4.I1=: failed curation can leave assistant content durable

Contract cells: =F88A4-ATOMIC= and =F88A3-SEM=.

Observed fact: for a non-tool response, =lisp/core/e-loop.el:1016-1027= adds
the assistant message to =turn-messages= and calls =append-message= before
=notify-response-complete=.  The latter is the first point at which the harness
binds labels and calls =e-context-lifetime-prepare-curation=
(=lisp/core/e-harness.el:3139-3194=).  Therefore an argument that passes stream
normalization but fails live-frame preparation, such as =(:keep (2))= for a
one-source frame, fails only after the assistant entry was appended.

A direct harness/loop reproduction at the reviewed revision returned
=e-context-lifetime-invalid-record= and then printed:

#+begin_example
messages=((user "trigger") (assistant "MUST-NOT-PERSIST"))
#+end_example

Existing invalid-control coverage either fails during stream normalization or
calls the harness preparation boundary directly; it does not cover an
assistant-bearing response whose label or prepared byte bound fails at provider
completion.

Consequence: a response reported as failed can still change durable semantic
context, and the next ordinary request can include assistant content from the
rejected response.  This contradicts the requirement that invalid curation
commit no semantic mutation.

Minimal correction: introduce a pure response-completion preflight before any
assistant append.  It must resolve the authoritative producer frame, validate
and prepare the complete zero/one curation, and return a prepared commit value
without mutation.  Only after preflight succeeds may the assistant entry,
prepared v3 record, and frame consumption occur in their required order.
Preserve the existing allowance for ordinary tool calls/results already
streamed before an invalid effect; do not add rollback, settlement, or crash
recovery machinery.

Acceptance evidence: add a composed loop/harness regression with a live
one-source frame, assistant text, and each provider-completion-only failure
class (at least unknown label and 8,193-byte prepared record).  Assert the turn
fails, no assistant or curation entry is appended, the original frame remains
live, no later provider request starts, and already-streamed ordinary calls
retain the documented behavior.  Retain the valid assistant-bearing path and
prove its curation commits before any later dispatch.

** TODO P2 =F88A3.I2=: external scenario failures emit no classified evidence record

Contract cell: =F88A3-CACHE= deterministic evidence runner.

Observed fact: missing authentication has a dedicated bounded record at
=e2e/e-live-e2e-test.el:414-430=, but the deadline helper signals directly at
=e2e/e-live-e2e-test.el:433-439=.  The tool-heavy and warm-prefix selectors
emit their only post-request records at =e2e/e-live-e2e-test.el:1472-1491= and
=e2e/e-live-e2e-test.el:1741-1761=, after all provider calls and most semantic
assertions.  Neither scenario has a surrounding classification/finalization
boundary.  A provider/infrastructure error, elapsed scenario deadline, or
semantic assertion failure therefore unwinds before any identity-complete
record is printed.

Consequence: unsuccessful credentialed runs cannot be distinguished or audited
as =inconclusive-timeout=, provider/infrastructure failure, or semantic product
failure from the promised machine-readable evidence.  This makes the accepted
runner contract incomplete even though the currently observed missing-auth
case is reported correctly.

Minimal correction: give each selector one outer evidence finalizer that emits
exactly one bounded record for success, unavailable usage, product-contract
failure, semantic failure, provider/infrastructure failure, and scenario
timeout, retaining all identity and material-shape fields captured before the
failure.  Preserve the ERT failure/skip after recording and keep auth,
semantic, and cache classifications separate.

Acceptance evidence: deterministic tests inject a provider error, an expired
scenario deadline, and a semantic assertion failure.  Each must emit exactly
one content-free identity-complete record with the correct distinct result and
then preserve the intended failure outcome.  Existing auth-unavailable,
missing-usage, explicit-zero, and passing records must remain single-record
cases.

* Architecture and design self-check

1. The package is a useful step only after =F88A4.I1= and =F88A3.I2= are
   resolved; the current successful semantic path otherwise moves toward the
   accepted canonical durable-context design.
2. Stable behavior is direct: core owns source/curation semantics, session owns
   durability, loop owns response ordering, harness composes them, and OpenAI
   owns wire continuation and the reserved carrier.
3. Provider cache capability remains explicitly uncertain, local to the
   adapter/evidence boundary, and reversible without changing core semantics.
4. Responsibilities are cohesive except for the completion ordering exposed by
   =F88A4.I1=; its correction should split pure preflight from mutation rather
   than move policy into the loop.
5. Interfaces remain narrow and consumer-shaped; the review found no new
   provider-to-core dependency or unused generalized interface.
6. Dependencies still point from adapter/harness orchestration toward stable
   core/session contracts.
7. Provider transport and persistence side effects remain outside core policy.
8. Runtime frames remain consumer-bound and in-memory; generations and v2/v3
   records use the smallest accepted durable lifetime.  No response graph or
   recovery state returned.
9. Source preparation and record validation are bounded by presented content
   and the 16-source/8,192-byte contract.  No new summary call or raw consumed
   observation retransmission was observed; the E2E performance record passed.
10. The backend capability and portable-message contracts remain substitutable
    across stateless, linear, branchable, and replaceable profiles.
11. Compatibility is explicit: generation and legacy promotion v2 remain
    readable, while new writes are v3 only and obsolete model-facing aliases
    are absent.
12. No additional legacy code was identified beyond the required v2 reader and
    historical audit data.
13. Expected malformed curation surfaces as a domain error; =F88A4.I1= is the
    remaining side-effect-order violation on that error path.
14. Owner, composed, persistence, retry, compaction, external-record, and full
    repository tests are broad, but the two finding-specific regressions are
    required before the next independent Tick.
