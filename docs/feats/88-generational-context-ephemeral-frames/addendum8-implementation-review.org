* Review corrections

The initial implementation review rejected three subtle shortcuts:

1. A duplicate could bypass ordinary frame-bound semantic validation.  The
   loop now validates against the retained just-curated frame before ignoring
   the effect.
2. The duplicate diagnostic could be emitted more than once.  Emission now
   occurs only on the first bounded correction.
3. A curation-bearing response candidate was classified immediate-only when
   received, but final promotion could discard that classification.  The loop
   now retains request replay state and recomputes from the completed response,
   so candidate-before-effect ordering is safe.

The terminal projection review additionally found that preserving
=turn-summary= could leave successful ModernChat state active, and that a
summary-only bounded replay lacked its provider witness.  Service-state
reconciliation and summary-owned aggregate state close both cases without
making the summary a second presentation terminal.

* Architecture review

Frame validity remains core-owned.  The loop owns request sequencing, bounded
recovery, and provider-candidate admission.  The adapter owns opaque wire
bundles.  Session owns accepted durable packages and anchors.  Board owns
public terminal/aggregate facts, while shells own rendering and composer
state.  No presentation component reads private frame or provider payloads.

The recovery state is one retained just-curated frame plus one turn-local
correction bit.  Candidate safety is one request-local boolean combined with
the completed response facts.  None is durable, unbounded, or scanned.  The
ordinary path adds constant work and no provider request; only the duplicate
path adds one bounded correction.

* Design self-check

1. Yes.  Stopping here leaves multi-frame curation useful and prevents the
   reported whole-turn corruption failure.
2. It moves toward frame-owned generational context with bounded,
   provider-neutral recovery.
3. Provider compliance remains uncertain and externally testable; frame
   identity, strict validation, and the one-correction bound are direct stable
   contracts.
4. Core owns validity, loop owns sequencing/admission, adapter owns wire state,
   session owns durability, and shells own presentation.
5. Coupling is reduced by replacing a turn-wide heuristic with one captured
   request/frame opportunity and narrow immediate-only candidate fact.
6. Stable context policy has no dependency on OpenAI or presentation code.
7. Opaque acknowledgement/correction serialization stays at the adapter edge.
8. Accepted packages and compatible anchors alone are durable; opportunity,
   correction, and candidate-order state end with the turn/request.
9. Normal cost is constant; duplicate recovery adds at most one request.
10. The same one-frame/one-decision contract applies to each adapter.
11. Existing sessions remain readable; v8 intentionally fences incompatible
    provider layout identities.
12. The obsolete turn-wide counter and failure-accepting regression are gone.
13. Recognized duplicates recover locally; malformed records and unexpected
    failures still surface.
14. Owner, composition, real-adapter, replay, shell, and graphical tests cover
    the change without relying on the user's live Emacs.
