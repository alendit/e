** P2-06: An endpoint-rejected response remains eligible in the proposed live ledger

The adapter owns the connection-local response ledger.
The representation is a lookup of completed response IDs with per-response invariant properties.
The lifetime is one healthy WebSocket connection.
The missing mutation boundary is the =previous_response_id= rejection that occurs before the one full retry.
The public surface is a full request without =previous_response_id= and bounded fallback diagnostics.
The named current evidence is =e-openai-test-websocket-unresolved-anchor-retries-full-request= at =test/e-openai-test.el:3465-3558=.

The addendum records only completed responses and defines close as the ledger-clear boundary at =addendum2.org:172-187=.
The addendum requires one full retry after an unavailable-response error at =addendum2.org:158-159=, but it does not remove or invalidate the rejected requested ID.
The current scalar implementation clears its sole response ID before the full retry at =lisp/adapters/openai/e-openai.el:2381-2391=.
The proposed ledger replaces that scalar with many eligible IDs, so retaining the rejected entry would change the recovery semantics.

The failure sequence is =R0= in the ledger, an incremental request from =R0= rejected as unavailable, and a successful full retry that later produces a contaminated response without advancing the harness clean anchor.
The harness may then select its still-clean =R0= again.
The adapter would find =R0= in the ledger and repeat the rejected incremental request instead of converging to the initial full path.
This violates the stated safe full-reconstruction recovery for unavailable response lineage and creates one endpoint failure plus one full retry on each such turn.

Insert this paragraph after =addendum2.org:178=.

#+begin_quote
When the endpoint rejects =previous_response_id= as unavailable, the adapter must remove only that requested response ID and its recorded properties from the live ledger before it sends the one full retry.
It must preserve the healthy socket and every other ledger entry.
A later request for the removed ID must select the initial full path without =previous_response_id= rather than retrying the rejected incremental branch.
The retry still records only the completed response from the actual full request.
#+end_quote

Add a focused adapter test that rejects a selected older entry, completes the full retry with a contaminated response, and proves that the next request selecting the retained clean anchor sends one initial full request without =previous_response_id=.
Add a companion assertion that a different compatible ledger entry remains incremental after the rejected ID is removed.

The adapter owns eviction-history diagnostics.
The representation is specified only as a bounded set of recently evicted IDs.
The lifetime is one WebSocket connection.
The mutation boundary is each live-ledger eviction and connection close.
The public surface is the =response-evicted= fallback reason.

The live ledger has insertion order, but the eviction history is only a bounded set at =addendum2.org:182-187=.

This weakness does not expose semantic context, but it makes bounded diagnostic behavior depend on an unstated container policy.
