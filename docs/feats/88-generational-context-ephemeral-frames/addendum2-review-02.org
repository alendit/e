* Findings

** DONE P2-03: Preserve the supported =nil= fallback policy

The baseline defcustom permits =nil=, which retains an idle socket until cancellation, failure, or backend replacement.
The planned profile field must therefore accept a non-negative number when present and must preserve the global value unchanged when absent.
The built-in Codex profile must still normalize to exactly 600 seconds.
The implementation tests must cover an undeclared custom profile with a global =nil= fallback and prove that no idle timer is scheduled.

** DONE P3-04: Define the ledger outcome for incompatible request properties

A property mismatch must send full reconstruction without =previous_response_id=.
It must not close a healthy socket or clear unrelated compatible ledger entries.
A later request may still use an entry whose recorded properties match that request.
Close paths remain the only wholesale ledger-clear boundary.

** DONE P2-05: Reflect the planned package in the feature index

The Feature 88 index row must be =Planned= while this addendum awaits operator readiness.
The title must identify Addendum 2 so coding agents do not treat the new package as completed Feature 88 work.
The addendum must state that the index advances through =Ready=, =In-progress=, =In-review=, and =Done= under the normal status workflow.
