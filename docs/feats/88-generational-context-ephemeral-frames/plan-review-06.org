* Finding

** P1 F88.13: tool terminality can precede completion of its durable transaction

=finished=, =failed=, and =resolved= are called terminal before the linked
provider result and result frame are durably complete.  Checkpoint retention
names only nonterminal executions.  Manual resolution also appends its execution
record and provider result before opening the frame outside that acknowledged
prefix.  A crash at any cut can therefore leave a terminal execution without
its linked result/frame, or omit an observation the next transition requires.

*** Owning correction

Persist the provider-linked result and result frame first, then append one
=execution-settled= commit marker last, referencing the complete identities.
Only that last marker makes an execution terminal and releases later work.
Checkpoint retention and replay must keep partial terminal transactions.
Replay idempotently completes the marker when every referenced record exists;
otherwise it records =outcome-unknown=.  Live completion and the public resolver
use the same transaction.  Acceptance crashes after every record boundary and
proves no incomplete transaction becomes terminal or loses its observation.
