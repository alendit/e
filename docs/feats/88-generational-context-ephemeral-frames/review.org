** P1 F88.I1.7: rejected replacement does not fence its predecessor

A same-key replacement sets the logical record to =pending= before preflight,
but preflight rejection changes only the state to =preflight-failed=.  The old
command remains mapped as current.  Its later success may therefore overwrite
the newer failed attempt with =acknowledged=, and the active logical watcher
incorrectly completes the barrier for the rejected replacement.

*** Owning correction

Advance logical-record attempt ownership before replacement preflight.  A
rejected replacement must terminally reconcile active logical watchers and
fence every predecessor response from changing the newer attempt's state.  The
old physical command may still complete its own callback and outbox lifecycle,
but it must not satisfy or overwrite the newer logical record state.  Add stale
success and stale failure predecessor tests after replacement preflight
rejection.

** P1 F88.I2.4: refreshed candidates persist under stale projection ownership

The loop correctly fences a response candidate after an incompatible stable
refresh, but the harness separately collects every raw candidate.  Refresh
changes only loop-local state; the active harness entry retains the original
context.  At turn completion the latest raw candidate is therefore persisted
with fingerprints from that original context.

For =request A -> refresh B -> request B=, =resp-B= can be recorded with
stable-A fingerprints.  If B emits no candidate, rejected =resp-A= can instead
be recorded as covering the final B assistant entry.  A later return to A can
then select provider state that actually inherited B.

*** Owning correction

Make accepted candidate ownership explicit.  Persist only candidates accepted
after projection-identity comparison, carrying their producing/final projection
identity or context.  Atomic refresh must also replace the active harness
entry's authoritative context.  Add real harness persistence tests for stable,
tool-schema, provider-option, and compaction changes, including later reversion
to the old fingerprint.

** P1 F88.I2.5: caller-controlled partition proofs bypass fail-closed validation

=:replaceable-current-state-partitioned= bypasses all adapter validation, while
=:context-segment-message-count= can authorize a partial segment description.
Both keys flow from ordinary default/session options, and the harness does not
remove a stale supplied count when exact coverage is absent.  Hostile probes
therefore placed current state in both top-level instructions and explicit
input, after which the response remained eligible as a clean anchor.

*** Owning correction

Remove the public partitioned escape; the continuation-delta branch already
knows lexically when its source is clean.  Treat segment-boundary metadata as
reserved derived state: strip caller values and recompute it only from exact
harness context coverage.  Add hostile and stale-option tests for both keys.
