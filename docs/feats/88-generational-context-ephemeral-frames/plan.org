* Goal

Make model context a provider-neutral projection with three model-visible
lifetime classes:

#+begin_example
immutable checkpoint C
  + append-only durable tail D
  + one reasoning-frontier observation E
#+end_example

The protocol is:

#+begin_example
observe -> consume -> curate selected information -> forget observation
#+end_example

Large addressable data remains outside context behind existing resource and
context-reference handles until explicitly retrieved.  The feature preserves
the existing tool and provider-follow-up lifecycle on successful turns while
preventing a useful observation from becoming permanent causal history.
Provider continuation accelerates this projection; local semantic state stays
authoritative and can always rebuild a request.

* Scope revision

The former plan proposed journaled tool admission, dispatch, result, frame
closure, and restart recovery.  That proposal is removed from Feature 88.  In
particular, this feature does not add:

- lifecycle durability or crash recovery for tool follow-ups;
- admission, dispatch, result, or settlement journals;
- recovery state machines;
- exactly-once semantics for arbitrary external effects;
- a transactional outbox;
- acceptance that requires recovery after every append; or
- an interim abstraction whose main purpose is making the append-only journal
  transactional.

Frame state may be in memory for the normal successful turn.  An existing
session identity may be retained when it is already required for audit or
projection, but the feature must not invent a restart guarantee for an
in-flight tool.  SQLite persistence and atomic transitions may provide that
guarantee in a later, separately owned design.

Test disposition follows the boundary:

- retain visibility, promotion, projection, anchor, and adapter-capability
  tests;
- strengthen successful-turn tests for observation disappearance and selected
  fact retention;
- replace transaction-oriented tests with normal successful-turn context
  tests; and
- remove tests whose acceptance depends on recovering a tool follow-up after a
  crash or on per-append acknowledgement.

* Problem

The current context model distinguishes stable and dynamic placement, but not
durable and ephemeral lifetime.  A request is approximately:

#+begin_example
[static][stable][current canvas][durable transcript]
#+end_example

That can be cache-friendly while still making the canvas part of inherited
provider state.  If an adapter advances an anchor after snapshot =E1=, a later
snapshot =E2= leaves =E1= in the inherited causal history:

#+begin_example
A -> B -> E1 -> response-1 -> | anchor |
                                  \
                                   E2 -> response-2
#+end_example

Newer instructions can tell the model that =E2= supersedes =E1=, but cannot
remove =E1= from transformer state.  Tool results have the same problem when
their complete bodies are copied into durable transcript context.  Existing
compaction solves occasional transcript replacement, not prevention of
high-volume observations entering the reusable prefix.

* Context lifetime model

These names describe logical model visibility, not storage retention, and
=ephemeral= is unrelated to provider prompt-cache vocabulary.

| Lifetime | Meaning | Examples |
|----------+---------+----------|
| =CHECKPOINT= | Immutable semantic baseline for one generation | compacted continuation, current goal, established decisions |
| =DURABLE= | Append-only semantic information reused later | user intent, assistant decisions, promoted facts |
| =EPHEMERAL= | Observation visible at one reasoning frontier unless promoted | tool output, trace, canvas snapshot, large source excerpt |
| =EXTERNAL HANDLE= | Existing reference delivery mode; resolving it creates a bounded observation | full traces, source indexes, runtime objects |

External handles are not a fourth frame state.  A semantic request is:

#+begin_example
active static-prefix + active stable-context
+ generation checkpoint + durable tail + open observation frame
#+end_example

=e-capabilities= rebuilds the static and stable segments per request.  They are
not copied into promotions, but their fingerprints participate in anchor
compatibility.  Current-state segments belong to the observation frontier.

Every frontier item has a semantic kind, stable observation identity, source
fingerprint, and an effective delivery mode.  Delivery is therefore a
kind-scoped query, not one scalar property of the whole request:

| Kind | Typical item | Effective delivery must be proven per profile |
|------+--------------+-----------------------------------------------|
| =current-state= | canvas/current value | =request-local-replaceable= only when the adapter proves it |
| =dynamic-context= | refreshed subscription/context value | =request-local-replaceable= only when the adapter proves it |
| =tool-result= | ordinary tool output | =inherited= unless separately conformed |
| =trace= | diagnostic or execution trace | =inherited= unless separately conformed |
| =retrieved-excerpt= | bounded source excerpt | =inherited= unless separately conformed |

The core query returns this mapping and each item's effective mode.  It never
infers that replacing a canvas also replaces a tool result, trace, or excerpt.

=e-session= is the canonical session transcript and current-branch path.  It is
the only durable body source.  An observation may remain there for
diagnosis/export while being absent from later model context; runtime frame
state never becomes a second durable body store.  Durable tails are derived
from eligible session entries and promotion provenance, not copied into a
generation record.

=e-harness-turn-context= is the real projection consumer: it reconstructs
eligible durable session entries and promotions for the current branch and
passes them through the core lifetime projector for later requests.  The
existing session export/audit surface may expose those same session records,
but it is not a second body store.

** Runtime frame schema

Frame state is runtime-only normal-turn state and has this consumer-shaped
schema:

#+begin_example
(:frame-id FRAME-ID
 :generation-id GENERATION-ID
 :consumer-request-id CONSUMER-REQUEST-ID
 :observations
 ((:observation-id OBS-ID
   :kind current-state|dynamic-context|tool-result|trace|retrieved-excerpt
   :source-entry-ref ENTRY-ID-OR-EXTERNAL-REF
   :source-fingerprint FINGERPRINT
   :effective-delivery inherited|request-local-replaceable
   :body RUNTIME-ONLY))
 :consuming-response-entry-id RESPONSE-ENTRY-ID-OR-NIL
 :promotion-ids (PROMOTION-ID ...))
#+end_example

No durable frame record is emitted.  A frame may be reused only for the same
not-yet-consumed =consumer-request-id= and matching source fingerprints.  Every
later invocation receives a new consumer-bound frame, even when the source
fingerprint is unchanged.  The consuming response identity and selected
promotion IDs bind provenance to the current frame and session path; they do
not make the runtime body durable.

Tool call identity/arguments, locally identified provider-required replay
items, and the corresponding tool result form one ephemeral follow-up
observation bundle.  The whole paired bundle is visible to its consuming
invocation and absent from later model projections unless selected information
is promoted.  Session audit may retain the bundle, but stateless, clean-branch,
and current-state-replaceable projections must not emit an orphan call, result,
or replay item after consumption.

Within =G17=:

#+begin_example
G17
  checkpoint: C17
  durable tail: D81 D82 D83
  open frame: E20
  external handles: trace:t19 value:v72 test-run:r14
#+end_example

#+begin_example
[C17][D81 D82 D83][E20]
                       |
                       v
                 promote Delta84

[C17][D81 D82 D83][Delta84]
#+end_example

If no selected information is promoted, forgetting =E20= is intentional.

* Required invariants

1. Local semantic state is authoritative; provider state is disposable.
2. A generation checkpoint never changes; its durable tail is append-only.
3. An ephemeral frame is visible only to its consuming reasoning transition;
   closing the normal turn removes its observations from later projections.
4. Promotion is explicit and small, and never an unreviewed copy of the
   source observation.
5. Audit history may retain provenance without making the observation body
   model-visible forever.
6. A provider anchor is reusable only when every ephemeral observation in the
   request is proven non-inherited for its own semantic kind.  A replaceable
   canvas alongside an inherited tool result contaminates the whole advancing
   response; the harness must hold the prior clean anchor or use stateless
   reconstruction.
7. Missing capabilities reduce optimization, not correctness; stateless
   reconstruction is universal fallback.
8. Compaction is a deliberate generation boundary, not ordinary frame cleanup.
9. Disabling the feature preserves existing request, tool, and follow-up
   behavior exactly.

* Anchor and cache rule

** No replaceable context channel

Let =H= be the latest clean anchor:

#+begin_example
C -> D1 -> D2 -> H -> | we are here |
                       \
                        E1 -> R1
#+end_example

=R1= must not replace =H=.  The harness consumes =E1=, appends selected
=Delta3= locally, and uses =H= only if the provider can safely branch from it;
otherwise it sends a stateless replay:

#+begin_example
[C][D1 D2 Delta3][E2]
#+end_example

Advancing across =E1= would make it an inherited ancestor that cannot be
removed.

** Proven replaceable channel

When a provider proves a kind-specific observation channel is not inherited:

#+begin_example
H -- replaceable=E1 --> R1 -> | safe new anchor |
R1 -- replaceable=E2 --> R2
#+end_example

Appending a newer system/developer message is not replacement.  The eligible
OpenAI Responses profile uses request-local top-level =instructions= for the
complete =current-state= and =dynamic-context= values while stable policy and
durable history remain in the reusable response chain.  This proves nothing
about =tool-result=, =trace=, or =retrieved-excerpt=; those remain inherited
unless a separate conformance claim covers that kind.  For example:

#+begin_example
H -- replaceable current-state=Ecanvas + inherited tool-result=Etool --> R1
R1 is contaminated: hold H for a clean branch or use stateless replay.
#+end_example

Cleanliness covers ephemeral items introduced by both the request and the
response.  A response that emits a tool-call/replay bundle produces a generic
=immediate-followup-only= candidate: it may be used only to deliver the
matching result in the current in-memory follow-up and is never persisted.
Any descendant with that bundle ancestry remains contaminated unless a
separately conformed capability replaces the entire paired bundle.  Otherwise
the harness retains the prior clean anchor or uses stateless reconstruction.
Adapters contribute only opaque provider IDs and wire encoding; they do not
decide that a partial bundle is clean.

* Curation contract (Addendum 4 supersedes model-facing promotion)

The durable result is a provider-neutral curation delta, not a provider summary
format.  Core owns its strict normalized schema and validation.  An adapter
decodes its wire carrier into this shape and returns an opaque acknowledgement;
wire syntax is not a second semantic contract.

#+begin_example
(:type context-curate
 :arguments (:keep (1)
              :summaries ((:sources (2 3)
                            :text "The durable fact from sources 2 and 3."))))
#+end_example

The model-facing arguments contain the required =:keep=, =:summaries=, and
=:drop= arrays.  Keep and drop labels are positive integers; every summary has
non-empty positive integer source labels and non-empty text.  The three arrays
must form one non-empty, duplicate-free, complete partition of the presented
labels.  Unknown or omitted fields, coercion, duplicate dispositions, unknown
labels, malformed values, multiple effects, or an empty disposition fail before
mutation.  Core binds labels to the still-live consumer-bound frame and derives
exact source values and provenance; no model or adapter-supplied frame,
observation, reference, or fingerprint identity is trusted.

The core accepts 1--16 disposed sources and a prepared record of at most 8,192
canonical UTF-8 bytes.  Exact keep items precede summaries in their submitted
orders.  New durable records use version 3 of the existing
=context-promotion= family and contain detached exact/summary content plus
core-derived provenance; version-2 records remain read-only compatible.  The
old model-facing =context-promote= carrier and writer are removed.

- User and ordinary assistant messages retain existing durable semantics.
- Raw tool results, traces, large retrieved excerpts, and current-state
  snapshots are ephemeral by default in new projections.
- The reserved curation carrier is outside the ordinary model-facing tool queue
  and is never dispatched through the ordinary tool registry.
- Ordinary tool calls keep their existing streaming lifecycle.  Response
  handling validates at most one curation effect in memory, prepares it before
  append, and commits it before any subsequent provider request.  This is not a
  cross-restart exactly-once guarantee.
- Invalid curation follows the existing provider-response failure path.  Calls
  already streamed are not rolled back, and later calls from that response are
  not dispatched after invalidity is detected.
- Sources explicitly assigned to =drop= are forgotten.  A successful curation
  stores only selected exact values or submitted summaries and derived
  provenance; the next request omits all consumed raw observations, labels,
  estimates, and transport data.
- No journal, barrier, outbox, recovery state machine, or automatic summarizer
  is introduced for this normal-turn path.

The core-generated curation schema/presentation revision participates in tool
schema and anchor/cache compatibility identities.  A revision change therefore
fences an old anchor instead of silently changing a cached request's meaning.

* Successful-turn frame protocol

Frames are the minimum semantic boundary needed to answer which observation is
visible to which invocation.  The enabled normal path is:

1. capture a provider-neutral observation identity and source fingerprint;
2. expose it only at the current request frontier;
3. accumulate and validate any reserved curation control while the ordinary
   response streams, then commit valid curation when the provider signals
   done;
4. append selected curation items to the durable semantic tail; and
5. build the next request without the consumed observation.

The =e-harness-turn-context= projection receives core-derived canonical source
provenance for the source frame and curation: an existing transcript entry or
an existing external/context-source handle plus fingerprint.  Its in-memory
state is not a promise that an interrupted tool can be resumed.  A context-only
rebuild may reuse a frame only when its source fingerprint matches; otherwise
it discards that frontier and captures a fresh observation.  This is a
projection consistency check, not tool retry or tool-lifecycle recovery, and it
never silently swaps bytes under an old identity.

Ordinary tools still use the established lifecycle, callback, error,
cancellation, timeout, and follow-up behavior.  The feature changes the
visibility of their returned observations, not the side-effect protocol.

* Generational compaction

The durable tail can contain superseded facts:

#+begin_example
C0 + D0
   |
   | deliberate compact boundary
   v
C1

C1 + D1 + D2 + ...
#+end_example

Portable compaction consumes the checkpoint and durable tail only.  It excludes
consumed observations and external payload bodies.  The readable existing
summary becomes the portable checkpoint for the next generation; the journal
remains append-only audit history.  The generation record contains only the
generation identity, portable checkpoint, and covered session boundary.  The
durable tail is derived from eligible entries and promotion provenance on the
canonical session path; it is not copied into the generation record.  Token
estimates, anchor fingerprints, and provider artifacts remain runtime or
adapter-owned diagnostics.

* Provider capability contract

Core asks the adapter for semantic capabilities and never branches on provider
fields:

#+begin_src elisp
(e-backend-context-capabilities backend options)
;; =>
(:continuation branchable
 :observation-delivery
 ((:kind current-state :mode request-local-replaceable)
  (:kind dynamic-context :mode request-local-replaceable)
  (:kind tool-result :mode inherited)
  (:kind trace :mode inherited)
  (:kind retrieved-excerpt :mode inherited))
 :prefix-cache explicit
 :provider-compaction opaque
 :reasoning-state replayable
 :reserved-effect-carrier context-curate-wire)
#+end_src

| Capability | Values | Core consequence |
|------------+---------+------------------|
| =continuation= | =none=, =linear=, =branchable= | whether a clean anchor can be reused |
| =observation-delivery= | kind-scoped mapping to =inherited= or =request-local-replaceable= | whether each frontier item is inherited |
| =prefix-cache= | =none=, =implicit=, =explicit= | acceleration only |
| =provider-compaction= | =none=, =opaque= | optional provider checkpoint projection |
| =reasoning-state= | =none=, =replayable= | ordinary replay treatment; distinct from the Responses =reasoning.summary= request field |
| =reserved-effect-carrier= | =none= or =context-curate-wire= | adapter carrier support for the core schema |

Missing capabilities select stateless reconstruction.  Unknown values are
configuration errors.  OpenAI alone maps proven replacement for
=current-state= and =dynamic-context= to =instructions=; no core module names
that wire field.  An adapter must not claim a capability it cannot implement
for its effective endpoint and transport.  No provider-owned reasoning-state
capability is supported: only =none= and =replayable= are allowed for ordinary
replay treatment.  This is separate from the mandatory OpenAI Responses
=reasoning= request object, whose effective =:summary= is =auto= or =detailed=.
If a provider requires an ordinary follow-up replay item, the semantic model
gives it a local provider-neutral identity and the adapter owns only its wire
encoding.  Core constructs the normalized =context-curate= schema, limits,
and revision/content fingerprint.  The reserved =context-curate-wire= carrier
only advertises that the adapter can encode/decode the exact core schema.  It
never advertises alternate limits, so there is one semantic authority.

* Ownership and dependency direction

** Core context policy

Own =CHECKPOINT + DURABLE + EPHEMERAL= projection, frame visibility,
curation limits, and semantic fingerprints.  Never import provider request
fields or tool transport objects.

** =e-session=

Own transcript/audit storage and existing branch semantics.  Preserve old
messages and anchors conservatively.  Retain semantic provenance only where it
is needed for audit or projection; do not claim tool-follow-up restart
recovery.

** =e-harness= and =e-loop=

Own normal-turn orchestration, streaming response handling, reserved-effect validation,
curation application, and anchor choice.  Keep ordinary tool lifecycle and
follow-up behavior intact.  =e-harness-turn-context= is the projection consumer
that rebuilds eligible session entries/curations through core projection.

** =e-compaction=

Own the deliberate generation-transition application service.  It calls pure
core checkpoint logic, persists the resulting durable generation through the
existing session append surface, and may delegate an optional opaque provider
projection to the adapter.  It never closes frames, settles observations, or
owns tool lifecycle.

** Backend adapters

Render semantic segments/frontier into provider wire shapes, advertise proven
capabilities, own provider ids/opaque items/cache controls/retries, and return
bounded diagnostics and candidates.  They decode/encode the core-owned
=context-curate= schema but do not define its limits or select curation items.

** Presentation

May show bounded generation/frame/cache diagnostics, but does not own lifetime
or curation policy.

* OpenAI projection and optional provider compaction

For an eligible Responses profile, stable policy and the durable canonical
projection remain before the changing frontier.  Addendum 3's affected layout
places current-state and dynamic-context observations in late developer-role
input with their inherited delivery truth; =context-curate= source labels and
estimates remain late-frontier presentation only.  Ordinary post-response turns
use canonical replay of session-owned durable state plus selected curation
items; =previous_response_id= is retained only for a matching immediate tool
follow-up.  Stateless replay is always the correctness fallback.

The adapter must not assume every OpenAI-shaped endpoint behaves like the
public API.  Profiles, gateways, HTTP, and WebSocket transports advertise and
prove their own capabilities.

OpenAI =POST /responses/compact= is optional acceleration at a generation
boundary.  The portable checkpoint is canonical and sufficient for every
backend.  Opaque provider state is disposable, keyed by provider/model/
boundary/layout/fingerprint, and never parsed by core.  A compaction request is
constructed statelessly from portable checkpoint + durable tail, or from an
anchor proven clean for every observation kind.  It must never reuse a
contaminated continuation id merely because the new delta omits an observation.
Consumed snapshots, tool output, acknowledgement, and diagnostics are excluded
from portable and provider checkpoint input.  Optional conformance/E2E evidence
records the literal compaction input and effective model context and asserts
consumed markers are absent from both; provider wire behavior remains externally
gated.  The curation presentation/schema revision and estimator ratio fence
material anchor/cache identity, while per-frame values do not.

* Observability

Add bounded diagnostics for generation/checkpoint boundary, normal frame
visibility and curation, observation/curated size estimates, anchor held or
advanced with reason, request/response observation classification, immediate-
followup-only candidate status, rendering strategy, portable/provider

Every request must make it possible to tell whether the observation was

* Implementation slices

1. *Semantic lifetime foundation.* Keep the capability query, generation/frame/
   promotion shapes, pure projection, bounded diagnostics, and opt-in behavior
   comparison.  Remove obsolete lifecycle-settlement machinery from the
   implementation rather than expanding it.
2. *Replaceable current-state delivery.* Keep the accepted OpenAI
   =instructions= projection, inherited/stateless fallback, and clean-anchor
   rules.
3. *Normal successful-turn promotion.* Accumulate and validate the reserved
   effect during the existing streamed response, apply valid facts at
   provider-done, and project the next request without raw tool observations.
   Preserve ordinary tools/follow-ups and do not add a completed-response
   buffering boundary.
4. *Generational portable compaction.* Start a new generation from durable
   context only and exclude ephemeral observations/provider artifacts.
5. *Optional provider compaction.* Add capability-gated disposable opaque state
   at a portable boundary and preserve local semantics when it is discarded.
6. *Presentation and evidence.* Show bounded diagnostics, add the real
   credential-free E2E, and complete performance/compatibility review.

Each slice is a semantic commit with focused tests and ledger updates.  Core,
session, harness, loop, and adapter changes require a full Emacs restart before
they affect a running instance; no live-reload shim is added.

* Accepted Slice 1/2 baseline

The accepted prior work remains part of the baseline only where consistent
with this narrowed scope:

- semantic backend capability resolution has conservative stateless defaults
  and rejects unknown values;
- generation/frame/promotion projection helpers and bounded diagnostics remain
  useful for visibility and audit comparison, with ordinary requests unchanged
  unless explicitly enabled;
- current-state and dynamic-context segments form an observation frontier;
  eligible OpenAI Responses requests render the complete current value through
  top-level =instructions=;
- inherited observations hold/discard anchors conservatively, while proven
  replacement can advance a clean anchor;
- stable prefix, tool schema, provider options, compaction boundary, endpoint,
  and transport identity remain anchor compatibility inputs; and
- forged anchor/partition metadata is ignored or rejected at the harness
  boundary.

The old lifecycle-settlement implementation is not an acceptance dependency.
It is to be removed or reduced to semantic audit/projection support in the next
code slice; this plan does not authorize extending it.

* Cleanup ledger

The current implementation inventory is intentionally explicit.  The next
code slice removes the Slice 1 settlement/barrier machinery rather than
building more consumers around it.  The retained durable boundary is the
generation identity/checkpoint/covered session boundary plus promotion
provenance for =e-harness-turn-context=.  Frames remain runtime-only; the plan
does not promise open-frame recovery, settlement, retry, or resume.  The
existing session export/audit surface may inspect the same records but is not a

* Acceptance criteria

** Core behavior

- The next projection is exactly portable checkpoint + durable tail derived from
  eligible canonical session entries/promotions + one runtime open frame, with
  active static/stable context added at request time; the frame body is never a
  second durable source.
- A marker present only in a consumed observation is present in exactly the
  consuming invocation and absent from the next request.
- A selected exact curation item or submitted summary remains in the next
  durable projection; a source explicitly assigned to =drop= does not.
- =e-harness-turn-context= can identify source observation, frame identity, and
  curation provenance from the canonical session path without implicitly adding
  source-observation or frame-payload fields to the durable projection.  An
  explicitly kept exact value or submitted summary is durable by choice within
  the bounded curation limit.
- Curation source selection resolves to an existing canonical transcript-entry
  ID when session-backed, or an existing external/context-source handle plus
  fingerprint otherwise.  Missing refs fail the response path; no transcript
  entry is manufactured solely to support curation.
- Model/adapter-supplied provenance controls such as =:source-refs= and
  =:fingerprint= are rejected before semantic mutation; external provenance is
  derived by core from the consumed runtime frame and existing source handle.
- A frame carries =frame-id=, =generation-id=, and =consumer-request-id=;
  reuse is allowed only for that same not-yet-consumed consumer and matching
  source fingerprint.  Two successful invocations with unchanged current
  state therefore have two consumer-bound frames, and a consumed older frame
  cannot accept a later curation.
- A provider-neutral tool call identity/arguments, any locally identified
  replay item, and its result remain one paired ephemeral bundle.  The bundle
  is visible to exactly its consuming invocation and later projections contain
  no orphan call, result, or replay item unless a source was explicitly curated.
- A changed canvas replaces the prior snapshot, does not create another durable
  transcript item, and does not invalidate an otherwise compatible stable
  prefix.
- A context-only rebuild reuses an observation identity only when its source
  fingerprint matches; otherwise it visibly starts a fresh frame and never
  swaps bytes under an old identity.  This is not a tool retry guarantee.
- Anchors never advance across inherited observations, may advance across a
  proven replaceable channel, and fall back statelessly with equivalent
  semantics when capabilities are absent.  Cleanliness covers ephemeral items
  introduced by both request and response; a tool-call/replay response yields
  only an in-memory =immediate-followup-only= candidate, and neither it nor a
  contaminated descendant may replace the clean durable anchor.
- Existing normal tool success, error, cancellation, timeout, and provider
  follow-up behavior remains unchanged outside observation visibility.
- Curation controls are accumulated in the existing in-memory response stream
  and a valid record commits at provider-done before the next follow-up
  projection; an invalid control follows the existing response error path, does
  not roll back already-streamed calls, and dispatches no later calls from that
  invalid response.
- Portable compaction starts a new generation from durable context only and
  remains correct when provider artifacts are discarded.

* Performance contract

- Ordinary turns append only small durable semantic deltas and reuse stable
  prefixes when safe.
- Consumed observation bytes are not retransmitted later.
- Canvas updates change only the request-local frontier, not stable-prefix
  fingerprints.
- No summary model call runs for every observation.
- Cold prefill occurs only at deliberate generation boundaries or safe fallback.
- Projection does not add an unbounded journal scan to every turn.
- Promotion validation is bounded by the returned effect, not history size.

Report first-turn, warm-turn, observation-turn, and post-compaction input/cache
counts for one capable profile.  Explain any material cache or latency

* Compatibility and migration

- Existing journals load without rewriting; messages without lifetime metadata
  remain durable.
- The generation codec remains version 2.  New context curation records use
  version 3 of the persisted =context-promotion= family; version-2 records
  remain readable and project according to their compatibility rules, but no
  version-2 writer or =context-promote= model-facing carrier remains.  Legacy
  =context-generation=, =context-frame=, and =context-frame-settlement= entries
  remain readable for ordinary transcript and audit loading, but reading them
  never recreates a runtime frame, recovery state, or resume-state projection.
- Existing ordinary tool calls/follow-ups keep current behavior and are not
  silently reclassified.
- New semantic visibility is explicit opt-in only.  An already opted-in session
  activates a changed classification at its next deliberate generation
  boundary; that boundary alone never enables the feature or reclassifies old
  results.
- Old/incompatible provider anchors fall back to one complete canonical replay.
- Backends ignoring new capabilities remain correct through flat stateless
  messages.
- Prompt-cache placement, continuation, and logical lifetime remain separate.
- Branches inherit checkpoint and durable path, not another branch's consumed
  frame.
- Export/audit views may show historical tool evidence while model context does
  not.

* Non-goals

- Do not delete or rewrite the append-only audit journal.
- Do not make provider fields such as =previous_response_id=,
  =instructions=, or opaque compaction items part of the core state model.
- Do not parse/display opaque provider compaction contents.
- Do not claim a provider forgot data merely because =e= omitted it; require a
  documented replaceable or stateless/clean-anchor path.
- Do not automatically promote every observation or summarize every result.
- Do not make the canvas durable conversation history.
- Do not require every backend to branch, replace, cache, or compact.
- Do not use compaction as bounded tool/resource output.
- Do not add another external-resource registry or persist external payloads in
  generation state.
- Do not promise exactly-once external side effects.
- Do not add in-flight tool crash recovery here; SQLite persistence and atomic
  transitions own that future concern.

* Risks and mitigations

- *A needed fact is not curated.* Make the contract visible, expose the
  explicit operation, retain audit provenance, and test selected versus
  unselected facts.  Do not retain every observation as insurance.
- *A provider falsely claims replacement.* Gate the claim per profile/transport,
  require conformance evidence, and fall back to a clean anchor/stateless
  replay.
- *Mixed observation kinds contaminate a continuation.* Evaluate the effective
  delivery of every frontier item independently; if any ephemeral item is
  inherited, hold the clean prior anchor or use stateless replay even when
  current-state/dynamic-context replacement is proven.
- *A response bundle contaminates a previously clean anchor.* Treat the
  immediate-followup-only candidate as in-memory delivery for the matching
  result only; descendants inherit contamination unless an entire-bundle
  replacement capability is proven.
- *Curation provenance cannot resolve its source.* Require an existing
  transcript-entry ID or external/context-source handle plus fingerprint and
  fail the curation path rather than manufacturing a transcript entry.
- *A reserved curation effect drifts between adapter and core.* Construct the
  normalized schema, source identity, limits, and revision/content fingerprint
  once in core; the optional adapter carrier only encodes/decodes it and never
  supplies alternate limits.  The fingerprint fences incompatible tool-schema/
  anchor identities.
- *A provider requires an unsupported reasoning mode.* Use only =none= or
  =replayable= for ordinary replay treatment; represent any ordinary replay
  item with a local semantic ID and let the adapter encode it, rather than
  adding provider-owned state.  The mandatory Responses =reasoning.summary=
  request field is separate and uses =auto= or =detailed=.
- *Portable/provider compaction drifts.* Portable context is canonical; opaque
  state is accepted only at the same boundary/fingerprint and is disposable.
- *A successful turn retains source fields accidentally.* Assert that the
  protocol does not implicitly add source-observation or frame-payload fields;
  an explicitly kept exact value or submitted summary is allowed to become
  durable by choice.
- *Provider compaction reuses contaminated state.* Build its input statelessly
  or from an anchor clean for every observation kind, and compare literal input
  with effective context while keeping provider wire proof externally gated.
- *Cache optimization leaks into policy.* Keep capability resolution/rendering
  in adapters and prove core projection with backend-free tests.
- *Audit storage grows.* This feature bounds model context, not audit storage;
  retention/export is separate work.

* Architecture self-check

1. *If work stopped here, is the project better off?* Yes.  The visibility and
   anchor rules prevent stale canvas inheritance, and normal-turn promotion is
   bounded without taking ownership of external side-effect recovery.
2. *Final direction?* A harness-owned semantic projection accelerated by
   provider adapters.
3. *Stable/uncertain?* Durable versus ephemeral visibility, the kind-scoped
   delivery map, request/response anchor cleanliness, stateless fallback, and
   portable checkpoints are stable.  Promotion wire realization and
   entire-bundle provider conformance remain local and reversible, while
   normalized schema, limits, and canonical source resolution are core-owned.
4. *Owner?* Core owns visibility/limits, normalized curation, and source-ref
   validation; session owns the canonical transcript/audit; =e-harness-turn-context=
   owns later-request projection; harness/loop own successful-turn orchestration;
   =e-compaction= owns deliberate generation transitions; adapters own opaque
   wire shape; presentation renders bounded status.
5. *Coupling?* Reduced: core depends on semantic capabilities, while normal
   tool lifecycle stays outside context policy.
6. *Dependency direction?* Provider code depends on the stable logical
   contract; core never imports an OpenAI request shape.
7. *Side effects outward?* Provider calls, session writes, tools, and resource
   retrieval stay at existing boundaries; projection is pure where practical.
8. *State lifetime?* Checkpoints and selected fact/provenance records are
   generation/session state; frames and immediate-followup candidates are
   normal-turn memory; anchors/provider checkpoints are disposable;
   presentation/cache state is runtime-local.
9. *Performance?* Repeated observation bytes disappear while monotonic prefixes
   remain reusable; cold work is limited to compaction/fallback.
10. *Real abstractions?* Each capability corresponds to a request strategy;
    missing capabilities select valid stateless behavior.  The ordinary replay
    modes are =none= and =replayable=; they are distinct from the mandatory
    Responses =reasoning.summary= values =auto= and =detailed=.  Core is the
    sole authority for the reserved curation schema, limits, and
    revision/content fingerprint; an optional carrier is only an adapter wire
    concern.
11. *Compatibility?* Opt-in is explicit; an opted-in session changes
    classification only at a deliberate generation boundary, never merely
    because a boundary exists or by reclassifying old results.
12. *Legacy removable now?* Remove the path treating refreshed dynamic input as
    sufficient replacement while retaining an anchor containing the old value.
13. *Errors?* Invalid promotions, capability mismatches, anchor rejection, and
    provider artifact expiry surface or use documented semantic fallback.
14. *Independent tests?* Pure projection/promotion/source-ref tests prove
    lifetime; adapter tests prove opaque wire mapping; the mandatory E2E proves
    paired bundle delivery, anchor contamination, and real successful-turn
    integration.
