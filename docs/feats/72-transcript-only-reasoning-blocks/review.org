** Resolved: the block destination was ambiguous

*** Problem

Bayesian guidance asked for the block in the "visible reply" while Org Canvas
called the document the primary output target.  The reported session therefore
placed assistant audit metadata in =edit.edits.newText=.

*** Change

Bayesian guidance now names the final assistant transcript message as the only
valid destination.  Org Canvas guidance says that internal reasoning,
calibration, claim-check, and audit metadata do not belong in the document or
another artifact.

*** Evidence

Instruction tests assert both sides of this contract.

** Resolved: deterministic tool rewriting was overengineered

*** Problem

The first implementation added a Bayesian =:pre-tool-call= hook that stripped reserved blocks from =write= and =edit= arguments.
User review rejected this because the agent should follow the output contract directly.
The hook also coupled Bayesian syntax to otherwise generic tool calls and silently changed requested output.

*** Change

The sanitizer, pre-tool hook, and enforcement tests were removed in =e92efdc=.
The final implementation consists only of the explicit Bayesian and Org Canvas instructions.
Resource tools remain transparent and preserve the content the agent supplies.

*** Evidence

The capability again registers only its existing turn-finished hook.
Instruction tests assert that reasoning metadata belongs only in the final assistant transcript message and never in an Org document.
