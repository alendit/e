** Resolved: the block destination was ambiguous

*** Problem

Bayesian guidance asked for the block in the "visible reply" while Org Canvas
called the document the primary output target.  The reported session therefore
placed assistant audit metadata in =edit.edits.newText=.

*** Change

Bayesian guidance now names the final assistant transcript message as the only
valid destination.  Org Canvas guidance says that internal reasoning,
calibration, claim-check, and audit metadata do not belong in the document or
another artifact.

*** Evidence

Instruction tests assert both sides of this contract.

** Resolved: guidance alone could not enforce the boundary

*** Problem

The resource lifecycle previously passed =write.content= and
=edit.edits.newText= through unchanged.  The turn-finished checker reads only
the final assistant message, so a tool-argument block had no audit value.

*** Change

The Bayesian capability now contributes a =:pre-tool-call= hook.  It strips
complete reserved Org and Markdown reasoning fences from resource writes and
edit replacement text.  It preserves =oldText= exactly so an existing leaked
block can be matched and removed.

The boundary intentionally does not rewrite arbitrary shell or =run_elisp=
source.  Rewriting executable text would be unsafe and would also corrupt valid
searches for the reserved markers.  General artifact placement remains covered
by the explicit model contract; deterministic enforcement covers the standard
model-facing resource mutation tools.

*** Evidence

Pure tests cover writes, edit lists, the provider's one-edit object shape,
preserved =oldText=, surrounding prose, and unchanged non-mutating calls.  A
harness-lifecycle test proves hook registration and execution.  A real
=file://= edit proves the cleaned replacement is what reaches disk.

* UX and performance playthrough

The user's screenshot and the persisted session supplied the real Org Canvas
failure path.  The resource-level regression test replays its =edit= argument
shape and verifies clean disk content.  The feature changes no window, focus,
rendering, or interactive command behavior, so a live UI playthrough would add
no distinct coverage.

The sanitizer performs one linear scan of each mutated string already present
in memory.  It adds no I/O or durable state.

* Architecture review

The Bayesian capability owns both the reserved syntax and its pre-side-effect
policy.  Org Canvas only clarifies its artifact contract, and generic resource
adapters remain unaware of Bayesian metadata.  Dependencies still point from
capability policy toward generic hook and tool-call contracts.  No compatibility
shim or new abstraction was added.

The design self-check in =plan.org= was re-evaluated against the final diff and
remains accurate.  In particular, the change reduces coupling, adds no state,
keeps side effects in resource adapters, preserves public tool contracts, and
tests the policy independently of the full UI.
