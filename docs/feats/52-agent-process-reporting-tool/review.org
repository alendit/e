  to present it as behavioral overhead.

* UX and performance playthrough

This slice has no new presentation shell or interactive UI.
Focused tests exercise empty-store first use, direct action capture, model tool
capture, restart/reload of the JSONL store, list/read, triage, duplicate
suppression, extraction accounting, redaction, and request-shape reporting.
Capture performs one bounded append and in-memory index update. It does not scan
sessions, spawn work, or call a provider.

* Plan coverage

The first slice meets the online capture, durable review, triage, redaction,
registration, guidance, and attribution requirements.
Provider-tokenizer accounting and repeated replay/A-B experiments are later
measurement executions. The slice stores the stable checkpoint, request shape,
request identity, usage joins, and estimate method needed to run them without
changing online capture.

* Architecture review

The process-reporting capability owns marker semantics and durable facts.
Core telemetry owns shared redaction and provider-request identity.
The loop stores hashes and sizes rather than depending on a provider adapter or
process-reporting storage implementation.
The model interface stays narrow. The append-only file is private behind
capability actions.
No presentation, issue tracker, extractor, or child-agent dependency points
into capture.

* Design self-check

1. The slice is useful alone because it preserves and routes high-signal process evidence.
2. It moves toward offline session learning and reviewed durable outcomes.
3. Signal vocabularies and triage states are local constants; stable append-only facts and ids are direct models.
4. Process reporting owns capture, marker storage, review, and triage.
5. The tool takes two fields. Other consumers use narrow actions.
6. Core telemetry does not depend on the process-reporting capability.
7. Persistence stays at the capability boundary. Provider lifecycle attribution stays in the loop.
8. Markers, triage, and extraction ledgers are durable facts. Cost summaries are derived.
9. Passive overhead is one tiny descriptor and one guidance sentence. Active persistence is one append.
10. The capture contract applies uniformly to all supported signals.
11. No legacy compatibility path was added.
12. There was no prior process-report store to retain.
13. Validation errors surface. Persistence and redaction errors are not swallowed.
14. Focused tests isolate store, redaction, capture, triage, and attribution behavior.
