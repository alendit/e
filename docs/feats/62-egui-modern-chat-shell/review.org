* Review summary

The first implementation slice is ready for review.

It adds =e-modernchat-new= as an optional egui-backed chat shell, vendors
=emacs-egui= as a submodule, adds a Rust/WASM UI, extracts a small
shell-neutral chat service, and keeps the existing =e-chat= shell as the stable
fallback.

No review findings are open from this implementation pass.

* UX and performance playthrough

Batch validation covered the launch preconditions and state conversion.
A live xwidget playthrough was not performed in the running Emacs because the
running instance was not reloaded with the new shell code during this pass.

The main UX path is ready for manual review after reload:

1. run =git submodule update --init emacs-egui= if needed;
2. run =wasm-pack build --target web --release --out-dir pkg ui/modernchat=;
3. reload =e= or restart Emacs;
4. run =M-x e-modernchat-new=;
5. send a prompt, inspect streaming state, expand/select activities, and open a resource.

* Plan coverage

- Feature-gated shell module: implemented.
- View-model bridge: implemented with bounded message and activity snapshots.
- Live updates: implemented with harness subscription and debounce.
- Rust egui app: implemented as a first slice with top bar, side panel, timeline, inspector, composer, and common Org rendering.
- UI actions: implemented for send, cancel, open resource, and output mode.
- Shell-neutral chat service: implemented for create, submit, steer, queue, abort, and output-mode operations.
- Build and validation commands: documented and exercised.

* Architecture review

Dependency direction is acceptable.
Core harness code does not depend on =emacs-egui= or Rust.
The modern shell depends on harness/session services and the optional vendored UI runtime.
The Rust app sees only DTOs and emits semantic UI actions.

The only durable state reused by the feature is existing chat session state.
New state is buffer-local UI/session metadata and Rust-side selection/composer state.
