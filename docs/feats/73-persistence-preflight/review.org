* Review summary

The persistence controller now validates and encodes a writer command before
the command enters the outbox or increments unsettled state.
The outbox stores the prepared wire command, so normal retries do not re-encode
application data.

The Node writer distinguishes deterministic request errors from retryable
filesystem failures.
Terminal rejections settle their outbox entry, call the error callback when one
exists, and otherwise raise an Emacs warning.

The development reload manifest now reloads session persistence.
Raw request plists remain accepted only for controllers created before a live
reload.

* Design self-check

1. This package stops the permanent retry loop and adds direct operational
   visibility, so it is useful independently.
2. It moves toward durable immutable board facts with transient runtime
   authority kept process-local.
3. JSON transport and retry policy are stable here; legacy live-controller
   support is local to the send boundary and can be removed after the current
   reload window.
4. Session persistence owns command preparation, outbox state, and retry
   policy; the Node writer owns filesystem I/O and classifies its own errors.
5. Coupling is reduced because retries retain an encoded transport command
   instead of revisiting arbitrary runtime data.
6. Core session policy does not depend on the board runtime; only the regression
   test loads the production opaque token type when that test runs.
7. Filesystem work remains in the Node adapter, outside Emacs mutation paths.
8. The only new state is one prepared wire string per unsettled command, owned
   by the outbox for exactly the command's unsettled lifetime.
9. Each command is encoded once instead of once per retry; status inspection is
   constant time.
10. The prepared-command record names a real invariant: validated request plus
    immutable wire representation.
11. Raw plist sending is retained explicitly for live controllers created by
    the older definition; new submissions use prepared commands only.
12. That raw-request compatibility branch can be removed after the current live
    upgrade window.
13. Local command errors signal synchronously; deterministic writer request
    errors settle and surface; process and filesystem failures remain queued
    for retry.
14. Focused tests prove preflight ordering, one-time encoding, terminal writer
    rejection, exact endpoint-token behavior, reload inclusion, and durable
    board-log reopen independently of the full system.
