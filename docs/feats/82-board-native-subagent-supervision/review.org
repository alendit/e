*** Expected

A structured child report must publish its durable terminal fact before local settlement.
A later manifest must replay that durable report into a valid projection.

** Review loop

*** DONE High: Board observation needed one bounded durable fact set

The new Board-owned query selects participant, lifecycle, orchestration, and
terminal-outcome facts as one byte- and count-bounded detached page.  Its tests
assert the exact source-key set and five constant-count SQL reads, so adding
participants cannot introduce per-participant routing, session, transcript, or
registry reads.

*** DONE High: The public registry still owned participant truth

The registry was replaced with a private live owner keyed by =(board-id .
participant-id)=.  It retains only pending admission and current execution
capabilities, removes entries at settlement, and cannot list, classify, hide,
reject, or reorder durable participants.  Binding-loss lookup now rejects an
ambiguous participant ID shared by multiple Boards instead of cancelling
either execution.

*** DONE High: Separate shells and observations preserved two models

The unified Board activity shell and Board observation actions now read the
same durable projection.  Selecting a durable participant optionally resolves
a current live handle for control; raw transcript inspection uses the bounded
durable session query.  Retargeting the singleton buffer cancels and fences the
old request.  The removal gate rejects the retired modules, public registry
operations, compatibility names, and generated =sub_NNNNNN= identities across
production, tests, E2E fixtures, extensions, and configuration.

** Architecture self-check

1. If work stopped here, the project would still be better: the contradictory
   process-local participant inventory is gone and the replacement is usable.
2. The change moves toward SQLite-authoritative Boards with Emacs owning only
   presentation and currently executable capabilities.
3. Page bounds and presentation remain local and reversible; durable identity
   and ownership are modeled directly, with no speculative extension layer.
4. The Board service owns durable observation, the runner owns live execution,
   and the shell owns presentation; each has one primary reason to change.
5. Coupling decreases because actions and presentation consume the narrow
   Board projection and optional live lookup instead of registry record shape.
6. No stable Board policy depends on the runner, shell, provider, transport, or
   persistence client implementation.
7. SQLite and process-handle effects stay at their adapters; detached mapping
   and presentation remain independently testable.
8. Added state is limited to a requesting surface's bounded detached page and
   active execution handles; neither is durable or a history mirror.
9. Five constant-count SQL reads replace inventory enumeration plus follow-up
   reads, while byte/count paging bounds work and retained memory.
10. The Board observation contract represents a real consumer fact set, and
    the private live lookup promises only optional current capabilities.
11. No compatibility requirement applies to the duplicated shells, operations,
    or process-local ID, so the implementation removes them outright.
12. The registry projection, normalized durable-like fields, both old shells,
    and their mechanism-coupled tests were removed.
13. Expected query failures stay request-local and visible; missing live handles
    reject only the requested control; unexpected errors surface normally.
14. Owner-level SQL/service and runner tests change narrowly, while one public
    graphical test proves composition through supported interfaces.
