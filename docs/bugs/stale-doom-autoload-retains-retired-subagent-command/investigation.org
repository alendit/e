#+title: Stale Doom Autoload Retains Retired Subagent Command Investigation
#+startup: overview

* Conclusion

The restarted Emacs was using the current Feature 82 runtime, but Doom's
generated Straight package metadata was stale.  Its installed =e-autoloads.el=
still declared =e-subagents-list-buffer= as an interactive autoload, so command
completion listed the retired command even though its source file had been
removed.

This was an acceptance and current-configuration test gap.  Feature 82 removed
the old public shell from the checkout, but the required cold-start gate did
not verify that the installed local-package inventory and generated autoloads
matched the checkout.  The active Emacs 31.1 package and profile metadata have
now been regenerated, and the cold-start gate covers the visible command
registration that exposed the drift.

* Evidence

** Live process

- The GUI Emacs process started at 2026-09-15 10:07:25, after the Feature 82
  implementation commits.  The result is therefore not explained by an Emacs
  process that predates the feature.
- A bounded live probe reported =e-subagents-list-buffer= as function-bound
  with no function file.  This is the shape of an unloaded autoload.
- =e-subagents-shell-refresh= was not function-bound.  The retired shell was
  not loaded wholesale.
- =e-board-activity-list-buffer= was function-bound from the current checkout's
  =lisp/shells/e-board-activity-shell.elc=.  The replacement shell was loaded.

** Checkout and installed package metadata

- The checkout contains no production definition or reference for
  =e-subagents-list-buffer=; =lisp/shells/e-subagents-shell.el= was removed by
  Feature 82.
- The active Emacs 31.1 Straight build and the older Emacs 30.2 build both
  contained an interactive autoload for =e-subagents-list-buffer= from
  =e-subagents-shell.el=.
- Both build directories retained an =e-subagents-shell.el= symlink whose
  checkout target no longer existed, and neither had an
  =e-board-activity-shell.el= entry.
- The inactive Emacs 30.2 native compilation cache also retained an August
  =e-subagents-shell-*.eln= artifact.

These facts give the observed request path:

1. Feature 82 removes the old shell source and adds the Board Activity shell.
2. Doom's Straight build directory and generated autoload table are not
   regenerated.
3. Restart loads the stale generated autoload table.
4. Emacs registers =e-subagents-list-buffer= as an interactive command without
   loading its deleted module.
5. Command completion lists the retired command.  Invoking it would then try to
   load the missing =e-subagents-shell= module.

** Why validation passed

- =e2e/e-e2e-bootstrap.el= first verifies that normal user startup loaded =e=
  from this checkout, then explicitly prepends the checkout and its Lisp
  subdirectories to =load-path=.
- =e2e/e-current-config-e2e-test.el= checks startup, runtime readiness, the
  default harness, configured projects, and the Slack layer.  It has no
  assertion about the installed Straight file inventory or retired autoloads.
- =test/e-test.el= generates a fresh temporary autoload file from the current
  source tree.  That proves the source autoload declarations, not the installed
  Doom-generated autoload table.

The current-config gate therefore proves that the configured runtime can load
the checkout, but not that Doom's generated package metadata reflects the
checkout's additions and removals.

* Fix

- Rebuild only the out-of-tree Straight package named =e=.  A normal Doom sync
  is insufficient because Doom deliberately skips modification checks for an
  out-of-tree package.
- Run =doom sync -U= after that rebuild so the generated profile embeds the new
  package autoload table without updating unrelated packages.
- Capture command registration in =e2e/e-e2e-bootstrap.el= before the test
  bootstrap adds checkout paths.
- Require the real current-configuration test to observe
  =e-board-activity-list-buffer= as a command and the retired subagent-list
  command as absent.
- Extend the source autoload test to require the Board Activity command and
  reject the retired command from freshly generated autoloads.

No production compatibility cleanup was added.  The package does not retain a
legacy symbol merely to compensate for stale generated state.

The active Emacs 31.1 build now contains =e-board-activity-shell.el= and its
autoload, and contains neither the retired shell link nor its autoload.  The
generated Doom 31.1 profile likewise contains only the Board Activity command.
The already-running GUI Emacs was not restarted, so it retains its startup
command table until the user next restarts it.

* Validation

- Before the installation repair, the new real-current-config assertion failed:
  5 expected and 1 unexpected out of 6 tests.
- After the scoped package rebuild and =doom sync -U=, the same private
  current-configuration cold start passed 6 of 6 tests.
- =eldev test -f test/e-test.el=: 17 expected, 0 unexpected.
- The focused Feature 82 removal and shell-control gate passed 1 of 1 tests.
- =eldev compile= completed successfully.
- =git diff --check= passed.
