#+title: Active OpenAI HTTP Stream Timeout Investigation
#+startup: overview

* Evidence

The affected persistent session is
=20260817T082401-fe31b7df9cd8=.  Its activity journal records repeated
Engineering AI Model Gateway HTTP Responses attempts for the same turn.  Each
failed after approximately 179.87 seconds and advertised =timeout-seconds= 180;
the provider did not report a terminal result.

The reproduction after restarting Emacs rules out the old process simply
retaining pre-fix Lisp.  Its =continue= prompt produced request
=01M0823WPGHMEN923ERV3H7GX8= with =gpt-5.6-sol=, high reasoning effort, 145
input messages, 16 tools, and a 972,399-byte serialized body.  The journal held
hundreds of retained messages and activity events.  Grimoire therefore matters
as the source of the large daily-session shape, but the inspected recent
Grimoire changes were test-only and provide no evidence of a runtime regression
there.

The source-adjacent OpenAI bytecode was newer than its source, so stale
bytecode was not the explanation.  The HTTP adapter received no observable
response-buffer progress before its timer fired.  A gateway may legitimately
buffer a long-reasoning response, which means a local idle timer cannot tell a
healthy buffered request from a stalled one.

A bounded =emacsclient= probe also timed out.  A read-only process sample found
substantial main-thread time in redisplay, mode-line evaluation, and garbage
collection.  That presentation pressure is real but separate: the evidence
does not establish that it prevented network progress, and this change does not
claim to fix it.  The running Emacs was not reloaded or mutated.

* Why the first E2E missed the recurrence

The first live regression selected the configured =:chat-default= harness, but
then used a fresh tiny session, forced low reasoning, waited for the real
provider to finish, held its completed callback, and manually inserted SSE
comments into the response buffer.  It proved that direct buffer insertions
re-armed the timer.  It did not prove that real network chunks do so, and it
could not reproduce a buffered high-reasoning request with Grimoire-sized
retained history.  The test encoded the proposed mechanism instead of the
reported behavior.

* Resolution

=e-openai-request-timeout-seconds= now defaults to nil.  OpenAI-like HTTP
requests therefore have no implicit local deadline that can kill a buffered,
healthy reasoning request.  Reload migration changes the old uncustomized
180-second value to nil while preserving explicit Custom, saved, or theme
overrides.

An explicit numeric timeout remains supported for providers that guarantee
observable progress.  The earlier response-buffer hook remains in place, and a
focused localhost chunked-HTTP test now drives the real =url.el= process-filter
path to prove that actual response chunks re-arm that opt-in idle timeout.
Completion, cancellation, and timeout still converge on the existing
one-settlement cleanup path.

* Corrected live coverage

The opt-in credentialed suite uses whichever =:chat-default= harness
=E_E2E_CONFIG= registers and no longer substitutes a fake transport or changes
its reasoning effort.  One test crosses the real provider path and verifies
that the actual HTTP request starts with no local deadline.  A second test seeds
144 inert historical messages, adds the prompt as message 145, reaches at least
900 KB, and requires that same configured harness and real provider to complete.

The live suite has two CI fences: =Eldev= excludes it whenever =CI= is present,
even if =E_E2E= is set, and its runtime gate skips when loaded directly under
=CI=.  Local execution still requires explicit =E_E2E= and =E_E2E_CONFIG=
opt-ins.

* Architecture self-check

1. This slice stops the reproducible retry loop without requiring a provider to
   expose progress that it may buffer, so stopping here improves the runtime.
2. It moves toward provider-owned transport policy behind the generic harness:
   the HTTP adapter exposes an optional timeout without imposing one globally.
3. Gateway buffering is variable and uncertain, so the decision remains a
   reversible provider setting.  The stable default models only what is known:
   no safe local deadline exists without a progress guarantee.
4. The OpenAI adapter owns the behavior because it owns this transport and its
   timeout; the harness only documents the backend-neutral policy.
5. No public interface widens and no new coupling is added.  The live tests
   consume the existing configured default-harness contract.
6. Dependencies still point from harness orchestration toward the provider
   adapter contract; core code does not depend on =url.el= details.
7. Network observation and timer effects remain inside the adapter boundary.
8. No durable state is added.  The default is configuration; explicit timeout
   timer and response hook state remain scoped to one request buffer.
9. Disabling the implicit timer removes per-request timer work.  An explicit
   timeout retains one cancel/create operation per received chunk.
10. No abstraction is introduced.  HTTP and WebSocket retain distinct timeout
    semantics because their observable progress contracts differ.
11. Explicit user timeout values remain compatible.  Only the unsafe
    uncustomized legacy default migrates.
12. The former implicit 180-second default is removed; the opt-in timeout path
    remains because it is a real provider-specific capability.
13. Expected explicit timeout and cancellation use existing settlement paths;
    unexpected callback and network errors still surface.
14. Unit tests prove default migration and real chunk handling independently.
    Live tests prove the configured default harness and reported request shape;
    unrelated test fixtures need no rewrites.
