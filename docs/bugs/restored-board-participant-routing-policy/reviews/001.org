* Findings

** P1 F001 — JSON replay changes admitted selector attribute values

Requirement: =R1-SCHEMA=, =R1-REPLAY=, and therefore =R2-RESTART= require the
same routing meaning before and after restart.

Observed fact:

- The validator deliberately accepts non-keyword symbols as selector data at
  =lisp/core/e-session.el:1885-1896=, including the symbol-valued attribute
  fixture at =test/e-session-test.el:151-160=.
- Replay normalization restores known kind and tag fields, but does not restore
  nested =:attributes= values at =lisp/core/e-session.el:1998-2036=.
- The board matcher compares attribute values with exact =equal= at
  =lisp/core/e-board.el:1870-1879=.
- A persistent-store probe at the reviewed revision produced
  =(:before (:marker car) :after (:marker "car"))=.

Consequence: a selector admitted and effective before persistence can stop
matching after JSON reopen, or collide with a separately meaningful string.
The passing persistence test uses only kind/tags and cannot detect that semantic
change.

Minimal remediation: define one reversible durable representation for admitted
attribute atoms, preserving the symbol/string distinction through JSONL,
index, checkpoint, and replay.  If symbols are not part of the real contract,
reject them before first persistence and remove the test that declares them
valid; do not make symbol and string values loosely equal in the matcher.

Acceptance evidence: route otherwise identical messages whose marker values are
=car= and ="car"= before and after persistent reopen and checkpoint rewrite;
prove each selector continues to select only its original value.  Include
nested list/vector/plist attribute values and caller-mutation detachment.

** P1 F002 — Sibling terminal activity can mutate the selected turn through a shared causal id

Requirement: =S1-TERMINAL= allows sibling activity to be visible but forbids it
from settling or changing selected-owned presentation state.  =S2-INTENT=
requires presentation and selected execution state to remain coherent.

Observed fact:

- Service projection intentionally maps output/activity back to the causal
  board input at =lisp/core/e-chat-service.el:316-327,343-352=.  Selected and
  sibling private turns caused by one input can therefore share the same shell
  =turn-id=.
- The sibling terminal renderer says it is non-settling, but still sets the
  selected record's end time, settles its open thought, and records failure at
  =lisp/shells/chat/e-chat.el:6441-6459=.
- Replayed activity also records =turn-finished= without an ownership gate at
  =lisp/shells/chat/e-chat.el:6348-6371=.  The service state reducer clears an
  equal active id without checking selected ownership at
  =lisp/core/e-chat-service.el:1207-1220=.
- Cancellation replay is unreachable: the terminal selector admits only
  =turn-failed= at =lisp/shells/chat/e-chat.el:8496-8502= although its consumer
  contains a cancellation branch at lines 8519-8524.
- A direct same-id probe left progress and global status running but changed
  the selected record to =:ended-at 2=, its provider round to =:status failed=,
  its Thought row to =failed=, and its failure text to the sibling error.
- The focused sibling test uses =selected-turn=, =sibling-failed=, and
  =sibling-cancelled= as distinct ids at =test/e-chat-test.el:6157-6209=.  The
  composed test's sibling output has no causal delivery/reply link at lines
  6385-6401, so it also misses the incident identity join.

Consequence: the UI can simultaneously show the selected turn as running and
its thought as failed/ended by a sibling.  Reopen omits no-output cancellation,
and a state snapshot can hide a genuinely active selected turn.  This is the
same semantic shape as the reported settlement incident even though the global
composer gate itself now remains selected-owned.

Minimal remediation: gate every selected turn-record and state-reducer mutation
on selected ownership, not only global progress/status/composer changes.  Render
sibling terminal rows without reusing or mutating the selected record; use a
board-message/subject/source identity if a row identity is needed.  Include
=turn-cancelled= in terminal replay and render selected cancellation with its
own semantics.

Acceptance evidence: through real board delivery, cause selected and sibling
private turns from the same input, then cover sibling success, failure,
cancellation, and empty output while the selected participant remains active.
Assert selected record/Thought/progress/status/composer and =submit/steer=
independently, then checkpoint/reopen and repeat failure/cancellation visibility
and non-mutation.  Use semantic fields rather than whole internal plists.

** P1 F003 — Legacy admission does not implement the accepted fail-closed boundary

Requirement: =COMPAT= permits main defaults only for the canonical roleless
root and owner records, rejects implicit participant restoration without a
policy, and permits an explicit caller-supplied complete legacy upgrade.

Observed fact:

- =e-chat-service--session-routing-policy= signals immediately for a
  participant-role record without policy at
  =lisp/core/e-chat-service.el:683-702=.  =e-chat-service-open-board= calls it
  before considering explicit arguments at lines 856-879, so the promised
  explicit upgrade is impossible.  The probe returned
  =(:explicit-upgrade e-session-error :policy nil)=.
- The canonical =chat:<session-id>= check exists only in root catalog filtering
  at =lisp/core/e-chat-service.el:1171-1188=.  Binding any other roleless board
  association falls through to generic =main= selectors at lines 782-822.  A
  noncanonical roleless probe returned
  =(:policy nil :default-tags (main) :default-to nil)=.
- If a policy already exists, =open-board= silently ignores supplied conflicting
  routing arguments at lines 863 and 880-887.

Consequence: a legacy private participant cannot use the only accepted upgrade
route, while an ambiguous noncanonical legacy record can be silently widened to
main routing.  Callers also cannot tell that requested overrides were ignored.

Minimal remediation: make admission modes explicit before binding: use the
durable complete policy when present and reject conflicting override arguments;
allow a complete validated caller policy to upgrade a missing-policy legacy
record; apply main defaults only to a canonical roleless root/owner; fail closed
for every other missing-policy association.  Persist an admitted upgrade once,
then attach from that persisted value.

Acceptance evidence: cover canonical roleless root and owner, noncanonical
roleless state, participant-role implicit restore, participant-role explicit
complete upgrade, incomplete upgrade, and conflicts with an existing policy.
Assert association and registry/binding mutation as well as the returned error.

** P2 F004 — Expected participant-creation failure leaves an orphan root session

Requirement: =ATOMIC= requires invalid/conflicting admission to fail before
session, association, or attachment becomes externally visible.

Observed fact:

- =e-chat-service-create-participant= creates the session first at
  =lisp/core/e-chat-service.el:902-907=, then resolves the board and validates the
  routing policy at lines 908-917, persists at lines 918-920, and attaches at
  lines 921-928.
- Invalid selector input therefore leaves a session with no board association.
  =e-chat-service--root-session-p= treats an association-free session as a root
  at =lisp/core/e-chat-service.el:1171-1183=.
- The direct invalid-policy probe returned
  =(:error e-session-error :session-exists t :roots ("orphan" "root"))=.
- Implicit restore has the correct relative order: policy validation occurs at
  =lisp/core/e-chat-service.el:785-788= before a missing board is created at
  lines 793-812.

Consequence: a rejected private-participant request pollutes the chat catalog
with a false top-level session and may reserve the requested session id.

Minimal remediation: resolve the board, participant identity, complete policy,
and expected admission conflicts before creating or persisting the session.
Keep the application-service operation atomic for expected failures; if a later
owned step can still fail after mutation, provide a narrow rollback owned by
the same service rather than swallowing the error.

Acceptance evidence: invalid board, invalid selector, duplicate session id,
duplicate participant id, persistence rejection, and attachment rejection leave
no new session, root-catalog row, association, registry participant, binding, or
subscription.  Successful creation must still persist before it is exposed as
restorable.

** P2 F005 — “Bounded” routing policy has no domain bound

Requirement: =R1-SCHEMA= explicitly calls selectors bounded declarative data.

Observed fact: =e-session--board-routing-json-value-p= rejects cycles but walks
arbitrary finite lists/vectors at =lisp/core/e-session.el:1885-1927=, and the
validity check calls =json-encode= without a prior node or byte ceiling at lines
1929-1934.  Policy validation at lines 1970-1996 adds no string, collection,
node, or encoded-byte limit.  Transport command budgets are not a domain policy
bound and do not protect the in-memory store or pre-encoding work.

Consequence: caller-controlled routing data can impose unbounded validation,
encoding, index, checkpoint, and replay work.  The architecture self-check's
bounded-cost claim is not established.

Minimal remediation: choose one measured stable policy ceiling and enforce
structural and canonical UTF-8/encoded-byte bounds before persistence or
attachment.  Bound strings and collections before full JSON encoding.  Reuse a
domain-owned board/session budget only if its semantics match this value.

Acceptance evidence: exact boundary, one-byte/one-node-over, deeply nested,
large-string, and large-collection tests must prove rejection before mutation
in both in-memory and persistent paths; a representative private policy must
remain comfortably below the limit.

** P3 F006 — The shell's synthetic-event compatibility path fails open for board-shaped events

Requirement: =S1-TERMINAL= needs selected ownership on every board projection;
the historical fallback is only for direct synthetic shell events.

Observed fact: every current service branch derives the top-level ownership
fact from the attached participant at
=lisp/core/e-chat-service.el:337-369= and copies it into projected messages at
lines 373-417.  However, =e-chat--event-selected-participant-p= and the message
equivalent return true for any missing key at
=lisp/shells/chat/e-chat.el:8136-8150=; they do not distinguish a keyless direct
event from a malformed board-shaped projection.

Consequence: one future or malformed board projection that omits the marker
regains the original fail-open settlement behavior.  Current production
projections are complete, so this is a boundary defect rather than evidence of
another current delivery path.

Minimal remediation: preserve historical true only for events with no board
identity.  A board-shaped event/message with =:board-id=, =:board-seq=, or
=:message-id= but no explicit ownership fact must be non-settling or signal at
the projection boundary.

Acceptance evidence: a direct synthetic non-board event retains legacy
rendering; board-shaped events with explicit true, explicit nil, and missing
ownership respectively settle, remain observed-only, and fail closed.

* Architecture review

The main ownership direction is correct: session owns durable representation,
chat service owns application admission/projection, registry owns board routing,
and the shell owns presentation.  The policy has the required restart lifetime;
selected ownership is correctly derived process-local state.  No Grimoire,
provider, or shell-local routing policy was introduced.

F004 is the material side-effect-placement exception: session creation occurs
before service admission has a valid aggregate.  F002 is the material identity
exception: a presentation convenience id is reused as if it were selected-turn
ownership.  F006 leaves a fail-open compatibility branch broader than its
synthetic-event purpose.  Closing these findings reduces coupling and removes
partial state; it does not require a board-wide settlement abstraction or a new
durable record.

Performance remains ordinary-path constant apart from policy validation and
persistence, but F005 means the claimed worst-case bound is absent.  Branch
selection does not independently vary board routing policy, and checkpoint
records retain the whole association; no separate routing ledger is present.
