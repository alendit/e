#+title: Investigation: Canvas New Session Loads an Unresumable Legacy Session
#+startup: overview

* Status

Closed.  The failure was caused by eager historical-session hydration in the
generic canvas shell.  Discovery is now catalog-only, non-Org buffers do not
resume historical reverse associations, and Org Canvas owns best-effort
recovery for its explicit document/session reference.  The strict checkpoint
guard remains unchanged.

* Live evidence

The supported read-only probes completed successfully.  The selected buffer
was =02-webassembly-and-clojure.md= in =markdown-mode=, with no chat session id,
status, or harness attached.  The buffer itself was therefore healthy and the
failure occurred before a new canvas session was attached.

The loaded definitions for =e-canvas-attach-current-buffer= and
=e-session--read-checkpoint= came from the installed =e= build.  No raw Emacs
evaluation or live reload was performed.

* Persisted-session evidence

The reported session =20260803T080924-d408dbc0c08b= remains in =index.json= as
an unloaded root session named =Untitled 2026-08-03T08:09:24Z=.  Its 497,665
byte JSONL journal exists, but its checkpoint file does not.  The index entry
contains no canvas attachment metadata for the current Markdown buffer.

Other current index entries demonstrate that =:context-references=, including
=chat-session= canvas attachment metadata, are already available in the
transcript-free session catalog.  Determining whether a buffer matches an
indexed canvas therefore does not require loading session journals.

* Cause

=e-canvas-open-for-current-buffer= first calls
=e-canvas--buffer-canvas-session= so an already-attached canvas can reveal its
existing chat.  That helper iterates every value returned by
=e-harness-session-list=.  For each session it calls
=e-canvas--session-canvas-attachment=, which calls
=e-chat-session-attachments=.

=e-chat-session-attachments= reads live context references through
=e-session-context-references=.  For an unloaded persistent session,
=e-session--get-live= consequently calls =e-session-load-session=.  Loading the
unrelated August 3 entry reaches =e-session--read-checkpoint= and raises
=e-session-checkpoint-missing= before the scan can continue or create the new
session.

The resume check is intentional.  Existing coverage explicitly requires
normal session loading to reject checkpoint-less journals rather than silently
performing an unbounded full replay.  Weakening that persistence boundary would
turn this presentation lookup bug into a runtime safety regression.

* Fix

Session metadata now has a transcript-free context-reference reader, and the
chat-session capability exposes attachment normalization over that metadata.
Generic Canvas uses those catalog values only for already-loaded sessions.
Unloaded or malformed historical reverse associations are nonmatches because a
generic document owns no durable session reference.  The attachment picker
also always offers =[New e session]=, even when historical sessions exist.

Org Canvas session listing, file matching, and buffer recovery now operate on
root catalog entries without hydrating transcripts.  A missing or mismatched
explicit document reference still prompts synchronously.  When a cataloged
session fails during asynchronous checkpoint or journal loading, =e-chat-open=
reports the original failure through a narrow load-error callback after
rendering it.

The follow-up design makes Org Canvas a substitutable specialization of Canvas
rather than a parallel resume implementation.  =e-canvas-kind= is the common
contract, and =e-canvas-open-buffer= owns catalog resolution, reference
validation, replacement prompts, session creation, binding order, asynchronous
load recovery, stale-reference protection, and UI-work scheduling.  The Org
kind supplies only its real variations: explicit reference lookup, Org metadata
and mode binding, project-layer preparation, workspace affinity, and its
presentation.  The base lifecycle contains no Org conditionals or type tests.
Declining replacement preserves both the failed transcript and the original
reference for diagnosis.

Checkpoint validation and the explicit offline migration rule were not
weakened.  Storage continues to surface unavailable or corrupt sessions; only
the document-owning presentation shell decides whether replacement is valid.

* Verification

- The combined session, chat-session, chat, generic canvas, and Org Canvas gate
  passed 538 expected tests, one skipped optional Markdown-rendering test, and
  zero unexpected results out of 539 tests.
- The full generic Canvas file passed 9 of 9 tests.
- The full Org Canvas file passed 73 of 73 tests.
- Project compilation completed without warnings or errors.
- Focused regressions prove that unloaded and malformed unrelated generic
  sessions are not hydrated, that the attach picker can create a new session,
  that checkpoint setup failures reach the chat recovery callback, and that
  accepting the Org replacement prompt installs a new session reference while
  a delayed stale failure cannot replace a newer one.  A substitution test
  opens the Org kind directly through the unchanged base Canvas lifecycle.
- The running Emacs and persisted session files were left unchanged.

* Architecture self-check

1. The package is independently useful: unrelated historical state can no
   longer block new canvases, and explicit Org references have a recovery path.
2. It moves toward one catalog-first Canvas application service with
   substitutable specializations, asynchronous hydration, and reference-owned
   recovery policy.
3. Stable facts--indexed references and strict resume validation--are modeled
   directly.  The replace-or-keep choice remains local and reversible.
4. Core session owns metadata shape, chat-session owns attachment semantics,
   chat presentation owns transcript load settlement, base Canvas owns the
   canvas lifecycle, and Org Canvas owns only its Org-specific policy hooks.
5. Coupling is reduced because Org Canvas no longer coordinates chat opening or
   recovery itself, and base Canvas has no dependency on the Org specialization.
6. Dependencies still point from shells to capability/session contracts; core
   does not depend on Canvas or Org Canvas.
7. Catalog inspection is side-effect free.  Session creation and reference
   replacement remain at the existing shell/application boundary, and delayed
   recovery UI enters through the serialized UI-work boundary.
8. No new durable state was added.  Replacement mutates the existing
   buffer-owned reference only after explicit consent.
9. Generic discovery changes from possible N-session replay to a linear scan of
   bounded catalog metadata.  Org discovery likewise avoids transcript I/O.
10. The metadata, load callback, and =e-canvas-kind= contracts are semantically
    real.  Every kind accepts the same lifecycle inputs and preserves the same
    create, resume, prompt, recovery, and stale-callback postconditions.
11. Existing checkpoint compatibility policy is unchanged; no implicit legacy
    replay or migration path was added.
12. Eager transcript hydration and the duplicate Org resume/recovery lifecycle
    were removed.
13. Unrelated malformed generic metadata becomes a nonmatch.  Referenced Org
    failures remain visible and require a user decision before replacement.
14. Core behavior is covered separately at metadata, load callback, generic
    discovery, base lifecycle, substitution, and Org policy boundaries, so a
    specialization can be tested through the same Canvas contract.
