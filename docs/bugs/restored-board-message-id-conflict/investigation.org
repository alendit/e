#+title: Investigation: restored board message id conflict
#+startup: overview

* Source inspected

- =e-chat-service--bind-session= reconstructs a board and imports its durable
  message envelopes before accepting new input.
- =e-board-import-message= preserved imported =msg_N= identities but did not
  advance the process-local fallback identity sequence.
- A later post could therefore allocate an identity already present in the
  restored board and fail in =e-board--make-message=.

* Conclusion

Replay restored the message table but not the state of the fallback identity
allocator.
The next generated message identity could collide with imported history.

* Fix applied

- Reserve each successfully imported numeric fallback message identity by
  advancing the process-local sequence to at least its suffix.
- Leave injected identity functions responsible for their own identity domain.
- Add a pure board regression proving that importing =msg_7= makes the next
  fallback message =msg_8=.
