* Scope and ownership

This package establishes =TEST-C01= without changing Feature 87's SQLite
failure model.  Test-environment capability assertions and fresh-process owner
checks live in =test/e-test-environment-support.el=.  Eldev owns deterministic
test-only dependencies.  Individual owner tests retain their exact semantic
assertions.  The production changes remain within presentation owners: the
chat transcript owns the URL property consumed by chat link commands, the
overview and composer own their optional Evil lifecycle, and Org Canvas owns
its buffer-local Evil prompt bindings.

The supported deterministic environment provides loopback bind/connect,
=node=, =python3=, =tail=, the existing local org-annotate integration, and the
test-only Evil and markdown-mode packages.  Missing capabilities fail
actionably; they are not converted to passing or skipped results.  Credentialed
live-provider E2E remains a separate opt-in compatibility tier and is not part
of =S-FULL-SOURCE-GREEN=.

* Markdown finding

Installing the declared =markdown-mode= dependency made the retained test run
against current package behavior.  The mode supplied semantic faces but did
not preserve the private =e-chat-link-url= property.  Because chat navigation
uses that property rather than markdown-mode internals, the smallest correction
is a transcript-local pass over Markdown links after fontification.  Focused
tests require the visible label and exact target on both the current-mode and
fallback paths.

Running real Evil on every pass exposed two adjacent optional-integration
defects.  Overview mode called =evil-local-mode -1= from the same mode hook
that Evil runs while disabling itself, causing unbounded recursion.  A
buffer-local reentrancy guard now makes that operation finite.  Composer input
focus called =evil-insert-state= merely because Evil was loaded; it now does so
only when local Evil is enabled.  Real-Evil tests prove overview creation,
enabled composer transition, deliberately disabled composer behavior, and
cleanup of process-global test state.

The same retained integration also showed that Org Canvas attempted to install
Evil-local prompt keys in buffers where Evil had no local state maps.  It now
installs and removes those keys only while buffer-local Evil is enabled;
focused tests prove both the active binding/cleanup path and the inert path.

* Architecture self-check

1. The package is useful alone because the ordinary suite becomes decisive.
2. It moves toward a zero-exception deterministic repository gate.
3. Environment capabilities are explicit and reversible test configuration;
   no speculative runtime abstraction was added.
4. Eldev owns dependencies, shared test support owns process isolation, and
   each presentation owner retains its own link or optional-Evil behavior.
5. One narrow helper reduces repeated load-order coupling, and each test file
   that needs its worker-lifecycle fixture declares that dependency directly.
6. Product owners do not depend on test support; test code depends inward on
   public or deliberately reviewed owner symbols.
7. Process and package side effects remain at the test-runner boundary.
8. No durable product state is added; child processes and test stores are
   disposable.
9. Five small child processes add bounded test cost; product rendering adds one
   bounded link scan only when markdown-mode succeeds.
10. Capability checks assert their actual requirement instead of pretending
    optional implementations substitute for missing tools.
11. Retired representation tests are removed; supported SQLite behavior stays.
12. Seven obsolete registered tests, five disabled remnants, and their
    dead-only fixtures are gone.
13. Missing capabilities and unexpected child failures surface with actionable
    output.
14. Focused owner, renderer, URL, Org, helper, and loopback tests localize each
    correction before the complete suite.
