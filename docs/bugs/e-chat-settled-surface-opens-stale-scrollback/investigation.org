#+startup: overview

* Reproduction

** Original settled-surface reproduction

The running Emacs reproduced the original report without changing live state.
The selected buffer was the dedicated composer for session
=20260803T164156-136fc3d8a0af=, while its owning transcript had:

- no active turn and no running-status bounds;
- =window-start= 21309, =window-point= 21531, and =window-end= 22070;
- =point-max= 23089 and latest final block bounds 22987--23087;
- a window-local output-follow value of =nil=.

The newest final output was entirely below the visible viewport.  A focused ERT
reproduction rendered a long settled turn before entering the chat surface.
Before the activation fix, =window-point= stayed at 1 instead of moving to
transcript =point-max= 5120.

** Restart recurrence, 2026-08-05

A bounded probe of the restarted Emacs confirmed that the selected buffer was
the dedicated composer for the current daily chat and its paired transcript was
a settled, composed surface.  By the time of the probe, a later focus boundary
had corrected the viewport, so that snapshot could not capture the opening race
itself.

Code tracing and a lifecycle-level ERT reproduction established the missed
ordering:

1. Opening an indexed session creates and displays a short =Loading
   transcript...= projection.
2. Surface activation moves the transcript window to the tail of that short
   projection and records that the window follows output.
3. The zero-delay activation callback settles.
4. Asynchronous session load completion calls =e-chat--attach-buffer=, clears
   the loading projection, and replays the long transcript.
5. No further display or focus boundary follows that replacement, so the
   window point falls to the beginning of the new projection.

The previous regression constructed the long, settled transcript first and
activated the surface second.  It proved the activation contract but could not
exercise restart ordering.

The new regression uses the real =e-chat--attach-buffer= completion path after
activation has already settled.  Before the revised fix, replacement changed
the transcript from its loading tail to =point-max= 7213 while =window-point=
fell to 1.

* Source and history inspected

- The original =e-chat--after-display-buffer= only tailed active turns and the
  selected-buffer resolver confused a dedicated composer with its transcript.
- The first architectural fix introduced an explicit
  =(TRANSCRIPT . TRANSCRIPT-WINDOW)= activation surface and removed the broad
  =window-configuration-change-hook= tail.
- The composed-surface restoration hook remains necessary for generic
  =switch-to-buffer= calls, which otherwise omit the separate input pane.
- The immediate activation plus one coalesced retry remains necessary for a
  separate, tested host window-restoration race.  More activation retries or
  focus hooks would not solve asynchronous transcript replacement.
- Full transcript replacement occurs in three presentation-owned paths:
  loaded-session attachment, older-message backfill, and explicit transcript
  rerender.  All three previously cleared and rebuilt text without preserving
  whether the old viewport physically showed its output tail.
- An initial revision reused the cached live-output follow flag for full
  replacement and broadened post-command tracking to settled transcripts.  A
  counterexample moved the paired transcript with its composer still selected:
  the stale flag remained true and replay incorrectly tailed the window.  That
  state coupling was removed.

* Design

** Activation contract retained

Presentation activation owns a concrete chat-surface value:
=(TRANSCRIPT . TRANSCRIPT-WINDOW)=.  It shows the latest output when the user
enters a chat surface.  Its single coalesced retry handles the separately tested
case where a host workspace restores an older window point after display.

Remaining within the same composed surface is not activation.  Moving between
its transcript and composer preserves deliberate scrollback.

** Projection replacement contract

Projection replacement changes the text underneath an already-visible surface
and must carry one local fact across the clear/replay boundary without
manufacturing another focus event.

Immediately before a full replacement, =e-chat= captures only visible
transcript windows whose viewport and window point are physically at the old
output tail.  After replay, it moves those same live windows to the new tail.
Windows physically showing scrollback are not forced there.  This applies
uniformly to asynchronous attach, loaded-message backfill, and explicit
rerender.

The existing window-local follow flag remains limited to changing live output,
where intent must survive incremental status movement.  Full replacement does
not consult it and settled navigation does not maintain it.  Projection uses
the physical pre-replay viewport because that is the complete fact required by
this operation.

No new timer, global hook, persisted state, or harness/session dependency was
introduced.  The prior activation machinery remains because its late host
restore regression proves a distinct responsibility.

* Design self-check for the revised fix

1. The package fixes the real restart ordering at a useful boundary and also
   makes backfill and rerender obey the same viewport contract.
2. It moves chat toward explicit presentation lifecycles: surface activation
   and transcript projection replacement have separate owners and contracts.
3. Asynchronous load timing is variable but local to attach.  Projection uses
   an immediate physical snapshot; no speculative scheduling or durable intent
   layer was added.
4. =e-chat= presentation owns the behavior because it owns transcript text,
   windows, and viewport policy.  Harness and session code remain unchanged.
5. Coupling is reduced by reusing one consumer-shaped capture/restore contract
   at each full projection boundary.
6. No dependency points from stable harness, board, session, backend, or
   persistence policy toward chat windows.
7. All window side effects remain in the presentation shell, after projection
   rendering completes.
8. No state was added.  The projection snapshot is a local list that exists
   only across one synchronous clear/replay operation.  Live-output follow
   state retains its narrower window lifetime and purpose.
9. Each full reprojection performs two bounded scans of visible transcript
   windows.  Rendering already dominates this work, and ordinary incremental
   output receives no added cost.
10. Physical output-tail position is a real substitutable viewport fact for
    monolithic and composed transcripts; neither presentation weakens its
    preconditions.
11. Restarted indexed sessions, loaded sessions, generic switching, and live
    reload remain supported.  No legacy fallback was added.
12. No new legacy code was created.  The previous broad layout hook remains
    removed; the distinct coalesced activation retry remains regression-tested.
13. Dead or repurposed windows are ignored during restore.  Unexpected replay
    and rendering errors continue to surface at their existing top boundary.
14. The restart-order test proves the real load-completion path; a second test
    proves stale live-follow state cannot override a composer-focused physical
    scrollback viewport.  Adjacent tests independently cover activation, late
    restore, backfill, reattach, rerender, and deliberate scrollback.
