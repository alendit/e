* Code findings

1. =e-bayesian-reasoning-instructions= says to emit the block in the "visible
   reply" but does not say that this means the final assistant transcript
   message only.
2. Org Canvas guidance says the document is the primary output target and that
   durable results belong there.  In combination, the model can reasonably
   treat the document edit as the visible reply.
3. Resource tools correctly preserve the content the agent asks them to write.
   Teaching them Bayesian fence syntax would mix capability policy into generic artifact mutation.
4. The turn-finished checker reads only assistant message content.  A block
   placed only in a tool argument cannot help the audit and only pollutes the
   artifact.

* Direction

Make the transcript-only rule explicit in both Bayesian and Org Canvas guidance.
Keep enforcement with the agent instead of rewriting resource-tool arguments.
Do not add Bayesian knowledge to Org Canvas write code, generic resource adapters, or a pre-tool hook.

Implementation is tracked by
=docs/feats/72-transcript-only-reasoning-blocks/plan.org=.

* Resolution

Resolved by =f21c056=, =b6e6abe=, and the simplification in =e92efdc=.

Bayesian and Org Canvas guidance now reserve reasoning blocks for the final
assistant transcript message.
Resource tools remain transparent and do not inspect or rewrite agent output.
The leaked block in feature 66 was removed with a normal edit.

Instruction tests cover the Bayesian and Org Canvas sides of the contract.
