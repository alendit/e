#+title: Archived daily resume rejects collapsed attachment metadata

* Report

Opening the archived Grimoire daily for 2026-08-07 still failed after the
earlier legacy attachment repair.  The running Emacs reported:

#+begin_example
Invalid object argument: "file:///.../daily/2026-08-07.org", "label", ...
#+end_example

The daily document opened, but its referenced chat session did not resume.

* Expected Behavior

=grimoire-daily-open= should decode every attachment representation actually
written by supported historical versions after an explicit one-off store
migration, replace the old daily canvas with the selected archived file, and
resume the chat.  The steady-state reader must accept only the canonical
attachment shape and fail loudly when migration has not run.

* Prior Gap

The first repair covered a legacy single plist and the malformed sequence seen
in the August 13 session.  It assumed the flattened pair followed an existing
canvas.  The August 7 checkpoint instead stores one object whose =uri= value
contains the URI and every remaining flattened field.  Neither the fixture nor
the compatibility reader represented that form.

The follow-up correction is architectural: historical serialization damage is
repaired offline.  It is not a permanent chat-session compatibility concern.
