#+title: Atomic e-chat Perspective Restoration Investigation
#+startup: overview

* Evidence

Bounded read-only =emacsclient= probes of the reported frame showed an atomic
transcript/composer subtree before the switch.  After the switch, the frame
contained a transcript from the previous workspace beside the selected Org
buffer, while the composer was not owned by any perspective.

The live =*Messages*= buffer recorded the primary failure and its secondary
chat-shell symptom in order:

#+begin_example
[persp-mode] Warning: Can not restore ... (error "Cannot resize window ...")
Could not create atomic e-chat composer window
#+end_example

Source inspection found three layers of derived structural state around the
atomic subtree: a transcript/composer window-pair cache, a custom composer
window parameter, and reconciliation that re-atomized, repaired, or deleted
windows during host restoration.  Separate buffer-list and perspective hooks,
a splitability predicate, and a reentrancy flag guarded that repair path.

* Root cause

The original conclusion that atomic windows were intrinsically incompatible
with =persp-mode= was incomplete.  Emacs represents an atom with the built-in
=window-atom= parameter.  =persp-mode= saves writable window state with
=window-state-get=, but Emacs only includes parameters registered with the
=writable= persistence policy.  =window-atom= was not registered, so the saved
tree silently lost the property that made its transcript/composer subtree one
structural unit.

e-chat then tried to infer and recreate the missing atom during restoration
through pair caches and repair hooks.  Those mutations raced =persp-mode='s
own reconstruction and resizing.  The resize error was primary;
=Could not create ... composer window= was the follow-on attempt to repair the
already inconsistent tree.  The durable session was never corrupt.

* Fix

- e-chat registers =(window-atom . writable)= in
  =window-persistent-parameters= before any chat surface can be saved.
- Composer creation uses =display-buffer-in-atom-window=.  Transcript and
  composer are again one native atomic surface.
- Writable =window-state-get=/=window-state-put= round trips now preserve that
  native structure directly.  =persp-mode= remains unaware of e-chat.
- The pair cache, custom composer window parameter, restoration repair hooks,
  duplicate scavenger, and re-atomization path remain removed.
- The ordinary-pair =C-x 0= and =C-x 1= implementations were removed.  Native
  structural commands and generic host wrappers operate on the atom.  e-chat
  retains only its semantic focus-cycle and external split-buffer policy.
- A narrow e-chat display-time migration replaces an already-open or persisted
  ordinary composer constituent with the native atom.  No workspace hook or
  generic component participates.

The composer-fitting reentrancy guard remains because
=fit-window-to-buffer= can synchronously invoke the window-configuration hook
that requested the fit.  It guards a direct callback cycle rather than trying
to recover an invalid structural representation.

* Regression

=e-workspace-behavior-test-chat-split-delete-survives-round-trip= uses real
=persp-mode= and proves the transcript/composer atom survives repeated workspace
switches with exact normalized geometry.  It then invokes the fixture's generic
workspace close command and proves native deletion removes the whole atom.

=e-workspace-behavior-test-chat-surface-restores-clean-target= proves switching
away from an atomic chat still restores an unrelated perspective exactly.
=e-chat-behavior-test-persp-switch-restores-focused-surface= independently
proves the atom and selected composer survive a real round trip.  Focused ERT
coverage proves writable state restoration, native deletion, splitting,
generic activation, and reload draft retention.

* Architecture self-check

1. This slice independently restores native surface behavior and reliable
   workspace round trips.
2. It moves toward presentation-owned composition using Emacs's structural
   primitive rather than shell-level emulation.
3. Writable parameter persistence was uncertain and was resolved with focused
   native and graphical evidence; no speculative boundary was added.
4. e-chat owns creation and persistence of its presentation surface;
   =persp-mode= owns generic window-state restoration.
5. Coupling is reduced by removing ordinary-pair command emulation without
   adding any chat-specific workspace integration.
6. No harness, session, provider, or capability dependency points toward the
   presentation or workspace adapter.
7. Emacs owns structural split and delete effects.  Focus, external split-buffer
   choice, fitting, and workspace admission remain at shell edges.
8. Buffer ownership lasts for the composer buffer lifetime.  Window geometry,
   selection, and activation work are ephemeral and rebuildable.  No durable
   state was added.
9. Persistence adds one small parameter per atom constituent; restoration no
   longer runs reconciliation scans or atom mutation.
10. =window-atom= is the real substitutable structural contract.
11. Existing workspace behavior is preserved; obsolete ordinary-pair command
    implementations are removed, with one explicit migration for saved pairs.
12. Removed legacy code includes both successive workarounds: repair hooks and
    shell-level delete emulation.
13. Unexpected split, delete, and host restoration errors still surface.
14. Unit tests isolate persistence and command behavior; graphical regressions
    prove real =persp-mode= transitions and exact target layout.
