** F005 — Empty nested JSON state aliases the historical null projection

Required boundary: persistent index ingress must distinguish physical JSON =null= from an empty object before Lisp representation collapse, preserve only the exact historical triple-null compatibility case, and prevent parser-private representation from escaping.

Current proof:

- =e-session--json-read-index-file= alone parses JSON null as the uninterned =e-session--index-json-null= sentinel.
- =e-session--normalize-index-json-entry= detects a present empty =:board-state= object while its parsed value is nil and replaces it with the bounded invalid marker.
- A physical null remains the sentinel until recursive normalization, so exact =board-state=null=, =board-id=null=, and =principal=null= becomes the historical no-association projection.
- Null board state with either flat mirror omitted fails the exact three-key compatibility predicate and becomes invalid.
- Non-null or otherwise malformed mirrors do not validate or repair nested state.
- Recursive normalization removes the sentinel from vectors, proper lists, keyword plists, metadata, and nested ordinary values before session construction.
- Object-shaped indexes pass through the same entry normalizer.
- JSONL and checkpoint readers retain their ordinary JSON-null behavior and their replay semantics are unchanged.
- The real =index.json= regression contains both exact triple-null and empty-object entries with identical null mirrors, proves their distinct outcomes, verifies malformed isolation, and confirms byte-for-byte index non-mutation.

Disposition: closed.

1. Yes. The package eliminates duplicate participant advertisement while preserving durable access and legacy compatibility.
2. It moves toward explicit durable ownership with one service-owned navigation policy and presentation as a consumer.
3. Owner/participant role and whole-association validation are stable. Historical role absence and triple-null projection are explicit compatibility decisions, localized and removable rather than generalized.
4. =e-session= owns persistence shape and normalization; =e-chat-service= owns chat-root policy; presentation owns only interaction and rendering.
5. Coupling is reduced. Consumers use the narrow root-catalog service instead of generic harness storage or association internals.
6. Dependency direction remains presentation to application service to session-domain persistence contracts; stable policy does not depend on UI or concrete writer details.
7. Parsing and durable writes remain at persistence boundaries. Catalog classification and presentation remain side-effect free.
8. Association role has session/board lifetime and is durably stored because ownership must survive restart and cross-store identity reuse. The JSON-null sentinel lives only during index parsing and is discarded before session construction.
9. Index normalization and catalog filtering are linear in entry count. Each association validation is bounded to at most three semantic fields.
10. Owner and participant roles are real substitutable domain values. The index adapter preserves representation faithfully without weakening downstream preconditions.
11. Canonical role-absent associations and the exact historical triple-null projection are the stated compatibility requirements. Other malformed shapes are not accepted through fallback.
12. Direct presentation access to generic root storage, per-field nested/flat repair, and null/empty conflation are removed. The remaining localized legacy paths correspond to real indexed data.
13. Invalid new writes fail before mutation. Expected malformed persisted state becomes a bounded non-root marker and is isolated; unexpected parser or runtime failures continue to surface.
14. Tests prove production ownership, persistent physical shapes, public selectors, restart paths, cross-store behavior, malformed isolation, and non-mutation through semantic assertions. A future design change would primarily affect the owning session/service tests rather than unrelated presentation suites.
