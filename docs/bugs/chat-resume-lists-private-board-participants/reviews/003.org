* Confirmed findings

** P3 F005 — Empty nested JSON state aliases the historical null projection

Classification: incomplete closure of F004.

Proof:

The accepted historical non-board index representation is:

#+begin_src json
{"board-state": null, "board-id": null, "principal": null}
#+end_src

A present empty association is:

#+begin_src json
{"board-state": {}, "board-id": null, "principal": null}
#+end_src

=e-session--json-read-file= parses with plist objects and =:null-object nil=.
An empty JSON object also becomes an empty plist, which is Lisp nil.  The two
physical inputs consequently become the identical value:

#+begin_example
(:board-state nil :board-id nil :principal nil)
#+end_example

=e-session--projected-board-association= must preserve the historical
triple-null case, so it returns nil for both.  The malformed empty association
is therefore treated as generic non-board state instead of the bounded invalid
marker.

The independent reproducer parsed both JSON objects and returned:

#+begin_example
((:id "null"  :board-state nil :board-id nil :principal nil)
 (:id "empty" :board-state nil :board-id nil :principal nil)
 nil
 nil)
#+end_example

The persisted-index regression includes =present-empty= only with non-null flat
mirrors.  Those mirrors make it distinguishable from triple-null, so the test
does not exercise this exact partition.

Owner and principled correction:

The persistence parser or index-ingress adapter must preserve enough JSON type
information to distinguish JSON null from an empty object before board
association normalization.  The historical null projection may map to absence;
a present object, including an empty object, must pass whole-shape validation
and map to the bounded invalid marker when incomplete.

Do not remove historical triple-null compatibility, infer validity from flat
mirrors, special-case a session id/title, or catch the ambiguity in a picker.
Those alternatives would either break existing indexes or move persistence
semantics into presentation.

Required regression:

Load one real =index.json= containing both exact entries above alongside a valid
owner, participant, and generic session.  Prove:

- triple-null remains generic non-board;
- empty nested object becomes the invalid marker and is not a chat root;
- neither entry affects other catalog rows;
- the index remains byte-for-byte unchanged;
- valid, legacy, partial, scalar, list, unknown-role, and extra-key partitions
  remain unchanged.

* Progress and fixed-point assessment

The current revision closes the reported Daily duplication, the Canvas bypass,
cross-store same-id ambiguity, and the previously reproduced partial/scalar
malformed-state failures.  Ownership, state lifetime, dependency direction,
public selectors, and normal persistence are substantially improved.

Fixed point is not reached because the persistence boundary cannot yet
distinguish the one accepted historical JSON-null projection from a present
empty JSON object.  This leaves one malformed physical representation silently
classified as generic non-board state and makes the investigation's
whole-shape claim too broad.

After F005 is corrected and the exact revision passes its gate, a fresh
independent Tick is required.

* Architecture self-check

1. The package is materially better than the baseline, but one malformed
   persisted shape still bypasses whole-shape validation.
2. It moves toward explicit durable board association ownership with one
   service-owned navigation policy.
3. Owner/participant role is stable.  Historical JSON null is a real
   compatibility case; empty-object handling is uncertain only because ingress
   erases their physical distinction.
4. =e-session= owns persistence shape and normalization; chat service owns role
   construction and root semantics; presentation consumes the service.
5. Presentation coupling is reduced.  F005 is a persistence representation
   issue, not a reason to add shell coupling.
6. Dependency direction is correct from presentation to service to session
   contracts.
7. Normalization and catalog reads are side-effect free.  The correction should
   remain at parse/ingress rather than adding presentation effects.
8. Association role has session/board lifetime and is the smallest durable fact
   that resolves cross-store ownership.
9. Catalog filtering is linear and association validation is constant-bounded.
   Preserving null/object type at ingress need not change that complexity.
10. Owner and participant roles are semantically real and substitutable.
    Empty-object aliasing violates the physical representation contract.
11. Canonical role-absent and historical triple-null data require compatibility.
    The compatibility path should accept only actual null, not every value that
    becomes Lisp nil.
12. No presentation fallback remains.  The remaining obsolete behavior is the
    parser-level collapse of empty object into the null compatibility case.
13. Invalid role writes fail before mutation and most malformed reads isolate
    correctly.  Empty object is still silently downgraded to absence.
14. Tests cover owner and public behavior well, but the malformed persisted
    partition must place exact null and empty-object entries with identical flat
    mirrors in the same real index fixture.
