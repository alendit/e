* Summary

The two rows are distinct durable sessions on one board, not duplicate picker
rendering.  The first is the user-facing Daily session that owns the board.  The
second is the private update participant that receives the board's sole
reconciliation continuation.

Generic root classification excluded sessions carrying subagent or task-queue
lineage, but the Daily update participant intentionally carries neither.  The
chat shell consumed that generic root catalog directly, so the private
participant appeared as another resumable chat after restart.

* Source cause

=e-session-root-p= owns generic session lineage.  It excludes durable
subagents and task-queue workers using their metadata and deliberately knows
nothing about the chat service's principal format.

=e-chat-service-root-session-list= previously delegated to that generic root
catalog without applying chat-board ownership.  The chat shell then bypassed
even that service seam and called =e-harness-root-session-list= directly in its
resume candidates, latest-session selection, and overview rendering.

=e-chat-service-create-participant= accurately describes the created session
as private execution context and persists the board id and principal.  Those
legacy facts classify the reported same-store data, but principal/session-id
equality is ambiguous when separate stores reuse an explicit session id.  The
initial fix therefore did not establish a durable cross-store role invariant.

Generic Canvas also bypassed the chat-owned catalog in its attachment picker
and existence check, leaving a second presentation route that advertised a
private participant.

* Fix

The chat service now establishes a bounded =:association-role= fact whenever it
creates a board owner or private participant.  The generic session persistence
boundary accepts only the scalar values =owner= and =participant=, projects the
complete three-field association through the journal, checkpoint, and index,
and rejects invalid roles before mutation.  Ordinary metadata updates cannot
erase the role because it lives with the board association rather than session
metadata.

An explicit role is authoritative: only =owner= is a user-facing chat root.
Canonical legacy board state has no role field and retains one localized
=chat:<session-id>= fallback, so existing indexes and journals remain readable
without a rewrite.  Explicit malformed or partial persisted state stays
non-root without mutation.

The chat and Canvas shells now consume =e-chat-service-root-session-list=
consistently for resume/switch candidates, latest-session selection,
active-session views, overview rendering, Canvas selection, and Canvas
existence checks.  Presentation no longer duplicates chat ownership policy.

Existing records are not rewritten.  New writes carry the role; old records
continue through the role-absent compatibility branch.  The catalog remains a
bounded, side-effect-free read.

The index adapter now preserves physical JSON null until entry normalization.
Only the exact historical three-key nested-null/id-null/principal-null
projection becomes no association.  A present empty nested object with the same
flat mirrors, or nested null with omitted mirror keys, is normalized to the
bounded invalid marker.  The adapter converts its private null sentinel out of
metadata and all other entry fields before constructing a session; ordinary
JSONL and checkpoint parsing are unchanged.

* Architecture self-check

1. This package removes private participants from every general chat navigation
   surface without rewriting existing data, so it is independently useful.
2. It moves toward the board model's intended separation between public board
   interaction contexts and private participant execution sessions.
3. Generic lineage and board association role are stable facts.  Physical JSON
   null versus object shape varies only at index ingress, where the distinction
   is local and removed after normalization; legacy inference stays removable.
4. Core session owns generic lineage, index parsing, and the bounded persistence
   shape; chat service owns construction and root semantics; presentation
   consumes the service catalog.
5. Coupling is reduced because the shell stops depending directly on the
   harness's generic root catalog.
6. Dependency direction remains shell to chat application service to generic
   harness/session contracts.
7. Role persistence occurs only at board association construction.  Catalog and
   presentation reads remain side-effect free.
8. The durable role has the session/board association lifetime.  The index null
   sentinel lasts only through entry normalization and cannot enter session
   state; no new durable state is added by F005.
9. Index normalization adds one linear traversal of each bounded index entry;
   catalog filtering remains linear with constant-bounded association checks.
10. The service boundary is real: every new constructor establishes one of the
    two substitutable association roles before the session is advertised.
11. Existing persisted participants need no migration.  Genuine nested absence
    permits canonical flat reconstruction, the exact historical three-key
    triple-null projection means no association, and missing mirror keys or any
    present malformed object are non-root.
12. Direct shell reads of the generic root catalog are removed.
13. Invalid role writes fail at admission.  Malformed persisted identities,
    including an empty object, stay absent from root catalogs without error
    swallowing or mutation.
14. The real index fixture distinguishes exact null from empty object and checks
    isolation/non-mutation; owner, generic index, checkpoint, and presentation
    tests remain coupled to their real contracts.
