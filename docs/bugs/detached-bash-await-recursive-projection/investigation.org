#+title: Detached Bash Await Recursive Projection Investigation
#+startup: overview

* Finding

The Bash process and its detached Work handle finished successfully.  The turn
stuck while =await= projected that Work result into model-facing data.

=e-await-tool--model-value= recognized the structured Bash result envelope,
constructed a safe envelope with the same =:tool-call-id=, =:name=, =:status=,
and =:content= discriminator keys, and passed that envelope back to itself.
=e-tools-result-p= recognized every reconstructed envelope as another structured
tool result, so projection recursed until Emacs signalled:

#+begin_example
Lisp nesting exceeds `max-lisp-eval-depth'
#+end_example

=e-work-await-set= had already marked its aggregation settled and cancelled the
timeout before it invoked the failing callback.  The exception therefore
prevented =e-work-finish= from settling the model-facing =await= Work, while the
aggregation's timeout could no longer report a failure.  No tool result or
provider continuation reached session or Board persistence.

* Test gap

The existing file-content test passed a naked =e-tools-file-content= carrier to
=await=.  It did not wrap that carrier in the structured result envelope that
real Bash Work returns.  The detached Bash test cancelled its handle and never
awaited natural process completion.

* Remediation

Project structured tool-result content once, then apply the existing bounded
inline check directly to the closed projected envelope.  Do not send the
projected envelope back through the structured-result classifier.

Regression coverage now includes both the focused structured-envelope boundary
and a naturally completed detached, file-backed Bash command observed through
the real model-facing =await= lifecycle.
