#+title: Valid Session Checkpoint Structural Budget Investigation
#+startup: overview

* Summary

The session produced a valid 46,249-byte checkpoint request, well below the
256 KiB command limit, but the pre-encoding traversal counted 4,155 Lisp nodes
against a 4,096-node default.  The request was therefore rejected before JSON
encoding or writer submission.

This is distinct from the closed multi-session checkpoint batching bug.  That
bug combined several individually valid manifests into one command.  Here one
session's independently submitted manifest exceeded the structural default.

* Live evidence

=scripts/e-live-probe chat= inspected the running Emacs without evaluating
arbitrary live state.  It reported:

- selected session =20260825T091746-7aec6ce8325c=;
- status =waiting for provider=;
- active progress turn =msg_1030=;
- a live harness and transcript buffer.

The probe completed normally, so no second live request or process-level hang
inspection was needed.

The session journal and checkpoint were copied to an isolated temporary store
and replayed with batch Emacs using current source.  The resulting one-session
checkpoint request contained:

- 329 retained board-message identities;
- 1,005 retained entry ids;
- 4,155 traversed Lisp nodes;
- 29,328 string bytes before encoding;
- 46,249 encoded bytes.

The existing checkpoint held 329 board records: 255 activity envelopes, 73
facts, and one output.  The live journal contained 4,472 activity envelopes,
73 facts, 25 inputs, and 31 outputs.  The checkpoint policy correctly bounded
that history to a recent tail plus the separately retained fact tail.

* Source path

=e-session-checkpoint-manifest= emits the compact root, board state, context
lifetime state, retained entry ids, and bounded board-message identities.
=e-session--checkpoint-board-messages= retains at most 256 recent envelopes
plus at most 256 facts, preserving order and removing overlap.

=e-session-persistence--command-within-budget-p= walks the complete Lisp value
before JSON encoding.  It rejected any command above 4,096 nodes even when the
encoded representation was far below
=e-session-persistence-command-byte-limit=.

The failed checkpoint never entered the outbox.  The batch failure path
correctly re-marked the captured session dirty.  Later persistence-relevant
mutations scheduled another debounced checkpoint, which rejected the same
still-valid manifest and displayed the repeated warning seen by the user.

* Fix

Raise the structural command default to 32,768 nodes while retaining the
existing 256 KiB string and final encoded-byte limits.  This keeps a bounded
pre-encoding traversal for structurally pathological values, while allowing
ordinary identity-rich checkpoint manifests to reach the authoritative wire
size check.

The new regression constructs the affected policy shape: 73 retained facts,
256 recent activity envelopes, and 1,100 retained path entries.  It proves the
manifest remains below the encoded-byte limit and passes the default
structural preflight.

The running Emacs was left unchanged.  Core session-persistence code requires
a full Emacs restart to use this fix; it is intentionally outside the supported
development reload seam.

* Validation

- The focused persistence suite passed: 24 tests, 0 unexpected.
- The combined session and persistence suites passed: 124 tests, 0 unexpected.
- Byte compilation of =e-session-persistence.el= with warnings as errors
  passed; the generated bytecode artifact was removed afterward.
- The affected session was copied again to an isolated store and replayed with
  current source.  Its 329 board identities and 1,005 entry ids encoded to a
  46,250-byte newline-terminated command and passed preflight.
- =git diff --check= passed.

* Architecture self-check

1. This slice restores checkpoint progress for currently valid sessions before
   the planned SQLite cutover, so it is independently useful.
2. It moves toward explicit bounded persistence commands without changing the
   long-term SQLite direction.
3. The JSONL lifetime is temporary, but its present command contract is stable.
   The uncertain storage replacement remains isolated in feature 87.
4. Session persistence owns transport preflight; session core continues to own
   resume-manifest semantics.
5. Coupling is unchanged.  The existing narrow writer-command boundary remains
   intact.
6. No stable policy gains a dependency on the Node writer or filesystem.
7. Encoding and writer filesystem effects remain outside session policy.
8. No state is added.  Only the accepted size of an already-bounded transient
   command changes.
9. Preflight may inspect more nodes for a large valid command, but the work is
   linear, bounded, and precedes an encoding operation the command already
   requires.  Ordinary commands are unchanged.
10. The structural and byte limits remain real independent guards; the former
    bounds traversal and the latter bounds the wire representation.
11. The writer protocol and durable file formats are unchanged.
12. No legacy path is introduced.  Feature 87 will remove this checkpoint
    protocol when SQLite becomes authoritative.
13. Deterministic invalid commands still fail before entering the outbox;
    transport and filesystem failures retain their existing retry behavior.
14. The focused regression proves the affected semantic checkpoint shape,
    while existing preflight tests continue to prove early rejection and batch
    cleanup independently of the chat UI.
