#+title: Test Tiers

The repository keeps deterministic tests in the normal suite and reserves
explicit opt-in for tests that call a real provider.

* Default batch tests

Run unit and deterministic integration coverage with:

#+begin_src sh
eldev test
#+end_src

The integration files under =test/= cross real harness, adapter, persistence,
tool, work, and chat-surface boundaries.  They use fake providers and require
no credentials.  Batch chat tests prove buffer/window structure and command
routing, but do not claim graphical redisplay or viewport behavior.

* Graphical behavioral tests

Run the graphical chat contracts with:

#+begin_src sh
bash e2e/run-graphical-tests.sh
#+end_src

On macOS the command starts a private Emacs daemon and uses a transparent,
off-screen, non-focusable NS frame.  It does not connect to or reload the
running Emacs and should not show a window or take focus.  To debug in a visible
native frame, set =E_GRAPHICAL_E2E_NATIVE_VISIBLE=1=.

On Linux, the runner uses the current display or automatically starts
=xvfb-run= when =DISPLAY= is unset.  A graphical frame is mandatory; the suite
never falls back to batch mode.

Set =E_GRAPHICAL_E2E_SELECTOR= to run one ERT selector.  The scenarios cover:

1. opening the chat atom focuses its composer and =C-x 0= deletes the atom;
2. short output stays near the bottom while preserving composer focus/drafts;
3. streamed output follows while pinned, stops following after user scroll,
   and follows again after the user reaches the tail;
4. a real =persp-mode= switch round trip restores the atom and composer focus;
5. the focused composer shows model/context fill and updates from settled
   provider usage after a turn.

* Live provider E2E

The credentialed suite exercises the runtime against a real provider API and
is not part of normal tests or CI:

#+begin_src sh
E_E2E=1 eldev test -f e2e/e-live-e2e-test.el
#+end_src

The default provider is the ChatGPT-backed Codex profile using the normal Codex
auth file.  To use a token-auth OpenAI Responses profile instead:

#+begin_src sh
E_E2E=1 E_E2E_PROVIDER=openai E_E2E_OPENAI_API_KEY="$OPENAI_API_KEY" eldev test -f e2e/e-live-e2e-test.el
#+end_src

Useful environment variables:

- =E_E2E_PROVIDER=: =codex= or =openai=; defaults to =codex=.
- =E_E2E_MODEL=: model override for live requests.
- =E_E2E_OPENAI_API_KEY=: bearer token for =E_E2E_PROVIDER=openai=.
- =E_E2E_OPENAI_BASE_URL=: OpenAI-compatible base URL.
- =E_E2E_TIMEOUT_SECONDS=: provider timeout override; defaults to =240=.

* Development bytecode smoke test

The stale source-adjacent bytecode check is an explicit checkout diagnostic,
not a normal package test:

#+begin_src sh
E_DEV_E2E=1 eldev test -f e2e/e-dev-bytecode-e2e-test.el
#+end_src
