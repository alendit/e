#+title: Test Tiers

The repository keeps deterministic tests in the normal suite and reserves
explicit opt-in for tests that call a real provider.

* Default batch tests

Run unit and deterministic integration coverage with:

#+begin_src sh
eldev test
#+end_src

The integration files under =test/= cross real harness, adapter, persistence,
tool, work, and chat-surface boundaries.  They use fake providers and require
no credentials.  Batch chat tests prove buffer/window structure and command
routing, but do not claim graphical redisplay or viewport behavior.

* Graphical behavioral tests

Run the graphical chat contracts with:

#+begin_src sh
bash e2e/run-graphical-tests.sh
#+end_src

On macOS the command starts a private Emacs daemon and uses a transparent,
off-screen, non-focusable NS frame.  It does not connect to or reload the
running Emacs and should not show a window or take focus.  To debug in a visible
native frame, set =E_GRAPHICAL_E2E_NATIVE_VISIBLE=1=.

On Linux, the runner uses the current display or automatically starts
=xvfb-run= when =DISPLAY= is unset.  A graphical frame is mandatory; the suite
never falls back to batch mode.

The default is a hermetic Eldev-prepared Emacs.  To run the same graphical
matrix after this machine's normal Emacs configuration has loaded, use:

#+begin_src sh
E_E2E_EMACS_CONFIG=current bash e2e/run-graphical-tests.sh
#+end_src

This starts another private Emacs process; it does not connect to or reload the
running Emacs.  Current mode verifies that normal startup loaded =e= from this
checkout before adding test-only paths or dependencies.  Because it really
loads the user configuration, it retains normal startup filesystem effects
such as cache updates and configured project-local byte compilation.

If Emacs cannot discover the intended configuration through its normal startup
rules, set =E_E2E_EMACS_INIT_DIRECTORY= to the directory passed to Emacs'
=--init-directory= option.  This override is valid only in current mode.

Set =E_GRAPHICAL_E2E_SELECTOR= to run one ERT selector.  The scenarios cover:

1. opening the chat pair focuses its composer and =C-x 0= deletes the pair;
2. short output stays near the bottom while preserving composer focus/drafts;
3. streamed output follows while pinned, stops following after user scroll,
   and follows again after the user reaches the tail;
4. a real =persp-mode= switch round trip restores the pair and composer focus;
5. the focused composer shows model/context fill and updates from settled
   provider usage after a turn.

** Screenshot traces

Set =E_GRAPHICAL_E2E_SCREENSHOT_DIR= to retain ordered screenshots and exact
window-state sidecars while a selected graphical scenario runs:

#+begin_src sh
E_GRAPHICAL_E2E_SCREENSHOT_DIR=/tmp/e-chat-shots \
E_GRAPHICAL_E2E_SELECTOR=focused-composer \
bash e2e/run-graphical-tests.sh
#+end_src

The standard key-input, provider-event, and provider-finish helpers capture
before/after pairs.  Successful waits capture their settled state; timeouts
capture the failing state before test cleanup.  Each capture always writes an
=.svg= and matching =.state.el= file.  When =rsvg-convert= is available it also
writes a =.png= suitable for image inspection after Emacs finishes, so image
conversion cannot change UI timing.

Tests can add a named checkpoint with
=(e-graphical-test-capture-state "after-open")= or wrap an arbitrary action
with =e-graphical-test-capture-transition=.  These helpers render the actual
test frame's window geometry, visible text, mode lines, selected window, and
viewport positions without using or focusing the desktop.

* Current configuration compatibility E2E

Run the opt-in non-provider compatibility checks with:

#+begin_src sh
bash e2e/run-current-config-tests.sh
#+end_src

The runner uses the same =E_E2E_EMACS_CONFIG=current= policy as the graphical
mode and starts a private named daemon through normal user initialization.  It
checks that the configuration loads the ready =e= runtime from this checkout,
can construct its configured default harness without sending a request, and
can integrate each configured default project through project-local policy.  It
also opens a first file through the host's startup hooks while loading a
test-owned copy of the configured Recentf cache.  This catches malformed or
incompatible persisted startup state without rewriting the user's cache.  The
suite accepts the same optional =E_E2E_EMACS_INIT_DIRECTORY= override.

* Live provider E2E

The credentialed suite exercises the runtime against a real provider API and
is not part of normal tests and explicitly skips whenever =CI= is set:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-openai-codex.el \
eldev test -f e2e/e-live-e2e-test.el
#+end_src

The Codex sample uses the normal Codex auth file and sends no project-derived
layers, tools, or context.  The canonical first-party API profile is selected
with =OPENAI_API_KEY= and:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-openai-api.el \
eldev test -f e2e/e-live-e2e-test.el
#+end_src

The Engineering AI Model Gateway profile used by the Doom configuration is
selected with =ENG_AI_MODEL_GW_KEY= and:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-eng-ai-gateway.el \
eldev test -f e2e/e-live-e2e-test.el
#+end_src

The Anthropic gateway sample is selected with:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-anthropic.el \
eldev test -f e2e/e-live-e2e-test.el
#+end_src

The two fresh Feature 88 cache-compatibility selectors are:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-openai-codex.el \
E_E2E_CACHE_SCENARIO_TIMEOUT_SECONDS=120 \
eldev test -f e2e/e-live-e2e-test.el \
  e-live-e2e-test-chatgpt-canonical-warm-prefix \
  e-live-e2e-test-chatgpt-canonical-tool-heavy
#+end_src

The =chatgpt-canonical-warm-prefix= selector sends a canonical pair on a
retained WebSocket and repeats it after deliberately replacing that socket.
The =chatgpt-canonical-tool-heavy= selector records a real tool call, its
matching immediate continuation, and a real reserved =context-curate= effect
before checking the following canonical ordinary request.  Each selector
prints one bounded JSON line beginning with =E88 external evidence:=.  The
record includes provider/profile and endpoint identity, transport and store
mode, model and layout/cache-key revisions, request-shape digests, socket
identity, usage, timeout, elapsed time, repository revision, and separate
semantic/cache classifications.  Missing Codex authentication produces a
bounded =configuration-unavailable= record before the selector skips.  Prompt contents, authentication headers,
response bodies, and provider-internal values are not printed.  A missing
cached-token field is reported as =unavailable=; it is not inferred to be a
cache hit.  The timeout is a private runner bound and is not a product limit.

Useful environment variables:

- =E_E2E_CONFIG=: readable Elisp file that configures and registers the
  =:chat-default= harness; required.
- =E_E2E_TIMEOUT_SECONDS=: live turn timeout override; defaults to 30 seconds.
- =E_E2E_LARGE_HISTORY_BYTES=: synthetic retained history for the Grimoire-sized
  default-harness regression; defaults to 900,000 bytes.
- =E_E2E_LARGE_HISTORY_TIMEOUT_SECONDS=: outer E2E wait for that large live
  request; defaults to 600 seconds and is not an adapter deadline.
The HTTP deadline regression uses whichever =:chat-default= harness the config
selects and crosses its real provider path.  It requires an HTTP default to
start without an implicit local deadline, because a provider gateway may buffer
a healthy long-reasoning response.  It skips for a non-HTTP default because
that transport has its own progress and timeout contract.

A second HTTP regression seeds 145 messages and roughly 900 KB of inert history
before prompting that same configured default harness.  This matches the
observed Grimoire daily request shape closely enough to cover the large retained
session path while keeping the fixture independent of personal Grimoire data.

Both canonical cache selectors require the exact built-in ChatGPT Codex
profile.  They use its actual usage fields and report explicit zero, missing
usage, and positive warm usage separately.  These are compatibility
measurements, not deterministic semantic gates: external capability remains
unconfirmed until fresh records show the required warm results with matching
identity.  The repository-side tests continue to cover provider-continuation
and encrypted-reasoning fallbacks without credentials.

* Development bytecode smoke test

The stale source-adjacent bytecode check is an explicit checkout diagnostic,
not a normal package test:

#+begin_src sh
E_DEV_E2E=1 eldev test -f e2e/e-dev-bytecode-e2e-test.el
#+end_src
