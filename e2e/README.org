#+title: Test Tiers

The repository keeps deterministic tests in the normal suite and reserves
explicit opt-in for tests that call a real provider.

* Default batch tests

Run unit and deterministic integration coverage with:

#+begin_src sh
E_RUNTIME_STATE_DIRECTORY=/tmp/e-test-runtime eldev test
#+end_src

Use a fresh disposable runtime directory for each run.  The supported runner
provides loopback bind/connect, =node=, =python3=, =tail=, the repository's
org-annotate integration, and Eldev's declared Evil and markdown-mode test
dependencies.  The canonical result is zero unexpected and zero skipped.
Missing capabilities fail with an actionable test error rather than silently
reducing coverage.

The integration files under =test/= and deterministic modules under =e2e/=
cross real harness, adapter, persistence, tool, work, and chat-surface
boundaries.  They use fake providers or no provider and require no credentials.
The post-cutover scenario performs an actual test-owned offline same-root
migration before opening the ordinary =:chat-default= composition.  It gates
the parent SQLite root, catalog-only startup, single-session lazy restore,
restart reconstruction, and exact sibling backup without touching operator
state.  Its companion post-cutover chat scenario creates a Board-associated
session through that composition and drives the real OpenAI Responses adapter
with an injected HTTP transport.  Stateless and anchored variants gate a
curation-only first response, its one immediate opaque acknowledgement, the
ordinary final answer, cold reopen, and absence of replay-carrier leakage on a
later turn.  Batch chat tests prove buffer/window structure and command routing,
but do not claim graphical redisplay or viewport behavior.

The deterministic post-cutover tests own cross-boundary regressions that the
other tiers cannot decide.  Graphical tests use a semantic fake backend and do
not inspect provider serialization.  Current-configuration tests construct a
fresh explicitly rooted harness but send no request.  Live-provider scenarios
are opt-in and model-dependent.  Focused loop/adapter tests continue to own the
larger provenance and multi-tool matrices; the post-cutover chat test covers
only the production first-response and one-request-lifetime path.

* Graphical behavioral tests

Run the graphical chat contracts with:

#+begin_src sh
bash e2e/run-graphical-tests.sh
#+end_src

On macOS the command starts a private Emacs daemon and uses a transparent,
off-screen, non-focusable NS frame.  It does not connect to or reload the
running Emacs and should not show a window or take focus.  To debug in a visible
native frame, set =E_GRAPHICAL_E2E_NATIVE_VISIBLE=1=.

On Linux, the runner uses the current display or automatically starts
=xvfb-run= when =DISPLAY= is unset.  A graphical frame is mandatory; the suite
never falls back to batch mode or skips a graphical contract.

The default is a hermetic Eldev-prepared Emacs.  To run the same graphical
matrix after this machine's normal Emacs configuration has loaded, use:

#+begin_src sh
E_E2E_EMACS_CONFIG=current bash e2e/run-graphical-tests.sh
#+end_src

This starts another private Emacs process; it does not connect to or reload the
running Emacs.  Current mode verifies that normal startup loaded =e= from this
checkout before adding test-only paths or dependencies.  Because it really
loads the user configuration, it retains normal startup filesystem effects
such as cache updates and configured project-local byte compilation.

If Emacs cannot discover the intended configuration through its normal startup
rules, set =E_E2E_EMACS_INIT_DIRECTORY= to the directory passed to Emacs'
=--init-directory= option.  This override is valid only in current mode.

Set =E_GRAPHICAL_E2E_SELECTOR= to run one ERT selector.  The scenarios cover:

1. opening the chat pair focuses its composer and =C-x 0= deletes the pair;
2. short output stays near the bottom while preserving composer focus/drafts;
3. streamed output follows while pinned, stops following after user scroll,
   and follows again after the user reaches the tail;
4. a real =persp-mode= switch round trip restores the pair and composer focus;
5. the focused composer shows model/context fill and updates from settled
   provider usage after a turn;
6. non-selected Board output is visibly prefixed with its participant name.

When =E_GRAPHICAL_E2E_TEST_FILE= names a custom test entrypoint and no selector
is supplied, the runner executes every test loaded by that file.  A selector
that matches zero tests is an error, never a successful E2E run.

** Screenshot traces

Set =E_GRAPHICAL_E2E_SCREENSHOT_DIR= to retain ordered screenshots and exact
window-state sidecars while a selected graphical scenario runs:

#+begin_src sh
E_GRAPHICAL_E2E_SCREENSHOT_DIR=/tmp/e-chat-shots \
E_GRAPHICAL_E2E_SELECTOR=focused-composer \
bash e2e/run-graphical-tests.sh
#+end_src

The standard key-input, provider-event, and provider-finish helpers capture
before/after pairs.  Successful waits capture their settled state; timeouts
capture the failing state before test cleanup.  Each capture always writes an
=.svg= and matching =.state.el= file.  When =rsvg-convert= is available it also
writes a =.png= suitable for image inspection after Emacs finishes, so image
conversion cannot change UI timing.

Tests can add a named checkpoint with
=(e-graphical-test-capture-state "after-open")= or wrap an arbitrary action
with =e-graphical-test-capture-transition=.  These helpers render the actual
test frame's window geometry, visible text, mode lines, selected window, and
viewport positions without using or focusing the desktop.

* Current configuration compatibility E2E

Run the opt-in non-provider compatibility checks with:

#+begin_src sh
bash e2e/run-current-config-tests.sh
#+end_src

The runner uses the same =E_E2E_EMACS_CONFIG=current= policy as the graphical
mode and starts a private named daemon through normal user initialization.  It
checks that the configuration loads the ready =e= runtime from this checkout,
can construct its configured default harness without sending a request, and
can integrate each configured default project through project-local policy.  It
also opens a first file through the host's startup hooks while loading a
test-owned copy of the configured Recentf cache.  This catches malformed or
incompatible persisted startup state without rewriting the user's cache.  The
suite also captures package command registration before the test bootstrap
adds checkout paths, so stale generated autoloads cannot retain a retired
command or omit its replacement unnoticed.  It accepts the same optional
=E_E2E_EMACS_INIT_DIRECTORY= override.

The compatibility mode intentionally sends no provider request.  Use the live
provider E2E below to exercise a real request with an isolated test harness.

* Live provider E2E

The credentialed suite exercises the runtime against a real provider API and
is not part of normal tests and explicitly skips whenever =CI= is set:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-openai-codex.el \
eldev -s test -f e2e/e-live-e2e-test.el
#+end_src

Those configuration/model classifications belong only to this explicitly
opt-in external-evidence tier.  They are not exceptions to the deterministic
ordinary suite's zero-skipped contract.

The Codex sample uses the normal Codex auth file and sends no project-derived
layers, tools, or context.

To check both configured Codex model IDs with one context-free live turn each:

#+begin_src sh

  eldev -s test -f e2e/e-live-e2e-test.el e-live-e2e-test-basic-assistant-response

The exact built-in ChatGPT cache-compatibility selectors are:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-openai-codex.el \
E_E2E_CACHE_SCENARIO_TIMEOUT_SECONDS=120 \
eldev -s test -f e2e/e-live-e2e-test.el \
  e-live-e2e-test-chatgpt-canonical-warm-prefix \
  e-live-e2e-test-chatgpt-canonical-tool-heavy
#+end_src

The =chatgpt-canonical-warm-prefix= selector sends a canonical pair on a
retained WebSocket and repeats it after deliberately replacing that socket.
The =chatgpt-canonical-tool-heavy= selector records a real tool call, its
matching immediate continuation, and a real reserved =context-curate= effect
before checking the following canonical ordinary request.  Each selector
prints one bounded JSON line beginning with =E88 external evidence:=.  The
record includes provider/profile and endpoint identity, transport and store
mode, model and layout/cache-key revisions, request-shape digests, socket
identity, usage, timeout, elapsed time, repository revision, and separate
semantic/cache classifications.  Missing Codex authentication produces a
bounded =configuration-unavailable= record before the selector skips.  Prompt
contents, authentication headers, response bodies, and provider-internal
values are not printed.  A missing cached-token field is reported as
=unavailable=; it is not inferred to be a cache hit.  These exact
ChatGPT/WebSocket claims remain capability-unconfirmed because the current
accepted run uses the configured Responses HTTP profile.  The timeout is a
private runner bound and is not a product limit.

Useful environment variables:

- =E_E2E_CONFIG=: readable Elisp file that configures and registers the
  =:chat-default= harness; required.
- =E_E2E_TIMEOUT_SECONDS=: live turn timeout override; defaults to 30 seconds.
- =E_E2E_LARGE_HISTORY_BYTES=: synthetic retained history for the Grimoire-sized
  default-harness regression; defaults to 900,000 bytes.
- =E_E2E_LARGE_HISTORY_TIMEOUT_SECONDS=: outer E2E wait for that large live
  request; defaults to 600 seconds and is not an adapter deadline.
The HTTP deadline regression uses whichever =:chat-default= harness the config
selects and crosses its real provider path.  It requires an HTTP default to
start without an implicit local deadline, because a provider gateway may buffer
a healthy long-reasoning response.  It skips for a non-HTTP default because
that transport has its own progress and timeout contract.

A second HTTP regression seeds 145 messages and roughly 900 KB of inert history
before prompting that same configured default harness.  This matches the
observed Grimoire daily request shape closely enough to cover the large retained
session path while keeping the fixture independent of personal Grimoire data.

Both canonical cache selectors require the exact built-in ChatGPT Codex
profile.  They use its actual usage fields and report explicit zero, missing
usage, and positive warm usage separately.  These are compatibility
measurements, not deterministic semantic gates: external capability remains
unconfirmed until fresh records show the required warm results with matching
identity.  The repository-side tests continue to cover provider-continuation
and encrypted-reasoning fallbacks without credentials.

The credentialed naturalistic adoption selector is separate from those cache
measurements.  Its deterministic runner gates classify captured behavior, but
the selector itself is external compatibility evidence, not a deterministic
repository test:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-eng-ai-gateway.el \
eldev -s test -f e2e/e-live-e2e-test.el \
  e-live-e2e-test-responses-autonomous-curation-adoption
#+end_src

It requires a configured Responses profile, uses only the ordinary
=e2e_deterministic= tool in its first prompt, and checks the autonomous
curation carrier, durable replacement, and next-turn raw-source exclusion.
Its bounded evidence record reports independent =adoption-result=,
=composition-result=, and =failure-stage= fields without prompt or response
content.  This selector is intentionally not run by repository-side tests.  Its
v5/presentation-v2 Responses HTTP record is historical after the explicit
eligibility correction; current v6/presentation-v3 adoption and exact built-in
ChatGPT/WebSocket adoption remain unconfirmed scopes.

The Addendum 7 negative-adoption selector uses a fresh session and the same
configured Responses profile:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-eng-ai-gateway.el \
eldev -s test -f e2e/e-live-e2e-test.el \
  e-live-e2e-test-responses-autonomous-curation-erase
#+end_src

It requires the ordinary deterministic tool to be useful only for the current
answer, then checks the exact transformed answer and one explicit erase
disposition selected through the optional =context-curate-v7= carrier.  The
composition gates prove durable erasure, receipt/aggregate suppression, and
preserved activity and temporary details across reopen.  Its bounded record
reports =adoption-disposition erase=,
=adoption-result=, =composition-result=, and =failure-stage= separately and
contains no prompt, sentinel, answer, summary text, or authentication data.
No Addendum 6 =drop= evidence is reused for this materially different schema.

  e-live-e2e-test-responses-canonical-tool-heavy
#+end_src

The 2026-08-28 run at revision =01a8466a= used the Engineering AI Model
Gateway / GPT (Responses) profile over native HTTP, with =:json-false= store
mode and model =gpt-5.6-sol=.  Its Addendum 6 results are historical after the
carrier revision.  A current Addendum 7 rerun must pass the reasoning probe,
positive adoption, explicit erase adoption, warm-prefix cache, and tool-heavy
cache scenarios under =context-curate-v7=.  Identity-complete records contain
only bounded request identity, revisions, classifications, counts, and timing;
HTTP evidence does not confirm the exact built-in ChatGPT/WebSocket selectors.

The Addendum 6 reasoning-summary capability probe is a separate, one-request
check of the configured Responses adapter:

#+begin_src sh
E_E2E=1 \
E_E2E_CONFIG=e2e/e-e2e-config-eng-ai-gateway.el \
E_E2E_CACHE_SCENARIO_TIMEOUT_SECONDS=120 \
eldev -s test -f e2e/e-live-e2e-test.el \
  e-live-e2e-test-responses-reasoning-summary-capability
#+end_src

The configured gateway requires =ENG_AI_MODEL_GW_KEY=.  The probe sends an
ordinary request with the effective Responses reasoning fields, including
=summary: "auto"=, and emits exactly one content-free =E88 external evidence:=
record.  Its bounded identity includes the scenario, provider/profile,
effective endpoint/base URL, transport, store mode, native requester, model,
effort/summary, material and probe request identities, timestamp, repository
revision, timeout, elapsed time, returned-summary presence, and result.  It
never records the prompt, answer, summary text, credentials, headers, or other
provider content.

The result is =pass= for any terminal successful request regardless of returned
summary presence (=present=, =empty=, or =absent=).  Endpoint rejection is
=unavailable= without a fallback request; authentication/configuration,
provider/infrastructure, timeout, and malformed or mismatched captured identity
use =configuration-unavailable=, =provider/infrastructure-failure=,
=inconclusive-timeout=, and =semantic-failure= respectively.  Evidence reuse
is limited to seven days with exact identity and dependency-cone equality.
Returned summary presence is diagnostic only: it is not curation evidence and
cannot change the capability or semantic result.
